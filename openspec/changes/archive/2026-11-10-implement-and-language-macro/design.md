# Design

## Context

Мотивация — в `proposal.md`. Сейчас `and_expr` строит `(let* (name value) (if name rest name))`, используя `Gensym.gensym`; пустой случай возвращает `true`, одиночный — исходный узел. `Language_macros.create` уже создаёт изолированное окружение на файл, загружает встроенный `cond.clj` и передаёт ему список `Syntax`. `Pipeline` оборачивает всё раскрытие в `Gensym.run`.

## Goals / Non-Goals

**Goals:** перенести алгоритм `and` с сохранением формы core-дерева, исходных metadata и семантики; использовать существующие evaluator, мост и проход desugar.

**Non-Goals:** новый механизм hygiene, отдельный счётчик имён, публичный `gensym`, реестр плагинов, дополнительные AST-проходы, перенос `or` или других макросов.

## Decisions

### Approaches

Выбран перенос в существующее расширение по образцу `cond`, с узким native helper для `Gensym`. Это соответствует выбранному пользователем следующему макросу и сохраняет единый источник временных имён. Собственный счётчик в `.clj` может конфликтовать с именами остальных макросов. Предварительная генерация списка имён адаптером усложняет контракт аргументов и оставляет часть алгоритма в OCaml; её не используем.

### Языковой алгоритм

Добавить `backend_eval/macros/and.clj` с `expand-and`, принимающим один список невычисленных форм. Использовать `count`/проверку пустого списка, `get`, `drop`, `list`, `let` и рекурсию. Для двух и более аргументов создавать символ через внутренний `(gensym)` и строить тот же `let*`/`if`, что сейчас. Последний аргумент возвращать как `Syntax`, а не оборачивать в лишний binding. Bootstrap-исходник не должен сам использовать переносимые `and` или `cond`, поскольку читается frontend-only parser.

### Compile-time helper и metadata

Технический выбор реализации: перед применением `expand-and` адаптер связывает в compile-time context native closure `gensym`, захватывающую metadata текущего вызова. Closure вызывает `Frontend.Gensym.gensym_string meta` и возвращает `Symbol`; существующий `to_sexpr` назначает новым узлам metadata вызова. Пользовательские узлы остаются `Syntax` и сохраняются целиком. Определение helper через существующий `Eval.define` ограничено изолированным context; глобальный счётчик или mutable metadata slot в адаптере не нужны. Прямые тесты обработчика выполняются внутри `Gensym.run`.

### Подключение

Расширить существующее Dune embedding вторым исходником. Оба определения загружать в одно новое окружение каждой фабрики, найти `expand-cond` и `expand-and`, добавить обработчик `and` рядом с `cond`. При появлении дублирующегося преобразования аргументов допустим небольшой локальный helper; универсальный registry не нужен. Удалить `and_expr`, `and_macro` и его регистрацию в OCaml. Проверку неполных пар `cond` сохранить.

### Проверки

Существующие `and_empty`, `and_last_value`, `and_short_circuit` сохраняют базовый контракт. Общий sample дополняет его проверкой эффектов через Atom, порядка, `nil`/`false`, истинных строк, одиночного аргумента и вложенных `and`/`or`/`case`. Сравнивать значения бинарным `=`/`not=`, выводить результаты через `str`.

Целевые тесты покрывают структуру bindings и свежесть имён без привязки к числовому суффиксу, metadata исходных и новых узлов, изоляцию helper, default/отключённую конфигурацию, отсутствие frontend fallback и вложенные пакеты. Расширить существующие проверки JS source maps и Java-аннотаций компактными примерами `and`. Уточнить английский справочник, затем выполнить `make test` и standalone probes по образцу `cond`.

## Risks / Trade-offs

- Потеря общего контекста `Gensym` → helper использует существующий effect под `Pipeline` и проверяется рядом с OCaml-макросами.
- Frontend-only callers перестанут раскрывать `and` → runtime/полную компиляцию проверять через `Pipeline`; низкоуровневую границу закрепить тестом без fallback.
- Повреждение metadata → использовать неизменённый мост `Syntax`, проверить source maps и аннотированный исходный узел.
- Случайная зависимость bootstrap от переносимого макроса → определения используют только оставшиеся frontend формы.
- Гарантии hygiene остаются такими же, как у существующего `Gensym`; защита от намеренного выбора пользователем `G__N` не расширяется этим change.

## Migration Plan

Добавить встроенное определение и helper, затем в одной согласованной правке включить обработчик и удалить OCaml-реализацию. Обновить проверки и справочник. После полного прогона и принятия результата синхронизировать delta и архивировать change. Откат — отмена переноса целиком, без параллельного fallback.
