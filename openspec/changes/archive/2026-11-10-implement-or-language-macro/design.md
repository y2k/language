# Design

## Context

Мотивация — в `proposal.md`. `or_expr` сейчас строит `(let* (name value) (if name name rest))` через общий `Gensym`. Пустой случай возвращает `nil`, одиночный — исходный узел. `Language_macros.create` загружает встроенные `cond.clj` и `and.clj` в новое compile-time окружение каждого файла. У `and` уже есть native helper `gensym`, захватывающий metadata вызова, и общий локальный `apply` для моста `Syntax`.

## Goals / Non-Goals

**Goals:** сохранить core-структуру и поведение `or`, повторно использовать существующие evaluator, мост и генератор имён, поставить третий языковой макрос в том же расширении.

**Non-Goals:** универсальный registry, параметризованный общий алгоритм `and`/`or`, новые runtime API, отдельный счётчик имён, дополнительные обходы AST или усиление hygiene.

## Decisions

### Approaches

Выбран отдельный короткий `or.clj` по образцу `and.clj`: различаются пустой результат и ветви `if`, поэтому алгоритм остаётся видимым целиком. Общая языковая функция с параметрами для двух макросов сэкономит мало строк и усложнит чтение. Сохранение OCaml fallback мешает композиционному отключению; оно исключено.

### Раскрытие и подключение

`expand-or` получает один список `Syntax` без имени макроса. Пустой список даёт `nil`, одиночный аргумент возвращается как исходный `Syntax`. Для нескольких аргументов `(gensym)` создаёт имя, а `list` строит прежний `let*`/`if`: истинная ветвь возвращает binding, ложная — рекурсивное раскрытие остатка. Используются существующие `count`, `get`, `drop`, `list`, `let`, `if` и рекурсия.

В Dune embedding добавить `or.clj`, в фабрике загрузить третий исходник и получить `expand-or`. Оба обработчика `and`/`or` используют существующий native `gensym`, связанный с metadata текущего вызова; небольшой локальный helper для установки `gensym` и вызова `apply` допустим, чтобы не дублировать адаптер. Мост и `Pipeline` не меняются. Затем удалить `or_expr`, `or_macro` и его регистрацию.

Bootstrap остаётся frontend-only и не использует `cond`, `and` или `or`. Каждый исходный файл, включая пакеты, получает новое окружение через существующую фабрику. Прямые тесты обработчиков работают под `Gensym.run`; временные имена остаются в общей последовательности с `and` и OCaml `case`.

### Тесты и совместимость

- В `test/language_macros_test.ml` добавить прямое раскрытие `or`, runtime-категорию пустого результата, сохранение одиночного `Syntax`, исходных metadata и metadata новых узлов. Проверить изоляцию `expand-or`/`gensym` и вложенные/соседние `or`, `and`, `case` без привязки к числовым суффиксам.
- В `test/pipeline_test.ml` проверить default, `extensions:[]`, восстановление default и frontend-only отсутствие fallback. В существующей проверке отключённого `and` заменить контрольный `or` на `case`, остающийся OCaml-макросом.
- Сохранить `or_empty`, `or_first_truthy`, `or_short_circuit`; добавить общий sample для порядка и однократности эффектов, одиночного эффектного аргумента, обеих комбинаций последних `nil`/`false`, истинных строк и возврата коллекции. Сравнивать коллекцию с исходным binding: JS использует identity equality. Для `nil`/`false` проверять значения и истинность, а не только вывод.
- Добавить `or` во вложенные пакеты и компактные проверки исходных позиций первого/последнего аргумента в JS и аннотированной lambda в Java по образцу `and`.
- Уточнить предложение о встроенных макросах в английском `skills/y2k-language/SKILL.md`. Семантическая таблица `or` остаётся прежней.

## Risks / Trade-offs

- Перестановка ветвей при копировании `and` → sample проверяет раннее истинное значение и последние ложные значения, а прямой тест — ссылки на binding.
- Ошибка metadata в общем helper → тестировать несколько вызовов с разными позициями, исходные узлы и source maps.
- Неявная зависимость bootstrap от удаляемого обработчика → исходник `or.clj` использует только оставшиеся frontend формы; standalone probes проверяют поставку.
- Frontend-only callers теряют `or` → закрепить границу тестом; полная компиляция использует `Backend_eval.Pipeline`.
- Общий `Gensym` сохраняет прежние ограничения относительно намеренно выбранных пользовательских `G__N`; change не заявляет новой защиты от них.

## Migration Plan

Добавить языковое определение, embedding и обработчик, удалить OCaml fallback в согласованной правке, обновить тесты и справочник. После `make test`, standalone probes и строгой валидации передать change на завершение. Откат — отмена переноса целиком; параллельная OCaml-реализация не сохраняется.
