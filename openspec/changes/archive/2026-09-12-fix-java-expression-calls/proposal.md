## Why

Java-бэкенд приводит локальное функциональное значение к `FnN`, но для результата выражения генерирует `.call(...)` на `Object`. Ошибка #19 подтверждена через `javac` для возвращённой функции, callback-цепочки и результатов `get`/`if`; пользователю приходится добавлять явный cast или локальный binding.

## What Changes

- Java-вызов результата выражения автоматически приводит вызываемое значение к `FnN` по числу аргументов текущего вызова, с поддержкой арностей 0–4.
- Неподдерживаемая арность такого вызова отклоняется Java-генератором с координатами исходной формы.
- Вызываемое выражение вычисляется ровно один раз; существующие непосредственные лямбды и явные приведения к `FnN` сохраняют работоспособность.
- **BREAKING**: функциональный синтаксис вызова результата выражения использует только `FnN`, в том числе при явном `(cast TYPE ...)`. Наличие произвольного Java-метода `call` больше не достаточно; такие вызовы записываются явно как `(.call (cast TYPE value) args...)`.
- Совпадение с eval фиксируется для оговорённых сценариев фабрики, callback-цепочки, `get`, `if` и арностей 0–4. Порядок побочных эффектов вызываемого выражения относительно аргументов не входит в изменение.
- Регрессия проверяется компиляцией и исполнением общих samples и целевым тестом диагностики.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `compiler-targets`: дополнить контракт Java-вызовов функциональных значений вызовом результата выражения, однократным вычислением и проверкой арности.

## Impact

- `backend_compiler/java.ml`: общая ветка вызова выражения и существующий `fn_interface`.
- `test/samples/`: общий регрессионный sample, исполняемый на eval, JavaScript и Java.
- `test/java_ns_test.ml`: диагностика неподдерживаемой арности вызова выражения.
- Используются существующие `Fn0`–`Fn4` из `prelude/language_runtime.java`; новые зависимости не требуются.
- Связанная задача: https://github.com/y2k/language/issues/19.
