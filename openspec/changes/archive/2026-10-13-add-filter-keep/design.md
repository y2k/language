# Design

## Context

Мотивация — в `proposal.md`. Существующие `map` и `run!` реализованы отдельно в eval stdlib и двух host runtimes. Eval уже имеет типизированные Nil/Bool, `truthy` и передачу callback через `apply`; Java — `truthy` и `call_fn`; JS — `truthy`, отличающий ложные значения языка от host truthiness. В Java импорт runtime общий, в JS список exports задан явно в `backend_compiler/js.ml`.

Изменение затрагивает три runtime и подключение JS, поэтому краткий design фиксирует общую семантику и различия host-представлений.

## Goals / Non-Goals

**Goals:** использовать существующие вызовы функций и представления коллекций, обеспечить линейный обход и единые результаты для переносимых входов.

**Non-Goals:** ленивые последовательности, transducers, одноаргументные перегрузки, maps/nil как входные коллекции, произвольные iterables, sparse JS arrays, ожидание async callbacks, поведение при изменении состава коллекции callback. Новые публичные helpers и отдельные проверки AST не нужны. Единая диагностика неверных аргументов JS/Java не вводится.

## Decisions

### Обычные runtime-функции по образцу map

- Eval: добавить два native binding в `backend_eval/eval_stdlib.ml`; использовать существующий шаблон `[Closure; List]`, `apply` и `truthy`. Для обхода подходят `List.filter` и `List.filter_map`; `keep` сопоставляет результат с Nil, остальные значения возвращает без преобразования.
- JS: добавить exports в `prelude/language_runtime.js` и import в `backend_compiler/js.ml`. `filter` использует нативный Array.filter с обёрткой, передающей callback только item и применяющей language `truthy` к результату. `keep` одним циклом собирает результаты в новый массив, пропуская null и undefined.
- Java: добавить методы в `prelude/language_runtime.java` по образцу `map`: проверка List, новый ArrayList, обход через существующий `call_fn`. Для filter использовать `truthy`, для keep — проверку результата на null.

Альтернатива — выразить операции через reduce и concat — многократно копирует растущий аккумулятор. Макросы добавляют работу frontend без необходимости. Прямые runtime-функции сохраняют O(n) обход, O(k) память результата и существующую семантику callbacks.

### Истинность и отсутствие — разные проверки

Filter использует общий `truthy`, поэтому сохраняет элементы при результатах 0, пустой строке, строках `"nil"` и `"false"`. Keep проверяет только отсутствие результата: Nil в eval, null в Java, null/undefined в JS. Проверка truthiness в keep ошибочно удаляла бы false; JS `.filter(Boolean)` также потерял бы 0 и пустую строку. Согласованное исключение undefined соответствует трактовке отсутствующих данных существующим JS `get`.

### Переиспользование проверок и тестов

Eval использует pattern matching по образцу map и существующий механизм арности callback; JS/Java следуют соседним runtime-функциям, не добавляя новую общую систему валидации. Ошибки callback не перехватываются в реализации.

Общие fixtures в `test/samples/` проверят отбор сообщений, преобразование карточек, скалярные типы, пустые результаты, list/vector, порядок и однократность callback, неизменность входа, именованные/локальные функции во вложенном namespace. Проверки значений используют count/get и бинарные `=`/`not=`, выводя booleans через str: сравнение текстового вида коллекции не различает nil и строку `"nil"`, а равенство коллекций непереносимо.

JS-specific fixture проверит прямой undefined из host callback, плотные массивы, сохранение identity объектов и unary callback. Проверки остановки при исключении повторят существующий подход `test/samples/js/run_callback_error.clj`, `test/samples/java/run_callback_error.clj` и eval suite `test/eval_stdlib_contracts_test.ml`. Eval suite также проверит заявленные неверные аргументы, включая пустой вход и отложенную проверку арности callback. Полная проверка — `make test`.

## Risks / Trade-offs

- JS host truthiness может незаметно удалить допустимые значения → отдельные проверки false, 0, пустой строки и текстового nil.
- Unconditional JS import новых exports несовместим со старым runtime → обновлять compiler и runtime вместе; использовать существующее копирование через `make build`.
- Callback может сам менять объекты или иметь побочные эффекты → гарантируется отсутствие мутации со стороны операции, но не глубокая копия или откат callback; изменение состава входа вне контракта.

## Migration Plan

Обновить runtime и compiler совместно, затем пересобрать и доставить потребителям `language_runtime.js`/`.java` существующим способом из `prelude/1.0.0`. Изменить английский справочник `skills/y2k-language/SKILL.md` в той же реализации. Миграции данных нет; откат выполняется согласованным возвратом compiler и runtime, а приложения должны прекратить использование новых функций.
