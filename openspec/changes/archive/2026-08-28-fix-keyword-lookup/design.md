## Context

После текущего `keyword_macro` форма `(:key collection)` неотличима от вызова строкового литерала. Все backend-цели получают уже дешугорированные s-expression и не могут корректно восстановить намерение исходного кода. См. мотивацию в `proposal.md` и контракт поведения в delta spec `frontend-syntax`.

## Goals / Non-Goals

**Goals:**

- Представить keyword lookup как существующий core-вызов `get` до передачи форм backend-целям.
- Сохранить строковое представление keyword в map-ключах и destructuring-паттернах.
- Выполнить новую форму в существующем кросс-бэкенд sample harness для `eval`, JavaScript и Java.

**Non-Goals:**

- Не добавлять форму lookup со значением по умолчанию или другую Clojure-совместимость keyword.
- Не менять API `get`, JavaScript/Java runtime или генераторы кода.
- Не менять семантику явного вызова строкового литерала.

## Decisions

### Раскрывать lookup отдельным frontend macro

Macro, распознающий список из keyword и одной коллекции, будет расположен до `keyword_macro` и создаст `(get collection "key")`. После этого существующее рекурсивное дешугорирование и все backend-цели обработают форму без специальных веток.

Альтернатива: распознавать строковую голову списка в JavaScript compiler. Отклонена, поскольку frontend уже стёр происхождение строки, а `eval` и Java останутся сломанными. Это также смешает keyword lookup с явным вызовом строки.

### Проверять поведением через общий sample suite

Новый fixture в `test/samples/` вызовет функцию lookup с map, использующей keyword в качестве ключа. Существующий suite выполняет каждый sample через `eval`, генерирует и запускает JavaScript с `language_runtime.js`, а также компилирует и запускает Java с `language_runtime.java`.

Альтернатива: только snapshot generated JavaScript. Отклонена: такой тест не обнаружит ошибку исполнения и не подтверждает согласованность целей.

## Risks / Trade-offs

- [Изменение порядка macro изменит раскрытие keyword в list] → правило ограничивается формой из keyword и ровно одной коллекции; остальные keyword продолжат обрабатываться существующим `keyword_macro`.
- [Поведение трёхаргументного lookup остаётся не определено] → не добавлять его без отдельного требования и расширения `get`.

## Migration Plan

Изменение не требует миграции данных или пользователей: ранее форма завершалась ошибкой, после релиза она станет допустимым lookup. Откат состоит в возврате frontend macro и fixture без изменений runtime или формата артефактов.
