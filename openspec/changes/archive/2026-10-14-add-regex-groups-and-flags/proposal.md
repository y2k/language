# Proposal

## Why

В #31 приложение извлекает ID через JS interop, поскольку `re-find` возвращает только полное совпадение, а `re-pattern` не принимает флаги. Нужны группы захвата и регистронезависимый ASCII-поиск средствами языка на eval, JS и Java.

## What Changes

- Добавить `(re-find-groups regex text)`: первое совпадение как коллекция `[полное-совпадение группа-1 ...]`, отсутствие совпадения как nil. Неучаствовавшая группа даёт nil, пустая — `""`.
- Расширить `re-pattern` необязательной строкой flags: отсутствие аргумента и `""` сохраняют регистр, `"i"` включает регистронезависимый поиск. Остальные значения flags отклоняются.
- Применять флаг при `re-find`, `re-find-groups` и `re-replace`; сохранять исходный регистр возвращаемого текста.
- Сохранить результат `re-find` строкой либо nil и буквальную глобальную замену. Гарантия регистра ограничена ASCII; Unicode остаётся зависимым от движка.
- Обновить английский справочник и проверки трёх targets.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `eval-runtime`: необязательные flags при компиляции regex, получение групп и контракты аргументов.
- `compiler-targets`: тот же API и переносимые результаты на JS/Java, сохранение flags при замене.

## Impact

- `backend_eval/eval_stdlib.ml`: компиляция через существующий Re, новая функция и binding.
- `prelude/language_runtime.js`, `prelude/language_runtime.java`: flags и извлечение групп через текущие движки.
- `backend_compiler/js.ml`: стандартный импорт новой функции; Java использует существующее подключение runtime.
- `test/samples/`, `test/eval_regex_test.ml`, `test/eval_stdlib_contracts_test.ml`, `test/regex_targets_test.ml`: переносимые сценарии и расширенный контракт аргументов.
- `skills/y2k-language/SKILL.md`: документирование API, nil и границ переносимости.
- Новые зависимости и новый runtime-тип не требуются. Реализация ограничена этим репозиторием.
