# Design

## Context

Мотивация и согласованный API описаны в `proposal.md`. Изменение затрагивает eval и два runtime, поэтому нужен общий дизайн адаптации движков.

Сейчас `backend_eval/eval_stdlib.ml` компилирует `Re.Perl.compile_pat` и извлекает группу 0 из `Re.exec_opt`. Установленная Re предоставляет `Caseless`, `Re.Group.nb_groups` и `Re.Group.get_opt`. JS хранит RegExp внутри Regex, Java использует Pattern. Все движки уже возвращают группы. В JS `re_replace` создаёт отдельный RegExp с одним флагом `g`; Java создаёт matcher из исходного Pattern. JS импортирует runtime-функции явным списком, Java — через static wildcard import.

Основные спецификации сейчас явно запрещают flags и закрепляют однопараметрический re-pattern. Delta обновляет эти требования, сохраняя сценарии и строковый результат re-find. Тесты ошибок тоже считают второй аргумент ошибкой арности: их нужно переключить на третий аргумент, а `"flags"` проверять как недопустимое значение.

## Goals / Non-Goals

**Goals:**
- Использовать существующие движки и обычные коллекции, не вводя matcher-объект в API языка.
- Нормализовать отсутствующие группы в настоящее nil/null и сохранять их позиции.
- Хранить настройку регистра в скомпилированном regex, чтобы она применялась ко всем операциям.

**Non-Goals:**
- Новый regex-парсер, эмуляция движков, Unicode case folding, именованные группы, поиск всех совпадений, дополнительные флаги и подстановка групп при замене.
- Расширение проверок AST и диагностики за пределы контрактов runtime-функций.

## Decisions

### 1. Отдельная функция поиска групп

`re-find-groups` возвращает коллекцию группы 0 и всех нумерованных групп. Альтернатива — менять форму результата re-find в зависимости от pattern — нарушает совместимость. Функция, возвращающая только одну группу по индексу, вынуждала бы повторять поиск для нескольких полей.

Eval собирает List по индексам от 0 до `Re.Group.nb_groups - 1`, переводя `get_opt` в String/Nil. JS создаёт обычный массив из числовых элементов match, переводя undefined в null; metadata `index`, `input`, `groups` в результат не переносится. Java собирает обычный список от 0 до `matcher.groupCount()` включительно; `matcher.group(i)` уже возвращает null для отсутствующей группы. Использовать список, допускающий null, а не `List.of`.

### 2. Ровно две формы flags

Отсутствие второго аргумента эквивалентно `""`; `"i"` включает нативную настройку регистра: `Caseless` в Re, `i` в RegExp, `Pattern.CASE_INSENSITIVE` в Java. Проверка flags — простое сопоставление строки с двумя допустимыми значениями. Дубликаты и неизвестные буквы отклоняются: общий парсер набора флагов не нужен.

Не переводить pattern или text в нижний регистр: это меняет возвращаемые группы и потенциально синтаксис pattern. Существующая Java-нормализация `$` сохраняется, как и стандартные правила точки и anchors.

### 3. Независимые операции над одним regex

Поисковый RegExp не получает `g` или `y`, поэтому exec не переносит позицию между вызовами. Для глобальной замены JS создаёт отдельный RegExp с сохранёнными flags и добавленным `g`. Eval и Java уже исполняют операции над исходным скомпилированным regex. Их алгоритмы глобальной буквальной замены менять не требуется.

### 4. Граница переносимости

Сохраняется существующий общий алфавит: печатный ASCII, TAB и LF. Флаг i обещает только ASCII-регистр. Нумерация, отсутствие необязательной группы и пустая группа нормализуются между targets.

Как минимальная граница нового API, захваты внутри повторяемой группы остаются нативными: движки могут различаться в сохранении захвата от предыдущей итерации. Это не мешает шаблону `post-([0-9]+)`: здесь повторяются цифры внутри единственной группы. Общая эмуляция истории захватов не вводится; ограничение явно отражается в справочнике.

### 5. Проверки в существующих suites

Общие сценарии поместить в `test/samples/`: ID из issue, несколько и вложенные группы, отсутствие совпадения, необязательная группа, альтернатива, пустая группа/шаблон, get/count/деструктуризация, ASCII-регистр и повторное использование после замены. Проверять значения через бинарные =/not= и истинность, выводя общий итог через str.

Расширить существующие целевые тесты regex и матрицу контрактов: допустимые арности re-pattern, ошибки flags и re-find-groups, namespace-подключение. Для JS добавить прямую проверку null, поскольку равенство языка может скрыть undefined. Для eval проверить Nil внутри результата существующим OCaml harness. Финальная проверка реализации — `make test`.

## Risks / Trade-offs

- Потеря i при JS-замене → общий сценарий поиска, замены и повторного поиска одним regex.
- Потеря отсутствующих позиций либо смешение nil с пустой строкой → проверки count, get, истинности и runtime-значений.
- Расхождения Unicode и повторяемых захватов → явная документированная граница без дополнительного движка.
- Устаревший runtime при новом JS-импорте → поставлять обновлённые compiler и runtime совместно; файлы `prelude/` сейчас обычные файлы этого репозитория.

## Migration Plan

Изменения runtime, JS-импорта, тестов и справочника поставляются вместе. Существующие корректные вызовы сохраняются; приложение может заменить JS interop на get результата re-find-groups. Для отката новые вызовы приложения возвращаются к прежнему interop, затем откатывается совместная правка compiler/runtime. Новые зависимости и миграция данных отсутствуют.
