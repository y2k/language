# Design

## Context

См. `proposal.md`. Основа — реализованный `add-eval-booleans`. Сейчас арифметика повторно разбирает текст `Symbol`, `count` создаёт текст, `str`/`slurp` также создают `Symbol`. `load_dep` ожидает пару `Symbol`. Деструктуризация преобразует ключ через `quote`, затем использует `List.assoc_opt`; `get` использует тот же OCaml lookup, а `=` — отдельный `equal_value`.

Keywords уже превращаются в строковые AST-атомы до eval. `quote` работает после macro expansion: этот change не исправляет обход цитированных векторов/map/макросов.

## Goals / Non-Goals

**Goals:** заменить текстовые псевдотипы реальными конструкторами и сохранить корректность всей цепочки от литерала до CLI; согласовать числовое равенство и ключи сразу, не оставляя промежуточную несовместимость до третьего change.

**Non-Goals:** новый reader, keyword-тип, полная Clojure-семантика quote, big integers, дробное деление/порядок, дополнительные builtins преобразования, изменения JS/Java.

## Decisions

### 1. Простые варианты существующего `value`

Использовать `String of string`, `Int of int`, `Float of float`, `Symbol of string` вместе с `Nil` и `Bool`. Сохранить машинные целые OCaml и binary64: перевод всего в float потерял бы точность текущих целых, а хранение чисел текстом сохранило бы неоднозначность потребителей.

Для обычного eval строки распознаются до lookup, а числа — на существующем этапе литералов: сначала `int_of_string_opt`, затем `float_of_string_opt`. Не расширять переносимую числовую грамматику; non-finite и переполнение остаются вне гарантий. Цитирование использует ту же классификацию атомов без поиска bindings: nil, boolean, строка, число, иначе `Symbol`. Не превращать произвольный неразрешённый символ в значение вне `quote`.

### 2. Числовое равенство по значению

Подтверждено пользователем: `1` и `1.0` равны. `Int`/`Int` сравниваются точно, `Float`/`Float` — по binary64 без epsilon. В смешанном случае float должен быть конечным, целым и точно соответствовать integer; нельзя просто округлить большой `Int` через `float_of_int`. Перед `int_of_float` нужна безопасная проверка границ машинного int; сравнение результата с исходным int исключает ложное равенство соседних целых за пределами точности binary64.

Рекурсивное равенство lists/maps сохраняет порядок. Функции и Atom остаются неравными, в том числе самим себе. `get` и ассоциативная деструктуризация переходят на общий небольшой lookup по `equal_value`, возвращающий первую подходящую пару. Не добавлять hash table или менять дубликаты: изменение структуры map не нужно. Из-за унификации функция/Atom в позиции ключа больше не находятся через структурное OCaml-сравнение; это явная часть breaking change.

### 3. Числа не возвращаются в текст между операциями

`+`, `-`, `*` работают с числовыми конструкторами: целая ветка остаётся целой, смешанная использует binary64. Точный целый результат в signed 32-bit диапазоне нормализуется в `Int`, включая отрицательный ноль. Вне него не вводится новая гарантия нормализации. Форматирование `float_text` используется только при выводе, а не как промежуточное хранилище.

`count` возвращает `Int`. `/`, порядок, `drop` и list index продолжают требовать `Int`; равенство `1` и `1.0` не делает их взаимозаменяемыми во всех API. В частности, литерал `1.0` не является допустимым list index, а нормализованный результат `(+ 0.5 0.5)` является. Расширение integer-only API до всех целозначных float не требуется для разделения типов.

### 4. Строковые границы и runner

`str` и `slurp` возвращают `String`; `slurp` принимает только `String`. В `load_dep` package/version также `String`, что сохраняет `(deps {:package "version"})`, поскольку keyword уже строка. Namespace metadata остаётся AST-текстом и не требует runtime-конвертации.

`to_string` печатает строки/символы без кавычек, boolean и nil прежними словами, числа десятичным текстом с существующим round-trip форматированием дробей. Сохранение исходной записи `1.00` не обещается. Runner выводит только скаляры, включая цитированный символ; диагностический `value_text` различает string, symbol, integer, float, boolean.

Строгая проверка основных типов входит сюда: оставлять разбор числовых строк как временную совместимость значило бы внедрять и затем удалять лишний путь. Третий change завершает аудит арностей, callbacks и ошибок операций.

### 5. Проверки

Сохранить общие samples дробной арифметики; добавить общие проверки строк/чисел там, где JS/Java уже совпадают. Mixed numeric equality, typed quote, ключи разных типов и list index `1.0` тестировать в eval-only fixtures. Целевые OCaml-тесты проверяют конструкторы, большие целые в смешанном сравнении и все consumers, а не только одинаковые строки вывода. Helpers `last_symbol`/`check_symbol` в namespace/deps/Atom suites адаптировать по назначению результата, не подменяя все проверки безусловным `to_string`.

## Risks / Trade-offs

- Изменение представления заденет нетекстовые результаты старых helpers → обновить callers в OCaml suites и сохранить прямые проверки типов.
- Большой int может ошибочно совпасть с округлённым float → guarded mixed comparison и граничные тесты на 64-bit OCaml.
- Реальные числа и строки раньше сравнивались одинаково → задокументировать строгие типы и замену цитированного текста строковым литералом.
- Полиморфное сравнение ключей с closure может выбросить исключение → единый языковой lookup без OCaml structural equality.
- Последовательные deltas переписывают одни требования → применять после boolean, сохраняя его сценарии и завершённые nil/Atom при синхронизации.

## Migration Plan

Реализовать после `add-eval-booleans`. Обновить всю цепочку scalar producers/consumers, документацию и tests одним change и выполнить `make test`. Проверить namespace/deps/Atom suites вместе с дробной арифметикой. Для отката вернуть change целиком; `enforce-eval-stdlib-contracts` нельзя сохранять поверх прежней модели. Миграция внешнего хранилища не требуется.

### Сверка baseline перед синхронизацией

Boolean-change уже архивирован и интегрирован. Main spec сохраняет имя `The eval target SHALL return only the final symbol value`; scalar-delta адресует его без переименования. Все имена сценариев четырёх MODIFIED-блоков main сохранены, включая nil/boolean и `Get from nil`. Отдельное boolean-требование не заменяется. Stdlib-блок включает `get-in` и функции Atom со сценарием `Функции Atom доступны без импорта` из завершённого Atom-change.

Завершённые `add-eval-nil`/`add-atoms` ещё не синхронизированы полностью. При их отдельной интеграции нужно сохранить новые scalar/boolean-блоки, добавить оставшиеся nil/Atom requirements и учитывать runner rename из nil-delta; применять старые MODIFIED-блоки поверх scalar нельзя. Если runner будет переименован до синхронизации scalar, адресующий заголовок scalar-delta также должен быть согласован с новым именем. Основные specs и старые changes при реализации scalar не изменяются.
