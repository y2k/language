# Design

## Context

Мотивация и объём описаны в `proposal.md`.

Сейчас `macros/dune` генерирует `Builtin_macro_source.definitions` — тройки «имя формы, точка входа `expand-*`, исходник» из `macros/builtin/{cond,and,or,with_open}.clj`. `Language_macros.create_from` склеивает исходники, разбирает их только базовыми макросами (`Builtin_macros.builtin_macros`), вычисляет в отдельном compile-time окружении и находит точки входа по именам. `Pipeline.parse_and_desugar` вызывает фабрику расширения для каждого исходного файла, включая файлы `deps`, поэтому окружение не разделяется между файлами. Загрузчик `deps` читает только файлы `*.clj`, лежащие непосредственно в `${LY2K_PACKAGES_DIR}/PACKAGE/VERSION`.

Каталог пакетов — отдельный репозиторий; в нём уже есть `prelude/1.0.0/macro/prelude.clj` с определениями под именами макросов. `make build` требует `LY2K_PACKAGES_DIR` и копирует туда JS/Java runtime, `make test` вызывает `dune runtest`. Dockerfile запускает `make test` с пустым временным каталогом пакетов от имени `opam` и не копирует `macros/` и `fex_unpack/`, поэтому Docker-сборка не проходит уже сейчас. Репозиторий пакетов `y2k/packages` публичный; `prelude.clj` добавлен в него коммитом `ea9c12d`.

## Goals / Non-Goals

**Goals:**
- Заменить встроенный источник определений чтением одного файла из каталога пакетов, сохранив модель подготовки (отдельное compile-time окружение, поиск точек входа по имени) и изоляцию на исходный файл.
- Не требовать каталог пакетов от программ, которые не используют `cond`, `and`, `or` и `with-open`.
- Не позволить кешу dune скрыть изменение внешнего файла от тестов.

**Non-Goals:**
- Перенос других форм в prelude, target-aware разбиение, пользовательский `defmacro`, загрузка произвольных макросов.
- Настраиваемые путь и версия, поиск альтернативных расположений, интеграция с `(deps ...)`.
- Изменение семантики и диагностики `cond`, `and`, `or`, `with-open`, `Syntax` API и `gensym`.
- Включение пакетов или prelude в финальный Docker-образ.

## Decisions

1. **Единственный экземпляр файла — в каталоге пакетов**
   - *Решение:* определения хранятся только в `${LY2K_PACKAGES_DIR}/prelude/1.0.0/macro/prelude.clj`. Генерация `Builtin_macro_source` и файлы `macros/builtin/*.clj` удаляются; `make build` файл не копирует.
   - *Почему:* proposal требует одного источника истины без копии в репозитории языка.
   - *Альтернатива:* хранить исходник в репозитории и копировать его при `make build`, как JS/Java runtime, — отвергнуто: две копии требуют синхронизации.

2. **Контракт файла: определения под именами макросов**
   - *Решение:* файл содержит top-level определения в порядке `cond`, `and`, `or`, `with-open`; точка входа формы — определение с её именем; вспомогательные определения допустимы (`with-open-bindings`). OCaml хранит только список имён форм, а `create_from` принимает список имён и исходник вместо троек.
   - *Почему:* файл в каталоге пакетов уже так устроен, и таблица «форма → точка входа» становится лишней.
   - *Альтернатива:* сохранить имена `expand-*` и таблицу соответствия — отвергнуто решением пользователя.

3. **Файл разбирается без языкового расширения**
   - *Решение:* исходник, как и сейчас, разбирается только базовыми макросами и вычисляется целиком в порядке следования определений, после чего точки входа ищутся по именам. Внутри файла `cond`, `and`, `or`, `with-open` — обычные compile-time функции: рекурсивный `(cond (drop 2 clauses))` остаётся вызовом функции. Bootstrap-порядок означает порядок вычисления определений.
   - *Почему:* при совпадении имён раскрытие файла языковым расширением превратило бы рекурсию в раскрытие макроса, а при ленивой загрузке — в повторное принудительное вычисление той же загрузки.
   - *Альтернатива:* регистрировать каждый макрос сразу после его определения, чтобы следующие определения использовали его как макрос, — отвергнуто: текущим определениям это не нужно, а смысл имени внутри файла зависел бы от позиции.

4. **Ленивая загрузка в экземпляре расширения**
   - *Решение:* фабрика расширения по-прежнему вызывается для каждого исходного файла, но чтение и подготовка `prelude.clj` выполняются через `lazy` при первом раскрытии одной из четырёх форм. Последующие раскрытия в том же файле используют подготовленные определения; следующий файл читает `prelude.clj` заново в новом окружении.
   - *Почему:* программы без этих форм не требуют `LY2K_PACKAGES_DIR` (в том числе сценарий `container-distribution` «Вычисление программы из stdin»), а изоляция на файл сохраняется без нового кеша.
   - *Альтернативы:* загрузка при создании экземпляра — отвергнуто: любая программа падала бы без каталога пакетов; общий кеш подготовленного окружения — отвергнуто: нарушает изоляцию изменяемого состояния.

5. **Fail-fast без fallback**
   - *Решение:* если `LY2K_PACKAGES_DIR` не задана или пуста, файла нет, его нельзя прочитать, разобрать или вычислить либо в нём нет определения одной из четырёх форм, раскрытие завершается ошибкой. При отсутствии источника сообщение называет переменную или ожидаемый путь; ошибки разбора и вычисления передаются как есть. Ошибка идёт путём ошибок раскрытия макросов, поэтому CLI сообщает её в stderr с ненулевым статусом. Пустая переменная считается отсутствующей, иначе путь стал бы относительным к текущему каталогу.
   - *Почему:* proposal требует fail-fast, а встроенных определений после решения 1 нет.

6. **Путь не связан с deps**
   - *Решение:* путь `prelude/1.0.0/macro/prelude.clj` обрабатывает только механизм макросов. `(deps {prelude "1.0.0"})` подкаталог `macro/` не подхватывает, потому что загрузчик читает лишь `*.clj` непосредственно в `PACKAGE/VERSION`.
   - *Альтернатива:* загружать определения через `deps` — отвергнуто: другой layout и runtime-окружение вместо compile-time.

7. **Тесты используют внешний файл и отслеживают его**
   - *Решение:* тесты читают файл из заданного `LY2K_PACKAGES_DIR` и не создают его. `test/dune` объявляет зависимость от переменной `LY2K_PACKAGES_DIR` и от самого файла, чтобы dune перезапускал тесты при их изменении. Тест подключения `cond` под другим именем дополняет исходник prelude синонимом `(def choose cond)`.
   - *Альтернатива:* запускать тесты с `--force` — отвергнуто: обходит кеш для всех тестов и не фиксирует зависимость.

8. **Docker получает prelude по зафиксированному коммиту**
   - *Решение:* сборочный этап копирует `macros/` и `fex_unpack/`, объявляет `ARG PACKAGES_REF` с полным SHA коммита репозитория пакетов (сейчас `ea9c12d7d6e90f604852196fafbb0e39dcd7ad43`), заранее создаёт `/tmp/language-packages/prelude/1.0.0/macro` от имени `opam` и загружает туда только файл: `ADD --chown=opam:opam https://raw.githubusercontent.com/y2k/packages/${PACKAGES_REF}/prelude/1.0.0/macro/prelude.clj`. Каталог создаётся заранее, потому что `make build` пишет рядом JS/Java runtime. Финальный этап не меняется: пакетов и `LY2K_PACKAGES_DIR` в образе нет; для программ с макросами пользователь подключает каталог пакетов: `-v "$LY2K_PACKAGES_DIR:/packages:ro" -e LY2K_PACKAGES_DIR=/packages`.
   - *Почему:* репозиторий пакетов публичный, поэтому `docker build .` из чистого checkout и workflow публикации работают без второго checkout в CI. Зафиксированный коммит делает сборку воспроизводимой: изменение prelude в `master` не ломает сборку старых коммитов. Исправление входит в этот change, чтобы реализация ушла в `main` одним push.
   - *Альтернативы:* брать `master` — отвергнуто: невоспроизводимо; `ADD` всего git-репозитория — отвергнуто: тестам нужен один файл; отдельный build context (`--build-context packages=…`) — отвергнуто: требует второго checkout в CI и меняет команду локальной сборки; пропуск тестов макросов в Docker — отвергнуто: нарушает требование полного suite; копия файла в репозитории языка — отвергнуто решением 1.

## Risks / Trade-offs

- [Программы с `cond`, `and`, `or`, `with-open` не работают без каталога пакетов, в том числе в контейнере без подключённого тома] → принято как BREAKING в proposal; README описывает подключение каталога пакетов к контейнеру, справочник — требование `LY2K_PACKAGES_DIR`.
- [Docker-тесты проверяют prelude из `PACKAGES_REF`, а не из `master`] → при изменении prelude, нужном компилятору, обновлять `PACKAGES_REF` в том же изменении репозитория языка.
- [Docker-сборка зависит от доступности GitHub] → как и от opam и Docker Hub; ошибка загрузки останавливает сборку до публикации.
- [Файл живёт в другом репозитории и может разойтись с ожиданиями компилятора] → fail-fast; изменения файла фиксируются в репозитории пакетов отдельно.
- [Каждый исходный файл с этими макросами, включая файлы `deps`, заново читает и вычисляет `prelude.clj`] → для четырёх небольших определений стоимость приемлема; общий кеш отвергнут ради изоляции.
- [Фиксированная версия `1.0.0`] → смена версии или пути — отдельный change.

## Migration Plan

1. Файл `prelude.clj` уже добавлен в репозиторий пакетов коммитом `ea9c12d`; сверить его с контрактом решения 2.
2. Одним изменением в репозитории языка переключить расширение на чтение файла, удалить встраивание и `macros/builtin/*.clj`, адаптировать тесты, документацию и Dockerfile.
3. Пушить в `main` только после успешной локальной Docker-сборки, чтобы не сломать публикацию.

Откат: revert изменения в репозитории языка возвращает встраивание; файл в каталоге пакетов откату не мешает.
