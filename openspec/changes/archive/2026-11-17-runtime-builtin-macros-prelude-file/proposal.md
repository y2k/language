# Proposal

## Why

Сейчас определения встроенных языковых макросов (`cond`, `and`, `or`, `with-open`) встраиваются в executable на этапе сборки. Это не позволяет обновлять или поставлять их отдельно от бинарника. Нужно загружать эти определения во время запуска из файла пакета prelude по фиксированному пути `${LY2K_PACKAGES_DIR}/prelude/1.0.0/macro/prelude.clj`.

## What Changes

- **BREAKING**: стандартное расширение больше не содержит определений builtin-макросов и загружает их во время запуска из фиксированного файла `${LY2K_PACKAGES_DIR}/prelude/1.0.0/macro/prelude.clj`.
- Источник истины для `cond`, `and`, `or`, `with-open` — один файл `prelude.clj` в каталоге пакетов. Он содержит top-level определения в bootstrap-порядке (`cond`, `and`, `or`, `with-open`) под именами самих макросов вместо `expand-*`; внутри файла эти имена обозначают compile-time функции, а не вызовы макросов. Репозиторий языка копию файла не содержит, `make build` его не копирует.
- Файл читается лениво, при первом раскрытии `cond`/`and`/`or`/`with-open` в исходном файле; программы без этих форм его не читают. Семантика и диагностика макросов и изоляция compile-time окружения на исходный файл сохраняются.
- **BREAKING**: если `LY2K_PACKAGES_DIR` не задана или пуста, файла нет, его нельзя прочитать, разобрать или вычислить либо в нём нет определения одной из четырёх форм, раскрытие завершается ошибкой. Fallback на встроенные определения нет.
- **BREAKING**: программы с `cond`, `and`, `or` или `with-open` не запускаются и не компилируются без каталога пакетов с этим файлом — ни в checkout, ни вне его, ни в Docker-образе без подключённого каталога пакетов: образ по-прежнему не содержит пакетов.
- Build-time встраивание удаляется: генерация `Builtin_macro_source` в `macros/dune` и файлы `macros/builtin/*.clj`.
- Docker: сборочный этап копирует `macros/` и `fex_unpack/` и для тестов загружает `prelude.clj` из публичного репозитория пакетов `y2k/packages` на зафиксированном коммите. Финальный образ не меняется; программы с этими макросами запускаются в контейнере с каталогом пакетов, подключённым томом, и `-e LY2K_PACKAGES_DIR`.

### Modified Capabilities

- `internal-language-macros`: определения builtin-макросов загружаются из `${LY2K_PACKAGES_DIR}/prelude/1.0.0/macro/prelude.clj` вместо встраивания; фиксируются путь, формат файла и fail-fast. Сценарии запуска без `LY2K_PACKAGES_DIR` заменяются сценариями с каталогом пакетов. Механизм подключения принимает имена форм и исходник с одноимёнными определениями, поэтому проверка `cond` под другим именем идёт через синоним. Требование «cond без внешнего bootstrap» переименовывается в «cond без импортов».
- `container-distribution`: сборочный этап получает `prelude.clj` для тестов из репозитория пакетов на зафиксированном коммите; программы с `cond`, `and`, `or`, `with-open` в контейнере требуют подключённый каталог пакетов; README описывает такое подключение.

## Impact

- Код: `macros/language_macros.ml` (контракт `create_from`, ленивое чтение файла), `macros/dune` (удаление генерации `Builtin_macro_source`), удаление `macros/builtin/*.clj`.
- Тесты: `test/dune` объявляет зависимость от `LY2K_PACKAGES_DIR` и файла; `test/language_macros_test.ml` и `test/eval_deps_test.ml` адаптируются; `make test` использует файл из заданного `LY2K_PACKAGES_DIR` и не создаёт его.
- Документация: `skills/y2k-language/SKILL.md` и `README.md` (сборка, тесты, запуск контейнера с каталогом пакетов).
- Каталог пакетов (отдельный репозиторий `y2k/packages`): `prelude/1.0.0/macro/prelude.clj` уже добавлен коммитом `ea9c12d` и должен соответствовать контракту.
- Окружение: `make build|test` по-прежнему требуют заданный `LY2K_PACKAGES_DIR`; значение по умолчанию и локальный каталог пакетов не вводятся. Путь не связан с layout deps `${LY2K_PACKAGES_DIR}/PACKAGE/VERSION/*.clj`, версия `1.0.0` фиксирована; механизм выбора версии не вводится.
- Docker: `Dockerfile` копирует `macros/` и `fex_unpack/` и загружает `prelude.clj` по `ARG PACKAGES_REF` (SHA коммита репозитория пакетов). Сборка образа зависит от доступности GitHub; чтобы Docker-тесты увидели новую версию prelude, нужно обновить `PACKAGES_REF`. Исправление входит в этот change, чтобы реализация ушла в `main` одним push без поломки публикации.
