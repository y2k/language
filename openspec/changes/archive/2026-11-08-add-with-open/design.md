# Design

## Context

Мотивация — в `proposal.md`. `frontend/builtin_macros.ml` уже содержит рекурсивное раскрытие bindings и helper `is_binding_symbol`. `frontend/desugar.ml` повторно раскрывает полученные macro forms. Java поддерживает `cast`, вызовы методов и expression-valued `try/finally` через существующий lowering. `backend_compiler/exception_forms.ml` требует непустое тело `try`.

Текущий Java sample `exception_resources.clj` моделирует этапы через журнал, но не вызывает реальные `.close()`. Справочник прямо сообщает об отсутствии `with-open`. Дизайн фиксирует выбор интерфейса и пограничных форм до реализации.

## Goals / Non-Goals

**Goals:** использовать существующие core-формы; сохранить metadata исходных bindings и expressions; не требовать подсказок типа ради cleanup.

**Non-Goals:** новый IR, runtime-протокол ресурсов, Java try-with-resources, suppressed exceptions, async cleanup, destructuring, поддержка eval/JS/FEX, отдельный проход диагностики некорректных программ. Общий frontend может раскрывать форму для других targets, но это не обещание поддержки или раннего отказа без побочных эффектов.

## Decisions

### Встроенный макрос вместо нового backend node

Добавить и зарегистрировать `with_open_macro` в `frontend/builtin_macros.ml`. На каждую пару строить binding, затем `try` с рекурсивным раскрытием остальных пар и `finally`. Существующий `let` выполняет обработку type metadata, а обычный desugar доводит результат до core-форм.

```clojure
(let [a (open-a)]
  (try
    (let [b (open-b a)]
      (try
        (do (process a b))
        (finally (.close (cast java.lang.AutoCloseable b)))))
    (finally (.close (cast java.lang.AutoCloseable a)))))
```

Initializer следующего ресурса находится внутри защиты предыдущего. Cleanup расположен после собственного binding, поэтому не вызывается для initializer, который не завершился.

### AutoCloseable вместо прямого вызова

Пользователь выбрал cast к `java.lang.AutoCloseable` в cleanup. Прямой `.close` проще, но не компилируется для типичного результата языковой фабрики `Object` без аннотации. Cast делается только при закрытии и не меняет статический тип binding в теле; для ресурсоспецифичных методов тела по-прежнему нужны обычные hints/casts. Альтернатива Java try-with-resources отвергнута: она меняет приоритет исключений и добавляет suppressed exceptions.

### Пустые формы и синтаксис

Принятое при планировании уточнение в духе Clojure: пустой вектор выполняет тело, пустое тело даёт `nil`. База рекурсии — `do` тела, а для отсутствующего тела — явный `nil`, чтобы не создавать пустой `try`. Binding names — простые символы, metadata сохраняются. Для разбора использовать существующий helper и локальную проверку формы/пар; отдельные валидаторы и гарантии текста диагностик не добавлять.

### Проверки на реальных host-ресурсах

В `test/frontend_desugar_test.ml` проверить структуру вложенности, cast и metadata. В `test/samples/java/` добавить self-contained ресурсы с наблюдаемым `close`: например, через существующий `raw-code` создать `AutoCloseable`, который пишет в журнал и при необходимости бросает заранее созданное исключение. Фабрика на языке возвращает `Object`, что проверяет выбранный контракт без hints. Использовать существующий sample-runner и ожидаемый вывод первой строки; сравнивать значения и исключения, а не только их текст.

## Risks / Trade-offs

- Ошибка cast/вызов на null происходит после тела → описать отсутствие предварительной проверки и проверить закрытие внешнего ресурса.
- Пользователь может ожидать Java suppressed exceptions → явно документировать семантику вложенного `finally` и проверить identity окончательной ошибки.
- Подсказка типа всё ещё нужна для специальных методов ресурса в теле → привести пример в Java-справочнике.
- Общий frontend не делает форму переносимой → документировать Java-only контракт; не расширять eval и JS в этом change.

## Migration Plan

Изменение аддитивное; существующие ручные `try/finally` продолжают работать. После добавления макроса и тестов обновить английский справочник и выполнить `make test`. Откат — удалить регистрацию/реализацию макроса и связанные примеры; данные и runtime миграции не нужны.
