## Context

`backend_compiler/js.ml` сначала преобразует строковый атом в JavaScript-литерал через `Target_syntax.string_literal`, а затем безусловно заменяет `/` на `.` в результате. Замена необходима для ссылок на namespace в нестроковых символах, но недопустима для уже сформированного литерала. См. мотивацию в `proposal.md` и требование в `specs/compiler-targets/spec.md`.

## Goals / Non-Goals

**Goals:**
- Разделить генерацию строковых литералов и преобразование namespace-символов.
- Сохранить текущую генерацию ссылок вида `alias/member` как `alias.member`.
- Зафиксировать регрессию точной проверкой generated JavaScript.

**Non-Goals:**
- Не менять parser, `Symbol_munge`, Java target или eval target.
- Не расширять правила экранирования строк и не добавлять новые формы namespace.

## Decisions

### Применять преобразование слеша только к символам

Ветка для строкового атома будет возвращать готовый JavaScript-литерал без последующей подстановки. Ветка для чисел, `nil` и символов сохранит существующую семантику; преобразование `/` в `.` останется только там, где формируется JavaScript-идентификатор или квалифицированная ссылка.

Это минимально использует уже существующие `is_string`, `Target_syntax.string_literal` и логику namespace. Альтернатива в виде исправления литерала после глобальной подстановки неверна: невозможно надёжно восстановить исходные `/` и она смешивает два разных вида данных.

### Добавить точечный compiler-output тест

Тест в `test/js_ns_test.ml` будет компилировать `(str "/")` и проверять, что output содержит `(str)("/")`. Существующая проверка строковых литералов не содержит `/`, поэтому не обнаруживает эту регрессию.

## Risks / Trade-offs

- [Непреднамеренное изменение namespace-символов] → Регрессионная проверка дополняет существующий тест `require imports`, который фиксирует `io.math.core` как `./io/math/core.js`.
- [Пропуск другого пути генерации строк] → У quoted-значений и строковых `:require` уже есть отдельные ветки; изменение ограничивается обычным `SAtom` в JavaScript expressions.

## Migration Plan

Изменение не требует миграции данных или runtime. При откате достаточно вернуть генерацию JavaScript compiler; API и формат входных программ не меняются.
