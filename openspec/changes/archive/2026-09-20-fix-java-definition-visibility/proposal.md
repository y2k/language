# Proposal

## Why

Issue #23 показывает, что публичные `defn` недоступны из namespace в другом Java package: генератор выпускает package-private методы. Такое же ограничение действует для полей `def` и мешает разделять приложение на namespace согласно структуре исходников.

## What Changes

- Обычные top-level `defn` и `def` генерируют `public static` методы и поля.
- Квалифицированные значения `alias/member` в Java используют существующее разрешение aliases, позволяя читать поля через `:require`.
- **BREAKING**: `defn-` и `def-` генерируют `private static` методы и поля; обращения из другого namespace, включая тот же Java package, больше не допускаются.
- Добавляются проверки реальной компиляции и исполнения межпакетного доступа, а также отказа во внешнем доступе к приватным определениям.
- Справочник языка описывает новый контракт видимости Java.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `compiler-targets`: видимость top-level Java методов и полей, публичный межпакетный доступ и приватность в пределах своего namespace.

## Impact

Изменяются `backend_compiler/java.ml`, тесты Java-генерации и интеграционные тесты в `test/`, при необходимости их регистрация в `test/dune`, а также `skills/y2k-language/SKILL.md`. Используется существующая metadata `private_`; новые зависимости не требуются. Пользователям, вызывающим `defn-` или читающим `def-` из другого namespace, потребуется сделать эти определения публичными либо обращаться через публичную функцию своего namespace.
