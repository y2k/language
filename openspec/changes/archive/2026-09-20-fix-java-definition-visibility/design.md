# Design

## Context

Мотивация приведена в `proposal.md`. В `backend_compiler/java.ml` функция `compile_function` генерирует `static Object`, а две ветви `compile_statement` делают то же для полей с inline-инициализацией и со static initializer. Metadata core-формы `def` уже содержит `private_`, установленную макросами `def-` и `defn-`. Текущие snapshot-тесты в `test/java_ns_test.ml` закрепляют package-private сигнатуры; примеры интеграции с `javac`, runtime и временными каталогами имеются в `test/instance_check_test.ml` и `test/get_in_test.ml`.

Документ нужен для фиксации согласованного изменения совместимости приватных определений и границ миграции.

## Goals / Non-Goals

**Goals:**
- Применять одно правило видимости к методам и обеим ветвям генерации полей.
- Проверять доступность средствами Java на реально сгенерированных классах.

**Non-Goals:**
- Изменение загрузки исходников, представления функций как значений, поведения eval или JS.
- Проверка чужих определений самим генератором до `javac`, поддержка nested `def` или изменение мутабельности полей.

## Decisions

### Использовать metadata core def

Выбирать `public` или `private` по `private_` внешней формы `def` и использовать выбранный модификатор в генерации метода или поля. При необходимости передавать его в `compile_function`. Это сохраняет существующий frontend и lowering. Альтернатива с распознаванием `defn-` в Java отвергнута: к этому этапу форма уже раскрыта.

### Приватность соответствует Java private

Согласованное правило — `private static`, включая поля. Сохранение package-private для private-marked форм позволило бы соседнему namespace обходить приватность. Добавление `public` всем определениям также отвергнуто, поскольку экспортировало бы приватные helpers. Вложенные классы `gen-class` могут обращаться к private членам своего внешнего класса по правилам Java; это проверяется отдельным сценарием.

### Доверить проверку межклассового доступа javac

При чтении квалифицированного значения использовать существующий `compile_qualified_name` после проверки литералов, локальных bindings и top-level функций. Сейчас `compile_atom` оставляет `alias/member` без разрешения; согласованное расширение устраняет этот пробел для доступа к полям, сохраняя приоритет локальных bindings.

Генератор компилирует namespace отдельно и не загружает исходники required namespace. Для новой проверки во frontend потребовалась бы информация о зависимостях; обычных модификаторов Java достаточно.

### Совместить точечные проверки генерации с интеграционными

Обновить существующие ожидаемые сигнатуры и добавить проверки всех трёх путей генерации: метод, поле с атомарным RHS, поле со static initializer. Для интеграционного теста использовать принятый в проекте подход с временным каталогом, `RUNTIME_JAVA`, `javac -d` и Java runner. Проверить reproducer #23, чтение публичных полей, внутренний private доступ и делегирование `gen-class`. Отрицательные случаи компилировать отдельно для метода и поля в том же и другом package, чтобы один отказ не скрывал непроверенный сценарий. Проверять причину отказа по недоступному члену без привязки к полному тексту диагностики конкретного JDK.

## Risks / Trade-offs

- [Существующие внешние обращения к private-marked определениям перестанут компилироваться] → Явно описать breaking change и миграцию к публичной функции или определению.
- [Исправление только методов оставит тот же дефект у данных] → Проверить обе ветви генерации полей и их значения после инициализации.
- [Текстовые тесты пропустят ограничения Java access control] → Компилировать и исполнять несколько namespace совместно с runtime.
- [Ошибки окружения могут выглядеть как ожидаемый отрицательный тест] → Сначала успешно собрать runtime и валидный fixture, затем проверять отдельные обращения и диагностируемый член.

## Migration Plan

После выпуска компилятора повторно сгенерировать Java и пересобрать приложение вместе с runtime. Для внешнего использования private-marked членов заменить `defn-`/`def-` на публичные формы либо предоставить публичную функцию в исходном namespace. Обновить соответствующие ограничения в `skills/y2k-language/SKILL.md`. Откат компилятора с повторной генерацией вернёт прежние package-private члены и ограничение межпакетного доступа.
