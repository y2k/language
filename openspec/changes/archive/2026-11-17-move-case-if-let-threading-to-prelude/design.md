# Design

## Context

Мотивация и объём — в `proposal.md`.

После `runtime-builtin-macros-prelude-file` стандартное расширение (`Language_macros.create`) при первом вызове одной из форм `prelude_names` читает `${LY2K_PACKAGES_DIR}/prelude/1.0.0/macro/prelude.clj`, вычисляет его в отдельном compile-time окружении и сразу ищет определения всех имён набора. Pipeline ставит обработчики расширения перед `Builtin_macros.builtin_macros`. Языковой обработчик принимает только формы `(имя ...)` в круглых скобках. Новые узлы результата получают metadata вызова, а `syntax-list-at` — metadata выбранного исходного узла. `macro-error` бросает `Failure`, как и `failwith` в OCaml-макросах.

OCaml-реализации:
- `case` — `let*` со свежим именем и вложенные `if`/`=`; все новые узлы получают metadata вызова; ошибок нет.
- `if-let` — пара раскрывается в `(let* (name value) (if name <rest> else))`, список пары получает metadata вектора; три сообщения об ошибках; имя проверяется `is_binding_symbol`, поэтому квалифицированные имена проходят. При этом JS генерирует `let a/b = ...`, а Java — `var a/b = ...`.
- `->`/`->>` — свёртка по шагам: список любых скобок получает значение внутрь с сохранением metadata и вида скобок шага; атом становится `(atom value)` с metadata атома; пустой список остаётся как есть.

`test/frontend_desugar_test.ml` проверяет раскрытие `case` и `if-let` через стандартный pipeline, `test/js_source_map_test.ml` — позиции шагов `->`/`->>`. `test/pipeline_test.ml` использует `->` и `case` как OCaml-макросы, которые работают при отключённом расширении.

## Goals / Non-Goals

**Goals:**
- Перенести четыре формы без изменения раскрытия, metadata и сообщений для корректных и уже диагностируемых программ.
- Обойтись одной новой операцией `Syntax`.

**Non-Goals:**
- Перенос `let`, `fn`, `defn`, `def-`, `defn-`, `ns`, `gen-class` и синтаксического сахара (`:kw`, `[]`, `{}`, `(:kw m)`, `.method`, `Class.`).
- Новые макросы (`when`, `when-let` и т. п.) и новая диагностика.
- Выбор версии prelude, изменение пути и формата файла.

## Decisions

1. **Тот же файл и версия `1.0.0`, дополнение на месте**
   - *Решение:* определения `case`, `if-let`, `->`, `->>` и их helpers добавляются в конец `prelude/1.0.0/macro/prelude.clj` после `with-open`; `prelude_names` расширяется до восьми имён в том же порядке.
   - *Почему:* путь зафиксирован предыдущим change. Дополнение совместимо назад: компилятор без этого change ищет только свои четыре имени, а тела новых определений обращаются к `syntax-list?` только при вызове.
   - *Альтернатива:* версия `1.1.0` — отвергнуто: потребовала бы выбора версии, который вынесен за рамки.

2. **Все имена набора ищутся при подготовке файла**
   - *Решение:* как и сейчас, подготовка ищет все восемь определений сразу. При старом файле первое раскрытие любой из восьми форм, включая `cond`, завершается ошибкой `symbol not found: case`.
   - *Почему:* контракт файла «всё или ничего» не требует нового кода и сразу показывает устаревший каталог пакетов.
   - *Альтернатива:* искать определение при вызове формы, чтобы `cond` работал со старым файлом, — отвергнуто: частично рабочий prelude хуже диагностируется, а требование fail-fast говорит об отсутствии любого определения.

3. **`case` и `if-let` на существующих операциях**
   - *Решение:* `case` вызывает `gensym` один раз и строит ветви рекурсивным helper по `(drop 2 clauses)`. `if-let` проверяет число аргументов и `syntax-vector?`, затем рекурсивно обходит `syntax-children` вектора слева направо. Список пары строится через `syntax-list-at` от вектора, имя проверяется `syntax-simple-symbol?`, ошибки выдаются через `macro-error` с прежними текстами в прежнем порядке. Отсутствующий `else` даёт `nil` с metadata вызова.
   - *Почему:* так воспроизводится текущее раскрытие без новых natives.
   - *Квалифицированные имена:* `syntax-simple-symbol?` отклоняет `a/b` сообщением `if-let: binding names must be symbols`. Это сужение принято: такие программы уже не компилируются в JS/Java. Отдельный предикат «любой symbol» ради сохранения бага не добавляется.

4. **`->`/`->>`: один helper и предикат `syntax-list?`**
   - *Решение:* добавляется native `syntax-list?`: истина для исходного списка в круглых скобках, ложь для любого другого значения. Общий helper `thread` с флагом позиции проходит по шагам. Для списка он берёт `syntax-children` и строит `syntax-list-at` шага со значением вторым или последним элементом. Для любого другого шага он строит `syntax-list-at` шага из `(step value)`. Без шагов возвращается само значение.
   - *Почему:* `syntax-list-at` сохраняет metadata шага, от которых зависят позиции source maps. Различить список и символ существующими операциями нельзя: `syntax-children` падает на атоме, а `syntax-simple-symbol?` ложен для квалифицированных функций вроде `str/join`.
   - *Отличие:* шаг-вектор или шаг-map вызывается как функция, а не получает значение внутрь своих скобок (контракт сценария «Шаг другой формы»). Сохранять вид скобок пришлось бы новой операцией ради формы, которой нет в тестах и документации.
   - *Альтернатива:* общий `syntax-kind`, возвращающий вид узла, — отвергнуто: одного предиката достаточно.

5. **Удаление OCaml-обработчиков без fallback**
   - *Решение:* `case_macro`, `if_let_macro` с helpers, `thread_macro`, `thread_first_macro` и `thread_last_macro` удаляются из `builtin_macros.ml` и списка `builtin_macros`. `is_binding_symbol` остаётся для `syntax-simple-symbol?`.
   - *Следствие:* сам `prelude.clj`, разбираемый только OCaml-макросами, не может использовать эти четыре формы; его текущие определения их не используют.

6. **Тесты**
   - *Решение:* существующие тесты раскрытия `case`/`if-let` и source maps `->`/`->>` остаются и проверяют prelude-версии. `pipeline_test.ml` переходит на OCaml-макросы, оставшиеся в builtin (например, `let`), и проверяет, что восемь форм не раскрываются без расширения и во frontend-only разборе.
   - *Новые тесты:* отклонение `a/b` в `if-let`, metadata списка пары `if-let`, `->`/`->>` с символьным шагом и шаг-вектор, файл только с четырьмя прежними определениями, вложенные `deps` с перенесёнными формами.

## Risks / Trade-offs

- [Программ, которым нужен `LY2K_PACKAGES_DIR`, становится больше: `case`, `if-let` и `->` встречаются чаще `with-open`] → принято в proposal как BREAKING; README и справочник перечисляют формы из файла prelude.
- [Локальный каталог пакетов со старым `prelude.clj` ломает все восемь форм] → ошибка называет отсутствующее определение; README указывает, что каталог пакетов нужно обновить вместе с компилятором.
- [`(case)`, `(->)` и `(->>)` без значения раньше падали при исполнении с `symbol not found`, а теперь раскрываются в `nil`; пустой шаг `()` раньше молча отбрасывал значение, теперь даёт ошибку `syntax-list-at`] → вне контракта `frontend-syntax`; диагностика не добавляется по правилу минимальности и при необходимости вводится отдельно.
- [Форма `[-> x f]` в квадратных скобках раньше раскрывалась, теперь остаётся литералом списка] → вне контракта: обработчик языковых макросов принимает только круглые скобки, как у `cond`.
- [Файл prelude вычисляется для большего числа исходных файлов] → определения небольшие, стоимость приемлема, как и в предыдущем change.

## Migration Plan

1. Добавить определения в `prelude.clj` репозитория пакетов отдельным коммитом и проверить, что текущий компилятор с обновлённым файлом проходит `make test`.
2. Одним коммитом в репозитории языка добавить `syntax-list?`, расширить `prelude_names`, удалить OCaml-обработчики и адаптировать тесты и документацию.
3. Опубликовать коммит пакетов, обновить `PACKAGES_REF`, собрать Docker-образ локально, затем пушить `main`.

Откат: revert коммита в репозитории языка возвращает OCaml-обработчики; дополненный файл prelude совместим с прежним компилятором.
