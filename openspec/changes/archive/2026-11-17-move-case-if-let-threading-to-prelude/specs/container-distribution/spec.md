# Spec Delta

## MODIFIED Requirements

### Requirement: Docker-сборка SHALL запускать полный suite

Dockerfile SHALL выполнять `make test` для eval, JS и Java внутри сборочного этапа с необходимыми OCaml, Node.js и JDK. Для тестов сборочный этап SHALL получать `prelude/1.0.0/macro/prelude.clj` из репозитория пакетов на зафиксированном коммите. Финальный этап SHALL получать бинарник только из успешно проверенного сборочного этапа. Отдельные шаги запуска тестов и установки toolchain в GitHub Actions SHALL NOT требоваться.

#### Scenario: Тесты при локальной сборке
- **WHEN** Docker выполняет сборочный этап без готового кеша для текущих исходников и тестов
- **THEN** внутри этапа запускается полный `make test` для eval, JS и Java

#### Scenario: Ошибка тестов останавливает сборку
- **WHEN** тест в сборочном этапе завершается ошибкой
- **THEN** Docker-сборка возвращает ненулевой код и финальный образ этого запуска не создаётся

#### Scenario: Prelude для тестов
- **WHEN** сборочный этап запускает `make test`
- **THEN** `LY2K_PACKAGES_DIR` указывает на каталог с `prelude/1.0.0/macro/prelude.clj` зафиксированного коммита репозитория пакетов, и тесты всех макросов из этого файла выполняются

### Requirement: Контейнер SHALL предоставлять интерфейс существующего CLI

Запуск контейнера SHALL непосредственно вызывать `language`, передавать ему аргументы, переменные окружения, stdin, stdout, stderr и код завершения. Без аргументов SHALL использоваться `eval`; `--target eval|js|java` SHALL сохранять существующее поведение CLI: вычисление либо генерацию исходного кода. Программы с builtin-макросами из файла prelude (`internal-language-macros`) SHALL требовать подключённый к контейнеру каталог пакетов, на который указывает `LY2K_PACKAGES_DIR`.

#### Scenario: Вычисление программы из stdin
- **WHEN** пользователь передаёт `(str "Hello, " "world!")` в stdin команды `docker run --rm -i y2khub/language:latest`
- **THEN** stdout содержит `Hello, world!` с завершающим переводом строки и процесс завершается с кодом 0

#### Scenario: Выбор target
- **WHEN** пользователь передаёт корректную программу в stdin контейнера с аргументами `--target js` или `--target java`
- **THEN** stdout содержит тот же сгенерированный исходный код, что и CLI из той же версии проекта с теми же аргументами, вводом и каталогом пакетов

#### Scenario: Ошибка CLI
- **WHEN** контейнер запущен с аргументами `--target unknown`
- **THEN** процесс завершается с ненулевым кодом и stderr содержит `unknown target: unknown`

#### Scenario: Builtin-макросы без каталога пакетов
- **WHEN** пользователь передаёт `(cond false 1 true 42)` в stdin команды `docker run --rm -i y2khub/language:latest` без подключённого каталога пакетов
- **THEN** процесс завершается с ненулевым кодом, а stderr называет `LY2K_PACKAGES_DIR`

#### Scenario: Builtin-макросы с подключённым каталогом пакетов
- **WHEN** тот же ввод передаётся контейнеру с томом каталога пакетов и `-e LY2K_PACKAGES_DIR`, указывающей на этот том
- **THEN** stdout содержит `42` и процесс завершается с кодом 0

### Requirement: README SHALL описывать использование контейнерного дистрибутива

README SHALL содержать команды локальной сборки и запуска через stdin, выбор target, подключение каталога пакетов для программ с builtin-макросами из файла prelude, описание полного прогона тестов внутри Docker-сборки и настройку GitHub Actions secret для публикации. Документация SHALL указывать поддержку `linux/amd64` и различать генерацию JS/Java и исполнение сгенерированного кода, требующее runtime-файлов из репозитория и Node.js/JDK.

#### Scenario: Настройка и запуск по документации
- **WHEN** пользователь следует README
- **THEN** он может собрать образ, выполнить пример eval, запустить программу с `cond`, подключив каталог пакетов, выбрать JS/Java target и определить имя секрета и необходимые права Docker Hub token для публикации
