# Proposal

## Why

После `runtime-builtin-macros-prelude-file` макросы `cond`, `and`, `or` и `with-open` определены на языке в `${LY2K_PACKAGES_DIR}/prelude/1.0.0/macro/prelude.clj`, а остальные builtin-макросы `macros/builtin_macros.ml` по-прежнему написаны на OCaml. Из них `case`, `if-let`, `->` и `->>` — чистые перестановки форм: им не нужен доступ к metadata формы (в отличие от `def-`/`defn-` и типов параметров `fn`), сам prelude на них не написан, а встречаются они заметно реже `defn` и `ns`, поэтому требование каталога пакетов расширяется умеренно. Перенос сокращает OCaml-код и проверяет механизм языковых макросов на формах с диагностикой и metadata шагов.

## What Changes

- `case`, `if-let`, `->` и `->>` определяются top-level определениями с их именами в том же файле `prelude/1.0.0/macro/prelude.clj` после `with-open`; стандартное расширение раскрывает их так же лениво, как первые четыре формы. Файл в репозитории пакетов дополняется на месте, версия `1.0.0` не меняется.
- OCaml-реализации этих четырёх форм удаляются из builtin-макросов.
- Внутренние операции `Syntax` дополняются предикатом списка в круглых скобках для шагов `->`/`->>`. `if-let` проверяет имена существующей операцией простого неквалифицированного имени, как `with-open`.
- Семантика, раскрытие, metadata и сообщения об ошибках `case` и `if-let` сохраняются. Квалифицированное имя binding в `if-let` (`a/b`) теперь отклоняется сообщением `if-let: binding names must be symbols`: сейчас eval его принимает, а JS/Java генерируют невалидный код `let a/b = ...`. Шаги `->`/`->>` в круглых скобках и шаги-атомы (символы, keywords) раскрываются как прежде; шаг другой формы (например, вектор) вызывается как функция `(step value)` вместо прежней вставки значения внутрь скобок.
- Некорректные формы вне контракта `frontend-syntax` меняют поведение без новой диагностики: `(case)`, `(->)` и `(->>)` без значения раскрываются в `nil` вместо ошибки `symbol not found` при исполнении; `[-> x f]` в квадратных скобках больше не раскрывается; пустой шаг `()` даёт ошибку раскрытия вместо молчаливой потери значения.
- **BREAKING**: программы с `case`, `if-let`, `->` или `->>` требуют `LY2K_PACKAGES_DIR` с файлом prelude, как программы с `cond`. Без языкового расширения (пустой список расширений, frontend-only раскрытие) эти формы остаются нераскрытыми, fallback нет.
- **BREAKING**: компилятор требует обновлённый `prelude.clj`: при старом файле без новых определений раскрытие любой из восьми форм завершается ошибкой. Docker-сборка переходит на новый `PACKAGES_REF`.
- Требования к контейнеру и README перестают перечислять формы и ссылаются на макросы из файла prelude.

### Modified Capabilities

- `internal-language-macros`: набор форм файла prelude расширяется до восьми; добавляются требования к языковым `case`, `if-let`, `->`, `->>` и к операции `Syntax`, распознающей список в круглых скобках; отключение расширения и загрузка из файла распространяются на новые формы.
- `frontend-syntax`: `if-let` принимает только простые неквалифицированные имена binding.
- `container-distribution`: требования к Docker-тестам, запуску контейнера и README говорят о макросах из файла prelude без перечисления форм.

## Impact

- Код: `macros/builtin_macros.ml` (удаление `case_macro`, `if_let_macro`, `thread_first_macro`, `thread_last_macro` и их helpers), `macros/language_macros.ml` (`prelude_names`, native `syntax-list?`).
- Каталог пакетов (`y2k/packages`): определения `case`, `if-let`, `->`, `->>` и их helpers в `prelude/1.0.0/macro/prelude.clj`; коммит должен быть опубликован до Docker-сборки, потому что Dockerfile загружает файл с GitHub по SHA.
- Тесты: `test/pipeline_test.ml` использует `->` и `case` как OCaml-макросы — нужна замена на оставшиеся OCaml-формы; `test/frontend_desugar_test.ml`, `test/js_source_map_test.ml` и samples проверяют перенесённые формы через стандартный pipeline.
- Документация: `skills/y2k-language/SKILL.md` (перечень макросов из файла prelude, строки `if-let` и `->`) и `README.md` (перечень макросов и обновление каталога пакетов вместе с компилятором).
- Docker: `ARG PACKAGES_REF` в `Dockerfile`.
- OpenSpec: delta-спеки опираются на требования `runtime-builtin-macros-prelude-file`, поэтому тот change нужно заархивировать раньше этого.
