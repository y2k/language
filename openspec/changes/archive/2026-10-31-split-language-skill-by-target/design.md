# Design

## Context

Мотивация описана в `proposal.md`. Сейчас `skills/y2k-language/SKILL.md` содержит 459 строк: общие таблицы, target-разделы, CLI, диагностику и source maps. Target-specific сведения также встроены в общие таблицы и пояснения. Раздел общих regex-функций ошибочно расположен внутри eval-раздела вместе с примером сборки userscript. `AGENTS.md` направляет обновления документации только в `SKILL.md`.

Скилл предназначен для внешних приложений и подключается целым каталогом. Этот репозиторий реализует все targets; обсуждавшееся предпочтение JS относится к внешнему приложению. Дизайн нужен для фиксации границ переноса смешанных разделов и правил выбора справочников.

## Goals / Non-Goals

**Goals:**
- Сохранить полноту существующих пользовательских контрактов при выборочном чтении документации.
- Обеспечить один источник общих правил и явные условия чтения дополнительных файлов.
- Сделать основной файл вместе с JS-справочником меньше исходного монолита без потери необходимых общих ограничений.

**Non-Goals:**
- Изменение семантики, runtime, API или процесса сборки приложений.
- Отдельные skills, автоматический загрузчик, генератор документации или новые зависимости.
- Фиксированный лимит строк, сокращение контрактов ради метрики, поддержка старых версий компилятора.

## Decisions

### Один скилл и три справочника

Выбран пользователем вариант `SKILL.md` плюс `references/js.md`, `references/eval.md`, `references/java.md`. Альтернатива с отдельными skills усложняет выбор и дублирует общие правила; монолит сохраняет избыточную загрузку. Справочники — обычные Markdown-файлы без самостоятельного skill frontmatter. Английский язык и имя основного скилла сохраняются.

### Маршрутизация по текущей задаче

В начале `SKILL.md` разместить короткую таблицу target → относительный путь → условие чтения. Target определяется по конфигурации и командам исполняемого или компилируемого кода. При отсутствии данных агент уточняет target. Для JS-кода читается JS-справочник; для eval-скрипта сборки добавляется eval. Изменение сборки само по себе не требует eval. При работе с общей семантикой компилятора читаются все затронутые targets.

Ссылки разрешаются относительно каталога скилла, а не cwd приложения. Инструкция не предписывает заранее читать все справочники. JS-default не добавляется в распространяемый скилл.

### Граница общего и целевого содержания

| Файл | Содержание |
| --- | --- |
| `SKILL.md` | Назначение, ссылки обратной связи, выбор target, общие формы и сигнатуры, переносимые контракты и примеры, общие regex-правила, базовый CLI и доставка runtime, подключение скилла |
| `references/js.md` | ESM, namespace/module imports, host interop, `export-default`, JS-представления и host-коллекции, source maps, JS-особенности печати и raw-code |
| `references/eval.md` | Типы, quote, равенство и ключи, диагностика аргументов, namespaces/deps, `slurp`/`assert`, результат CLI, OCaml Re и пример userscript-сборки |
| `references/java.md` | Helper classes, видимость, arity/callback ограничения, imports/interop, casts и metadata, `instance?`, `gen-class`, JVM entry point, Java runtime-представления и raw-code |

Общие таблицы сохраняют краткие предупреждения о непереносимости quote, равенства, ключей и других различий; подробные примеры и диагностика переезжают в целевые файлы. Общие regex-контракты переносятся из eval-подраздела в общую библиотеку; зависимость Re и eval-диалект остаются в eval. Не следует сохранять утверждение, что весь смешанный regex-раздел относится только к eval.

Для `raw-code`, общего только JS/Java, небольшой общий контракт повторяется в двух целевых справочниках вместе с их собственными примерами. Это предложенная техническая деталь: четвёртый справочник ради одного раздела добавил бы лишний переход. При переносе сверить две копии. Основной файл сохраняет краткое указание доступности формы и ссылки.

### Сопровождение и проверка

Правило `AGENTS.md` должно требовать обновлять соответствующую часть комплекта, а не только `SKILL.md`. Существующий контракт спецификации об одном target-разделе заменяется файловой структурой и сценариями выборочного чтения.

Проверка документационная: сопоставить все старые разделы с новыми местами, проверить ссылки из каталога скилла, прочитать комплект в сценариях JS-only, JS+eval и Java. Зафиксировать число строк основного файла и суммы `SKILL.md` + `js.md` относительно исходных 459 как индикатор, не как замену проверки полноты. Новые runtime-тесты не требуются, поскольку поведение не меняется.

## Risks / Trade-offs

- Потеря ограничений при переносе смешанных абзацев → проверить каждый исходный раздел и оставить предупреждения о переносимости в общей части.
- Агент прочитает все ссылки заранее → явно указать условия чтения и отсутствие необходимости читать незатронутые targets.
- Дублирование `raw-code` разойдётся со временем → сверить общий контракт двух справочников и включить их в правило сопровождения.
- Основная часть останется значительной → сохранить полноту общих API; дробление общей библиотеки отложить за рамки этой задачи.

## Migration Plan

В одной правке переместить документацию, добавить относительные ссылки и обновить правило сопровождения. Подключённый симлинком каталог уже включает `references/`; повторная установка или изменение конфигурации приложения не нужны. Для отката восстановить монолит и прежнее правило сопровождения, удалив добавленные справочники в рамках отката той же правки.
