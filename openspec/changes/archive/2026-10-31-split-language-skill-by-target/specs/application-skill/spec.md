# Spec Delta

## MODIFIED Requirements

### Requirement: Скилл SHALL выделять target-specific возможности отдельно

Скилл SHALL хранить подробности `eval`, `js` и `java` в `references/eval.md`, `references/js.md` и `references/java.md`, доступных относительно каталога скилла. `SKILL.md` SHALL содержать общие правила и ссылки с условиями чтения. Пользовательские формы, ограниченные target, включая Java `gen-class` и JS `export-default`, SHALL оставаться в соответствующем справочнике. Скилл SHALL предписывать определять target задачи по конфигурации и командам приложения, а при недостатке данных уточнять его у пользователя.

#### Scenario: Генерация JavaScript экспорта
- **WHEN** агенту требуется `export-default`
- **THEN** его синтаксис и ограничения доступны в `references/js.md` и не представлены как общие для всех targets

#### Scenario: Target неизвестен
- **WHEN** конфигурация и команды проекта не позволяют определить target
- **THEN** инструкция направляет агента уточнить target, а не выбирать его по предположению

#### Scenario: Работа только с JavaScript
- **WHEN** задача затрагивает только код, компилируемый в JavaScript
- **THEN** инструкция направляет агента прочитать общую часть и `references/js.md`
- **AND** не требует читать `references/eval.md` и `references/java.md`

#### Scenario: Сборочный скрипт использует eval
- **WHEN** задача в JS-приложении затрагивает сборочный скрипт, исполняемый через `ly2k --target eval`
- **THEN** инструкция направляет агента дополнительно прочитать `references/eval.md`
- **AND** само по себе изменение сборки без использования eval не является основанием читать этот справочник

#### Scenario: Изменение нескольких targets
- **WHEN** задача затрагивает несколько targets, включая изменение общей семантики компилятора
- **THEN** инструкция направляет агента прочитать справочники всех затронутых targets
- **AND** не устанавливает JavaScript как универсальный target по умолчанию

#### Scenario: Общие контракты остаются доступны
- **WHEN** агент читает общую часть без справочников других targets
- **THEN** ему доступны общие формы, библиотечные контракты, включая regex, и краткие предупреждения об ограничениях переносимости
- **AND** подробности представления значений, host interop и целевой диагностики находятся в соответствующих справочниках

#### Scenario: Справочники подключены вместе со скиллом
- **WHEN** каталог скилла подключён симлинком в другом проекте приложения
- **THEN** все три справочника доступны по ссылкам из `SKILL.md` без файлов исходников компилятора или локальных путей автора

### Requirement: Скилл SHALL соответствовать текущей реализации

Содержание SHALL сверяться с реализацией и тестами всех трёх targets, используя спецификации как дополнительный источник контракта; одного README недостаточно. Правила разработки проекта SHALL требовать обновления соответствующих частей `SKILL.md` и `references/` при изменении описываемых пользовательских возможностей. Скилл SHALL описывать текущий компилятор без отдельных справочников для старых версий и без обещания совместимости с ними.

#### Scenario: Изменение пользовательской возможности
- **WHEN** изменение компилятора добавляет или меняет пользовательскую форму, кроссплатформенную функцию либо target-specific ограничение
- **THEN** правило завершения изменения требует актуализировать соответствующую часть скилла в `SKILL.md` и/или справочниках `references/`

#### Scenario: Устаревший README
- **WHEN** README расходится с подтверждённой реализацией и тестами
- **THEN** скилл описывает подтверждённые возможности текущего компилятора, а не копирует устаревшее ограничение
