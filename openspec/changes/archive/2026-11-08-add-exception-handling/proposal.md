# Proposal

## Why

В [issue #38](https://github.com/y2k/language/issues/38) обработка ошибок reload, очистка loader state, закрытие ресурсов и проверки ожидаемых ошибок требуют пользовательского `raw-code`. Нужны синхронные средства языка для JS/Java, сохраняющие исходную ошибку и результат успешной операции.

Реализация должна развивать существующий expression-to-statement lowering: значение `try` передаётся через временную переменную, а не через сгенерированную функцию. Это архитектурное требование, проверяемое по generated code, а не предположение об оптимизациях JVM.

## What Changes

- Добавить выражение `(try body... (catch error handler...)? (finally cleanup...)?)`: непустые тела, хотя бы одна секция, максимум один `catch` перед необязательным `finally`.
- Возвращать последнее значение тела или обработчика, включая `nil`/`false`; результат очистки игнорировать.
- На Java перехватывать `Exception`, на JS — любое синхронно выброшенное значение. Передавать обработчику исходный объект без преобразования в текст.
- Добавить `(throw error)` для выбрасывания вычисленного значения: `Throwable` на Java, любое значение на JS, без нового конструктора ошибок.
- Выполнять очистку один раз при нормальном и исключительном завершении, включая ошибку обработчика. Ошибка очистки заменяет предыдущую без автоматического сохранения причины или suppressed exceptions.
- Lower-ить `try` в native statement и присваивания результата на обоих targets. Не создавать для него Java `Supplier`, JS IIFE, callback или отдельный helper-метод, в том числе косвенно через окружающие `do`/`let`/`if`. В discarded-позиции результат не сохранять.
- Довести передачу statements до тел функций/callbacks и инициализаторов определений, сохранив порядок вычислений слева направо, защищённые области, lexical scope и metadata. Существующие helpers lowering переиспользовать; не добавлять параллельный компилятор или отдельный AST-анализ исключений.
- Для Java expression-valued `throw` добавить минимальный `throw_value(Object): Object` поверх существующего `sneaky_throw`: он бросает исходный `Throwable` и не создаёт callback. Это отдельное решение для Java typing/reachability, не разрешение оборачивать `try` в функцию.
- Явно обозначить отсутствие поддержки eval и FEX. Не вводить async/await, откат эффектов, переносимые классы ошибок или API получения сообщения.
- Обновить английский справочник и проверить сценарии issue целевыми тестами. `with-open` и миграция REPL остаются отдельными changes.
- Завершать реализацию code review, автоматическим исправлением подтверждённых замечаний в согласованном объёме и повторной проверкой исправлений.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `frontend-syntax`: грамматика новых специальных форм и проверка их структуры при компиляции JS/Java.
- `compiler-targets`: значение `try`, перехват и распространение ошибок, `finally`, `throw`, statement lowering без обёрток для `try`, порядок вычислений и защищённые области, отсутствие поддержки FEX.
- `eval-runtime`: явное отклонение достигнутых `try`/`throw` без исполнения их содержимого.

## Impact

Затронуты общий compiler lowering, JS/Java generators и их statement consumers, минимальные guards в eval/FEX, Java runtime helper для выражения `throw`, целевые samples и OCaml-тесты, английский справочник `skills/y2k-language/`. Новых зависимостей не требуется. **BREAKING**: формы `try` и `throw` становятся специальными в позиции вызова; приложения с одноимёнными вызовами потребуют переименования.

Исходники приложения REPL здесь не проверены: локальный `repl/` пуст. План покрывает возможности языка и воспроизводимые модели сценариев, а не правки внешнего приложения или Android-device тестирование.

## Предварительное изменение lowering

До реализации выполнить отдельный change `preserve-if-statement-lowering-order`. В него вынесены общий переход value-if на `(statements, result)`, сохранение порядка операндов и доставка этих prefixes до JS/Java body/initializer consumers. Здесь переиспользуется готовый механизм и проверяется его работа с try; повторная реализация общего преобразования if в этот change не входит.

## Выполнение после предварительного change

Этот change — план реализации exceptions поверх завершённого `preserve-if-statement-lowering-order`, а не патч к предыдущей попытке. Исследованная исходная ревизия: `5b012b22ac9fc2485eaeeb611f89903c2c3b4937`. На ней поддержки `try`/`throw`, общего exception parser, новых samples и `throw_value` ещё нет; их требуется создать. История чата, отменённый implementation diff и результаты прежних тестов не являются доказательством готовности.

Перед выполнением прочитать `design.md`, все три файла `specs/*/spec.md` и `tasks.md` этого change. Все задачи сброшены и должны быть выполнены и проверены по новой архитектуре. Если часть кода уже присутствует, сверить её с новым design, а не считать доказательством готовности. Для запуска в новой сессии: `/opsx-apply add-exception-handling`. Для переноса на базовую ревизию достаточно сохранить весь каталог этого change; удаление текущего рабочего diff не является шагом реализации.
