# Proposal

## Why

В issue #30 приложение events сортирует публикации через JS `.sort` и `localeCompare`: исходный массив изменяется, ключи вычисляются повторно, порядок зависит от locale. Нужна переносимая сортировка по вычисляемому ключу средствами языка.

## What Changes

- Добавить обычную функцию `(sort-by keyfn coll)` с фиксированными двумя аргументами на eval, JS и Java.
- Вычислять ключ один раз на элемент слева направо и возвращать стабильную сортировку по возрастанию без изменения входной коллекции.
- Поддержать строковые ключи либо числовые ключи, включая смесь целых и конечных binary64. Строковое сравнение не зависит от locale; общий порядок между targets гарантируется для ASCII.
- Оставить nil, составные ключи, смесь строк с числами, non-finite числа, пользовательские компараторы, дополнительные арности и публичные sort/compare вне объёма.
- Описать контракт и отличие от Clojure sort-by в английском справочнике.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `eval-runtime`: binding sort-by, вычисление ключей и стабильный числовой/строковый порядок.
- `compiler-targets`: тот же API и гарантии для JS/Java, включая плотные host-массивы JS.

## Impact

`backend_eval/eval_stdlib.ml`, оба runtime в `prelude/`, список runtime imports в `backend_compiler/js.ml`, общие и целевые тесты в `test/`, `skills/y2k-language/SKILL.md`. Используются стандартные сортировки платформ; новые зависимости, синтаксис и перегрузки не нужны. Compiler и runtime должны поставляться согласованно, чтобы compiled программы могли разрешить sort_by.
