## Context

Frontend уже раскрывает встроенные макросы в `frontend/builtin_macros.ml`, а все backends поддерживают необходимые core forms: `let*`, `if`, `=` и `nil`. Поэтому `case` можно реализовать только на уровне desugaring и сохранить одинаковую семантику для `eval`, `js` и `java`.

## Goals / Non-Goals

**Goals:**

- Добавить компактный выбор по значению с последовательной проверкой вариантов.
- Гарантировать однократное вычисление проверяемого выражения и ленивое вычисление результатов.
- Использовать существующие core forms и `Gensym.gensym`.

**Non-Goals:**

- Добавление отдельного AST-узла или backend-инструкции для `case`.
- Оптимизация выбора в jump table или hash lookup.
- Поддержка групп вариантов, pattern matching или Clojure-специфичных compile-time проверок констант.

## Decisions

Макрос будет зарегистрирован в существующем `Builtin_macros.builtin_macros`. Форма

```clojure
(case value match-1 result-1 match-2 result-2 fallback)
```

раскрывается концептуально в:

```clojure
(let* (fresh value)
  (if (= fresh match-1)
    result-1
    (if (= fresh match-2)
      result-2
      fallback)))
```

Fresh имя создаётся через `Gensym.gensym`, поэтому пользовательские bindings не могут быть захвачены. Генерация `let*` напрямую короче и не требует дополнительного прохода через пользовательскую форму `let`.

Хвост вариантов разбирается рекурсивно: пустой хвост даёт `nil`, одна оставшаяся форма становится fallback, а две и более формы образуют очередную ветвь `if`. Это сохраняет порядок сравнений и естественную ленивость `if`.

Альтернатива без временного binding отклонена, поскольку повторяла бы вычисление `value` в каждой проверке. Отдельная реализация в backends отклонена как дублирование уже существующей семантики core forms.

## Risks / Trade-offs

- [Линейное число сравнений для большого количества ветвей] → Это соответствует простому раскрытию в `if`; оптимизацию следует добавлять только при измеримой проблеме.
- [Формы `match` вычисляются во время последовательных сравнений, а не ограничиваются compile-time константами] → Зафиксировать это как текущую простую семантику и не заявлять полную совместимость с Clojure.
- [Ошибки в структуре раскрытия могут проявляться по-разному в backends] → Проверить AST раскрытия frontend-тестом и поведение общей sample-программой на всех targets.
