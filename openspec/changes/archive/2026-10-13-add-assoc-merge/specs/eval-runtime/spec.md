# Spec Delta

## ADDED Requirements

### Requirement: Eval SHALL предоставлять трёхаргументный assoc для map

Eval SHALL предоставлять без импорта `(assoc map key value)`, возвращающий map с добавленным или заменённым ключом без изменения исходника. Значение SHALL сохраняться без преобразования, включая false и nil. Обновление SHALL использовать существующее равенство ключей =; все совпадающие пары SHALL заменяться одной новой парой. Остальные пары SHALL сохраняться.

#### Scenario: Добавление и замена
- **WHEN** m равно `{:a 1}` и вычисляются `(assoc m :b 2)` и `(assoc m :a 3)`
- **THEN** результаты содержат соответственно a=1,b=2 и a=3; их count равен 2 и 1
- **AND** m сохраняет a=1 и count=1

#### Scenario: Ложные значения остаются полями
- **WHEN** выполняются `(assoc {} :x false)` и `(assoc {} :x nil)`
- **THEN** count каждого результата равен 1, get по x равен соответственно false и nil и не равен их строковым представлениям

#### Scenario: Существующее равенство ключей
- **WHEN** m равно `(hash-map 1 "first" 1.0 "second" "1" "text")` и r равно `(assoc m 1.0 "new")`
- **THEN** get r по 1 и 1.0 возвращает `"new"`, по `"1"` возвращает `"text"`, count r равен 2
- **AND** count m остаётся 3, get m по 1 по-прежнему возвращает `"first"`

### Requirement: Eval SHALL предоставлять двухаргументный merge для map

Eval SHALL предоставлять без импорта `(merge left right)`, возвращающий map без изменения обоих входов. Поля right SHALL заменять равные по = ключи left, включая значения false и nil. Непересекающиеся поля SHALL сохраняться. Вложенное значение SHALL заменяться целиком, без рекурсивного объединения. Для входов с дубликатами ключей переносимых гарантий нет.

#### Scenario: Правый приоритет и пустые map
- **WHEN** выполняются `(merge {:a 1 :b 2} {:a 3 :c 4})`, `(merge {} {:a 1})`, `(merge {:a 1} {})` и `(merge {} {})`
- **THEN** первый результат содержит a=3,b=2,c=4, следующие два содержат a=1, последний является пустой map
- **AND** исходные map не меняются

#### Scenario: False и nil перезаписывают прежнее значение
- **WHEN** r равно `(merge {:a 1 :b 2} {:a false :b nil})`
- **THEN** count r равен 2, get по a равен false, get по b равен nil

#### Scenario: Поверхностное объединение
- **WHEN** r равно `(merge {:nested {:a 1 :b 2}} {:nested {:a 3}})`
- **THEN** nested содержит только a=3; b не переносится из левой map

### Requirement: Eval SHALL проверять фиксированный контракт assoc и merge

Assoc SHALL принимать ровно три аргумента с map первым; merge SHALL принимать ровно две map. Иная арность, nil, list или скаляр вместо map SHALL давать Eval_error с именем операции. Nil SHALL NOT трактоваться как пустая map. Ключ и значение assoc SHALL подчиняться существующей модели значений map, без новых ограничений типов.

#### Scenario: Неверная арность
- **WHEN** вызываются `(assoc {})`, `(assoc {} :a 1 :b 2)`, `(merge {})` или `(merge {} {} {})`
- **THEN** возникает Eval_error соответствующей операции

#### Scenario: Обязательный аргумент map
- **WHEN** assoc получает nil, list или скаляр первым аргументом либо merge получает такое значение в любой позиции
- **THEN** возникает Eval_error соответствующей операции, включая merge с пустой второй map
