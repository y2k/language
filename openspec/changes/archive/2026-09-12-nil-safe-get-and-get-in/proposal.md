## Why

В issue #17 обработчики Telegram Update вынуждены защищать каждый вложенный lookup от отсутствующих данных: текущий `get` бросает исключение на `nil`. Nil-безопасный `get` и `get-in` позволят выразить такие чтения напрямую с одинаковым результатом на eval, JS и Java.

## What Changes

- Двухаргументный `get` возвращает `nil` для коллекции `nil`; keyword lookup получает это поведение через существующее раскрытие в `get`.
- Добавляется `(get-in collection keys)` с путём-вектором: последовательное чтение map keys и неотрицательных целых индексов, включая смешанные пути.
- Отсутствующий ключ, индекс за границей или промежуточный `nil` дают `nil`; пустой путь возвращает исходное значение; конечный `false` сохраняется.
- Продолжение пути через скаляр остаётся ошибкой. `nil`, map и строка вместо пути отклоняются. Поведение list-пути не специфицируется: существующая поддержка допустима без специального кода.
- Трёхаргументные варианты, новые типы коллекций для `get`, изменение truthiness, унификация некорректных индексов и destructuring на `nil` не входят в изменение.

## Capabilities

### New Capabilities

Нет новых самостоятельных capabilities.

### Modified Capabilities

- `eval-runtime`: nil-безопасный `get` и новая stdlib-функция `get-in` с согласованным контрактом пути.
- `compiler-targets`: тот же контракт в JS/Java runtimes и доступность `get-in` из compiled source.

## Impact

- `backend_eval/eval_stdlib.ml`: поведение `get`, реализация и регистрация `get-in`.
- `prelude/language_runtime.js`, `prelude/language_runtime.java`: runtime lookup.
- `backend_compiler/js.ml`: импорт `get_in`; Java использует существующий static wildcard import.
- `test/samples/*.clj` и существующие целевые тесты: общие позитивные сценарии и проверки ошибок.
- Изменение общего `get` также влияет на compiled destructuring; известное расхождение с отдельным механизмом evaluator документируется в design, без расширения контракта bindings.
- Новые зависимости не требуются. Spectator — контекст потребителя; его исходники не затрагиваются.
