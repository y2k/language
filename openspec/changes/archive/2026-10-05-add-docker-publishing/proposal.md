# Proposal

## Why

Сейчас запуск `language` требует локальной сборки OCaml-проекта, а Dockerfile и GitHub Actions для публикации образа отсутствуют. Готовый образ в Docker Hub позволит запускать CLI без установки сборочного окружения и получать актуальную версию после push в `main`.

## What Changes

- Добавить multi-stage Dockerfile: этап `builder` использует образ `ocaml/opam` на Debian 12 с OCaml 5.x, opam и Dune для обычной нативной сборки `language`; этап `runtime` использует `debian:bookworm-slim` и содержит только готовый бинарник и необходимые системные библиотеки. Упаковка пакетов и prelude не требуется. Первоначальная целевая платформа — `linux/amd64`.
- Предоставить запуск CLI через `docker run --rm -i y2khub/language:latest`, с чтением программы из stdin и передачей аргумента `--target eval|js|java` существующему CLI.
- Добавить GitHub Actions workflow, который при каждом push в `main` собирает и публикует образ как `docker.io/y2khub/language:latest`. Полный `make test` для eval/JS/Java выполняется внутри сборочного этапа Dockerfile; ошибка тестов останавливает сборку и публикацию.
- Использовать Docker Hub token из GitHub Actions secrets для аутентификации публикации.
- Описать в README локальную сборку, запуск контейнера и настройку секрета для публикации.

Полная статическая линковка отложена в отдельную будущую задачу: проверить сборку с musl и текущими зависимостями, отсутствие динамических зависимостей и запуск в `scratch`, чтобы бинарник можно было переносить через `COPY --from` без системных библиотек. Текущее изменение поставляет обычный бинарник в совместимом Debian-окружении.

## Capabilities

### New Capabilities

- `container-distribution`: сборка и запуск контейнерного дистрибутива CLI, а также автоматическая публикация проверенного образа в Docker Hub при push в `main`.

### Modified Capabilities

Нет.

## Impact

- Новые файлы: `Dockerfile`, `.dockerignore`, workflow в `.github/workflows/`; обновление `README.md`.
- Сборочный этап содержит OCaml, Node.js и JDK и выполняет существующий `make test` с временным `LY2K_PACKAGES_DIR`. Финальный образ получает только executable `language`; тестовые зависимости, каталог и переменная в него не переносятся.
- Точный существующий тег `ocaml/opam` для Debian 12 и OCaml 5.x требуется проверить перед реализацией; системные библиотеки финального образа определить по динамическим зависимостям собранного бинарника.
- Внешние системы: GitHub Actions и репозиторий Docker Hub `y2khub/language`; для публикации нужен настроенный secret с токеном, имеющим право записи в этот репозиторий.
- Проверка поставки: полный suite eval/JS/Java внутри Docker-сборки. При реализации отдельно проверяется запуск финального контейнера. Семантика targets регулируется существующей спецификацией `compiler-targets`; новый контракт относится к распространению CLI в контейнере.
