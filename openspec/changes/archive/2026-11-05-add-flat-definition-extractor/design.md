# Design

## Context

См. `proposal.md`. `add-flat-definition-target` задаёт текстовый bundle и canonical keys в `compiler-targets`. Extractor (unpacker) получает этот bundle из stdin; `add-flat-definition-interpreter` получает уже распакованные файлы RHS.

## Goals / Non-Goals

**Goals:** последовательная материализация RHS с точным сохранением bytes, безопасными именами и пропуском неизменившихся файлов.

**Non-Goals:** компиляция, разбор FEX, исполнение/reload, изменения make, доставка, объединение bundles, удаление устаревших файлов, предварительная проверка всего пакета, staging, temp+rename, атомарная запись и rollback.

## Decisions

### 1. Отдельный CLI-модуль

Разместить логику в отдельной Dune-библиотеке `fex_unpack/` с модулем `fex_unpack.ml` и зависимостью только от `unix`. `bin/dune` подключает библиотеку, а `bin/main.ml` выбирает `--unpack-fex --output-dir PATH` и передаёт параметры без вызова frontend. Сохранить согласованный CLI; extractor — название capability, unpacker — название режима.

### 2. Последовательное чтение

Читать пары key/Base64 по контракту compiler; поддерживать LF, CRLF и последний payload без LF, не пропускать пустые строки. Проверять безопасное canonical filename и декодировать payload каждой пары без разбора FEX и нормализации bytes. EOF после имени и неверный Base64 — ошибки; EOF между парами завершает bundle. Не снимать percent/case escapes и не сканировать case-only коллизии. Правила кодирования принадлежат compiler, а не дублируются здесь.

Обрабатывать по одному определению вместо предварительной проверки пакета: это сохраняет простой потоковый контракт и допускает частичный результат при ошибке.

### 3. Запись и отчёт

Создать каталог при необходимости. Сравнить bytes существующего файла: при совпадении сохранить файл и mtime, иначе перезаписать. Повторный key проходит тот же путь, последнее вхождение побеждает. Соседние файлы не удалять. Не вводить staging, temp+rename или rollback. После каждой успешной пары печатать key с LF в stdout, включая повторные и неизменившиеся; диагностику направлять в stderr.

### 4. Границы интеграции

```sh
ly2k --target fex < app.clj > app.fex
ly2k --unpack-fex --output-dir out < app.fex > load-order.txt
```

Список keys может использовать host, но распаковка не исполняет initializers и не запускает reload. Доставка, например `adb push --sync`, выполняется отдельно после локальной распаковки. Несколько bundles обрабатывает shell; API объединения не добавляется.

## Risks / Trade-offs

- Ошибка оставляет частично обновлённый каталог; обрыв между парами не обнаруживается → документировать границы, не обещать транзакционность или полноту пакета.
- Устаревшие файлы сохраняются → очистка остаётся отдельной операцией.
- Полный payload одного определения находится в памяти; ограничения длины filename сохраняются → не обещать неограниченные размеры.

## Migration Plan

После compiler подключить opt-in CLI и fixtures к `make test`, обновить английский справочник примером source → bundle → каталог. Проверять extractor без evaluator; сквозное исполнение на JS/Java относится к interpreter change.
