# Proposal

## Why

После добавления regex в eval один исходник ещё нельзя надёжно запускать на всех targets: JS не импортирует regex bindings, а нативные runtimes расходятся в равенстве и обработке пустых совпадений. Нужен проверяемый переносимый контракт для текстового поиска и замены без эмуляции целого regex-движка.

## What Changes

- Подключить `re-pattern`, `re-find`, `re-replace` в compiled JS и закрепить доступность API в Java без пользовательских imports.
- Определить переносимое ASCII-подмножество шаблонов, первое полное совпадение, истинную пустую строку и настоящий nil при отсутствии совпадения.
- **BREAKING**: согласовать JS/Java с eval для бинарного сравнения непосредственно regex-значений (regex не равен себе) и пропуска пустого совпадения сразу после непустого при глобальной замене. Закрепить строгий конец строки `$` тестами.
- Сохранить буквальную замену, повторное использование regex, истинность и текст `#<regex>`; проверять арности и runtime-типы до поиска.
- Добавить общие fixtures и целевые проверки ошибок compiled programs; обновить английский справочник с границами переносимости.
- Полная унификация Unicode, расширений диалектов, представления ключей map, равенства коллекций и финального вывода runner в объём не входит. Eval сохраняет существующий контракт.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `compiler-targets`: regex API в JS/Java, переносимые поиск/замена, непрозрачные значения и ошибки аргументов, согласованные с eval в указанной области.

## Impact

- `backend_compiler/js.ml`: стандартный runtime import.
- `prelude/language_runtime.js`, `prelude/language_runtime.java`: symlinks на companion-файлы отдельного репозитория `~/project/packages`: `prelude/1.0.0/js/language_runtime.js` и `prelude/1.0.0/java/language_runtime.java`. Эти два файла включены пользователем в объём change: regex API, adapters и прямое бинарное равенство поставляются совместно с compiler import.
- `test/samples/`, целевой OCaml suite и `test/dune`: выполнение исходников на eval, Node и JVM, отрицательные сценарии.
- `skills/y2k-language/SKILL.md`: общий API и отдельные ограничения targets.
- Новых зависимостей нет: Re 1.13.2, JavaScript RegExp и Java Pattern сохраняются. Userscript file I/O и bundler не расширяются.
- Companion runtime уже содержал незакоммиченные regex API и исправление истинности строк `"false"`/`"nil"` до этой реализации. Эти изменения сохраняются; при совместной поставке runtime должен включать исправление истинности как зависимость ранее согласованного контракта языка, а не как новую regex-семантику.
