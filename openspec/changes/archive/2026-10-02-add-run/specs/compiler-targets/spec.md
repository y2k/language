# Spec Delta

## ADDED Requirements

### Requirement: Java target SHALL разрешать ссылки на свои именованные функции в namespace

Передача своей top-level функции как значения SHALL использовать фактический класс текущего namespace. Это SHALL работать как без ns, так и во вложенном namespace, включая передачу callback в map и связывание функции локальным binding, без пользовательского cast.

#### Scenario: Named callback во вложенном namespace
- **WHEN** программа в namespace `checks.callbacks.core` передаёт собственную unary-функцию duplicate в map непосредственно и через локальное функциональное значение
- **THEN** generated Java компилируется и возвращает результаты callback в порядке исходной коллекции
- **AND** программа без ns сохраняет работоспособность передачи именованных функций

### Requirement: Compiler targets SHALL предоставлять run! для последовательных эффектов

JavaScript и Java SHALL предоставлять без пользовательского импорта обычную функцию `(run! f items)` для unary callback и list/vector. Run! SHALL немедленно вызывать callback ровно один раз для каждого элемента в исходном порядке, передавая только элемент, игнорировать результаты и SHALL NOT собирать результирующую коллекцию. После успешного обхода SHALL возвращаться nil/null. Пустая коллекция SHALL NOT вызывать callback и SHALL возвращать nil/null. Именованная функция, лямбда и локальное функциональное значение SHALL поддерживаться. Поддержка maps, nil как коллекции и произвольных iterable не входит в контракт. Ошибка callback SHALL прерывать обход и передаваться наружу без отката выполненных эффектов; единый host exception type и текст диагностики не требуются.

#### Scenario: Переносимый порядок и результат
- **WHEN** `(run! f [1 2 3])` записывает аргументы в Atom, а callback возвращает произвольные значения
- **THEN** после возвращения run! журнал содержит ровно 1, 2, 3 в этом порядке, как на eval
- **AND** результат равен nil, ложен и не равен строке `"nil"`

#### Scenario: Пустая коллекция
- **WHEN** compiled программа выполняет `(run! f [])` с callback, изменяющим Atom
- **THEN** Atom не изменяется и результат равен nil

#### Scenario: Формы callback и вложенный namespace
- **WHEN** программа в namespace `checks.effects.core` передаёт run! именованную unary-функцию, лямбду или локальное функциональное значение
- **THEN** generated JS и Java компилируются с обычным runtime и выполняют ожидаемые эффекты

#### Scenario: Ошибка прерывает обход
- **WHEN** callback выполняет наблюдаемый эффект и затем завершается ошибкой на втором элементе из трёх
- **THEN** третий callback не вызывается, ошибка выходит из run!, эффекты первого и второго вызовов сохраняются

### Requirement: JavaScript run! SHALL поддерживать массивы host-объектов

JavaScript run! SHALL принимать обычные плотные JS-массивы, включая массивы DOM-элементов, полученные через Array.from. Элементы SHALL передаваться callback без преобразования или копирования объектов. Непосредственный обход NodeList и поведение при изменении состава массива во время обхода не специфицируются.

#### Scenario: Скрытие тредов через interop
- **WHEN** массив host-объектов thread передаётся `(run! hide-thread! threads)`, где hide-thread! вызывает `(.click (.querySelector thread ".post__btn_type_hide"))`
- **THEN** для каждого исходного объекта вызывается querySelector с указанным selector и затем click найденной кнопки ровно один раз в порядке массива
- **AND** run! возвращает nil/null и не собирает результаты click
