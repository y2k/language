# Design

## Context

Мотивация — в `proposal.md`. List и vector используют одно runtime-представление; concat уже присутствует на всех targets. Eval регистрирует обычные функции в `Eval_stdlib.env`, JS импортирует явный список runtime exports, Java использует static wildcard import. Старый Java-prelude в packages содержит conj с копированием и добавлением в конец. Изменение пересекает три runtime и JS generator, поэтому решения фиксируются совместно.

## Goals / Non-Goals

**Goals:** использовать текущие представления коллекций и обычные вызовы функций, сохранив переносимость и Promise-сценарий #32.

**Non-Goals:** новые AST-формы, lowering, persistent vector, поддержка map/set/nil как коллекции, variadic conj, Clojure-добавление в начало list и общая диагностика символов.

## Decisions

1. **Обычная runtime-функция.** В eval добавить функцию и binding в `backend_eval/eval_stdlib.ml`, в JS/Java — runtime-функции рядом с concat, в `backend_compiler/js.ml` — импорт conj. Java generator менять не требуется. Макрос через concat отвергнут: обычная функция соответствует остальной stdlib и не требует изменений frontend.
2. **Поверхностное добавление одного элемента.** Использовать стандартное добавление к OCaml list и копирование Java list; в JS переиспользовать concat с одноэлементной коллекцией либо эквивалентное короткое копирование. Нельзя передавать value напрямую в host Array.concat: массив-value должен остаться одним элементом. Не вводить отдельные helpers ради этой операции.
3. **Границы аргументов.** Eval следует существующему pattern matching stdlib и выдаёт Eval_error для неподходящих аргументов. На compiled targets переносимая гарантия охватывает только два аргумента и list/vector; отдельная диагностика неправильных программ не проектируется. Существующие проверки коллекций при переиспользовании concat сохраняются.
4. **Проверка через существующие runners.** Общий `test/samples/conj.clj` во вложенном namespace проверяет порядок, пустой вход, неизменность, вложенный элемент, nil/false и общую ссылку Atom. Проверки значений используют count/get и бинарное равенство, выводятся через str. Целевой `test/samples/js/conj_batch.clj` воспроизводит исходную Promise-цепочку batch, проверяет несколько эффектов и пустой вход. Завершение Promise можно дождаться top-level raw-code в ES module, а `test` вернуть уже готовый текст проверок; менять sample-runner не требуется. Там же можно проверить host identity. Внешний пакет не становится зависимостью тестов.
5. **Общая операция вместо локальной замены.** `(concat result [x])` исправляет один batch, но не остальные существующие вызовы conj. Согласованный общий binding устраняет эту зависимость для совместимых версий compiler/runtime без изменений пакетов.

## Risks / Trade-offs

- Копирование коллекции при каждом добавлении даёт O(n²) для накопления n результатов → принять текущую простую модель; оптимизацию рассматривать при измеренной необходимости, обозначить потолок коротким `ponytail:` комментарием при реализации.
- Новый JS compiler импортирует conj и для исходников без его вызовов → поставлять compiler вместе с обновлённым runtime, как другие stdlib additions.
- Название conj может вызвать ожидание Clojure-семантики → явно описать в английском справочнике фиксированную арность и добавление в конец для list/vector.
- Локальная регрессия воспроизводит batch, но не проверяет всю внешнюю систему сборки packages → не заявлять совместимость всех пакетов на основании одного сценария.

## Migration Plan

Обновить compiler и runtime совместно обычным процессом проекта; `make test` собирает compiler и копирует runtime в prelude через существующий Makefile. Потребители пересобирают generated JS/Java с этой парой. Откат выполняется совместно для compiler/runtime; потребители conj при откате вновь требуют прежнюю совместимую поставку либо отдельную миграцию исходника.
