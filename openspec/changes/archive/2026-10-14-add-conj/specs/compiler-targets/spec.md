## ADDED Requirements

### Requirement: Compiler targets SHALL предоставлять двухаргументный conj

JS и Java SHALL предоставлять без пользовательского импорта `(conj items value)` для list/vector и одного значения. Результат SHALL быть новой коллекцией с исходными элементами в прежнем порядке и value в конце, без изменения входа. List и vector SHALL иметь одинаковую семантику. Другие арности, map и nil вместо коллекции не входят в переносимый контракт.

#### Scenario: Пустой вход и добавление в конец
- **WHEN** программа выполняет `(conj [] 1)`, `(conj [1 2] 3)` и `(conj (list 1 2) 3)`
- **THEN** JS и Java возвращают соответственно коллекции с 1; 1, 2, 3; 1, 2, 3, как eval
- **AND** исходные коллекции сохраняют длину и элементы

#### Scenario: Вложенный namespace
- **WHEN** программа с namespace `checks.collections.core` вызывает conj без пользовательских imports
- **THEN** generated JS и Java компилируются и исполняются с соответствующим runtime без неразрешённого символа conj

### Requirement: Compiler conj SHALL сохранять значения поверхностно

Conj SHALL сохранять элементы без преобразования, фильтрации и рекурсивного копирования. Nil, false, 0 и пустая строка SHALL оставаться элементами. Коллекция в позиции value SHALL добавляться одним элементом. JS SHALL поддерживать обычные плотные host-массивы с сохранением ссылок на объекты; sparse arrays и произвольные iterable вне контракта.

#### Scenario: Типы и вложенность
- **WHEN** через conj последовательно добавлены nil, false, 0, пустая строка и `[1 2]`
- **THEN** результат содержит пять элементов с исходными типами, последний — коллекция из двух элементов
- **AND** извлечённые nil и false не равны строкам `"nil"` и `"false"`

#### Scenario: Сохранение ссылок
- **WHEN** исходный либо добавляемый элемент является Atom
- **THEN** изменение Atom, извлечённого из результата, наблюдается через исходную ссылку
- **WHEN** JS conj получает плотный host-массив объектов и добавляемый объект
- **THEN** результат является новым массивом, а все объекты сохраняют JS identity

### Requirement: JS conj SHALL поддерживать последовательное накопление Promise-результатов

Скомпилированная JS Promise-цепочка по образцу effect/batch SHALL выполнять conj внутри then без неразрешённого символа и накапливать результаты в порядке эффектов. Conj SHALL работать как обычная синхронная операция коллекции внутри callback; управление асинхронностью остаётся у Promise-цепочки.

#### Scenario: Несколько эффектов
- **WHEN** batch начинает с `Promise.resolve([])`, последовательно запускает два эффекта через then и добавляет каждый результат через `(conj result x)`
- **THEN** итоговый Promise разрешается коллекцией двух результатов в исходном порядке
- **AND** второй эффект запускается после завершения первого

#### Scenario: Пустой batch
- **WHEN** та же цепочка получает пустой список эффектов
- **THEN** итоговый Promise разрешается пустой коллекцией без вызовов эффектов
