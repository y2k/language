# Proposal

## Why

В issue #22 дробные веса теряются: eval отвергает дробные аргументы, а Java обрезает их до целых перед вычислением. Нужны работающие `+`, `-`, `*` и общие интеграционные тесты, включая дальнейшее использование результатов.

## What Changes

- Поддержать дробные и смешанные числовые аргументы `+`, `-`, `*` на eval, Java и JS с обычной двоичной плавающей точкой.
- Сохранить существующую арифметику целых в переносимом signed 32-bit диапазоне, арности, порядок свёртки и правило `(- x)` → `x`.
- Согласовать целые результаты дробной арифметики в этом диапазоне: `(str (+ 0.5 0.5))` возвращает `"1"`, `(= (+ 0.5 0.5) 1)` возвращает `true` на всех targets.
- Добавить общие sample-тесты для дробных, смешанных и составных вычислений, нормализации результатов и сохранения целочисленных операций.
- Уточнить числовые ограничения в `skills/y2k-language/SKILL.md` и сузить соответствующие открытые вопросы.
- **BREAKING**: Java больше не обрезает дробные операнды этих трёх операций; код, полагавшийся на усечение, получит другие результаты. Java runtime сможет возвращать дробное число вместо исключительно `Integer`.

Деление, операции порядка `<`, `>`, `<=`, `>=`, произвольная точность, переполнение и полный пересмотр равенства всех числовых литералов не входят в change. Это частичное решение issue #22, а не закрытие всех его требований.

## Capabilities

### New Capabilities

- `fractional-arithmetic`: общий контракт дробных `+`, `-`, `*`, переносимых результатов и межцелевых проверок.

### Modified Capabilities

- `eval-runtime`: сузить неопределённость дробной арифметики до поведения за пределами нового контракта.
- `open-questions`: отделить согласованные дробные операции от оставшихся вопросов числовой модели.

## Impact

Основные точки изменения: `backend_eval/eval_stdlib.ml`, `prelude/language_runtime.java`, при необходимости `prelude/language_runtime.js`, общие fixtures в `test/samples/` и `skills/y2k-language/SKILL.md`. Используется существующий harness `test/test.ml`, который исполняет один sample через eval, Node и JVM. Новые зависимости и отдельный тестовый runner не нужны. Генераторы литералов и представление значений eval не требуют заранее запланированной переработки.
