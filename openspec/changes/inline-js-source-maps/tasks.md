# Tasks

План повторной реализации после отдельно согласованного отката. Все чекбоксы относятся к новому проходу. Исторический успех предыдущего кода не закрывает эти задачи. Откат здесь не выполняется и не считается задачей реализации.

Единицы поставки — группы 1, 2 и 3 целиком: каждая даёт работающий результат с тестами и документацией. Этапы 2 и 3 независимо опираются на этап 1; их можно выполнять в любом порядке. Полный change завершён только после всех трёх этапов и итоговой сверки.

## Порядок выполнения

Prerequisite: завершён и принят отдельный change `refactor-js-emission`. Переход со строк на отложенные фрагменты и его побайтовая проверка выполняются там, до добавления карты.

Один запуск apply выполняет только один этап: первую незавершённую группу 1, 2 или 3, включая её тесты и документацию.

После завершения группы остановиться и представить результат для приёмки. Следующую группу начинать только после отдельного разрешения пользователя. Разрешение выполнить change не означает разрешения выполнить все группы. Эта граница ограничивает общий цикл apply «до завершения всех задач».

Итоговую сверку группы 4 выполнять вместе с последним этапом.

## 1. Грубая inline-карта — найти проблемную функцию

**Зависимости:** генератор отложенных фрагментов после `refactor-js-emission`. **Польза:** стек указывает на исходную верхнеуровневую форму вместо JS.

- [ ] 1.1 Добавить небольшой writer/codeс v3 в `backend_compiler/source_map.ml`: текст, scoped origin, UTF-16 generated positions, Base64 VLQ и inline JSON. В целевом `test/js_source_map_test.ml` через Node SourceMap проверить mapped/unmapped сегменты, отрицательные deltas, Unicode, CRLF между записями, CR/U+2028/U+2029 и точное восстановление `sourcesContent`; зарегистрировать suite в `test/dune`.
- [ ] 1.2 Подключить `--source-map`, default `user.clj` и исходный stdin через CLI/runner к top-level сборке JS; направить запись существующих фрагментов через writer с origin верхнеуровневой формы. Node-тест должен показывать `user.clj:2:1` для ошибки внутри `defn` на строке 2, точное начало прямой top-level формы, исходный тип ошибки и ненулевой exit code; проверить явную ошибку карты для eval/Java.
- [ ] 1.3 Проверить этап целиком: отсутствие карты по умолчанию, неизменный исполняемый JS/эффекты, runtime frame с собственной JS-позицией и корректный учёт пролога. Сравнить обычный вывод с эталоном до изменения в отдельных процессах. Обновить README и английский справочник примером запуска `.mjs`, default `user.clj`, встроенным исходником и явным ограничением до top-level формы; выполнить пример и `make test`.

## 2. Настоящее имя исходника — перейти к файлу приложения

**Зависимости:** только этап 1. **Польза:** стек содержит реальный source path. **Граница:** CLI/runner и source identity writer; точность mapping не меняется.

- [ ] 2.1 Добавить `--source-file PATH` с разрешением относительно generated JS и URL-экранированием `#`, `?`, `%`; CLI/Node-тестами проверить default `user.clj`, путь с пробелами в другом каталоге и буквальные имена `a#b.clj`, `a?b.clj`, `a%20b.clj`. Использовать ошибочный top-level вызов, чтобы проверки были независимы от этапа 3.
- [ ] 2.2 Проверить отсутствие чтения PATH и отсутствие эффекта `--source-file` без карты; описать правило путей и пример сборки в README и английском справочнике, выполнить пример и `make test`. Этап завершён при корректном первом пользовательском frame с переданным именем и неизменной точности по сравнению с его исходной базой.

## 3. Точные позиции — найти конкретный ошибочный вызов

**Зависимости:** только этап 1. **Польза:** стек различает выражения внутри функции. **Граница:** генератор и origin; CLI и кодировщик карты переиспользуются, а реализованный этап 2 сохраняется.

- [ ] 3.1 Добавить scoped origin на уровне выражений поверх существующих фрагментов, с восстановлением родительского после receiver/callee/аргумента. Node-тестами проверить прямой/member/constructor вызов, ошибку внутреннего и внешнего вызова, несколько форм на строке, цепочку пользовательских frames. Заменить промежуточное ожидание `user.clj:2:1` для примера `fail` на точное `user.clj:3:3`; сравнивать полные координаты первого пользовательского frame, не пропуская generated JS-frame.
- [ ] 3.2 Проверить происхождение через threading, `let`/destructuring, `if`/`do`, параметры с destructuring, callback и Promise; добавить Unicode/CRLF перед выражением и многострочный raw-code с JS line terminators. Проверить, что runtime остаётся JS-frame, а ошибочный вызов после raw-code не получает его позицию. Для этого использовать default `user.clj`, без зависимости от этапа 2.
- [ ] 3.3 Обновить README и английский справочник до точности выражений, сохранив ограничения raw-code/runtime и существующий раздел имён, если этап 2 выполнен. Выполнить документированный пример, сравнить JS без карты с эталоном исходного генератора и запустить `make test`.

## 4. Итоговая сверка всех этапов

- [ ] 4.1 После этапов 1–3 сверить каждый сценарий delta spec, в том числе совместную работу точных координат с пользовательским путём, пройти `make test`, форматирование изменённых OCaml-файлов, `git diff --check` и `openspec validate inline-js-source-maps --strict`. Только этот результат означает готовность полного change.

## Результаты повторной реализации

- `make test`: 476 тестов прошли, включая 33 проверки source maps через CLI, runner и Node.
- 86 обычных JS-результатов совпали с исходным генератором; рефакторинг фрагментов сохранил все 172 результата с грубой картой и без неё.
- Пример README выполнен: `SyntaxError`, `program.clj:3:3`, ненулевой exit code.
- OCaml-файлы отформатированы; `git diff --check` и строгая валидация change прошли.
- Независимое финальное ревью замечаний не обнаружило.

## Исторические результаты предыдущей реализации

- До перепланирования `make test` прошёл: 427 тестов, включая 18 source-map checks. Это справка, не результат нового прохода.
- Node показал `SyntaxError` и `program.clj:3:3` в примере README. Ошибка имён с `#`, `?`, `%` была воспроизведена и исправлена URL-экранированием.

- Независимое ревью сравнило 75 JS samples с исходным генератором: обычный вывод совпал побайтово. Последующий переход к отложенным фрагментам сохранил все 150 результатов этих программ с картой и без карты.
