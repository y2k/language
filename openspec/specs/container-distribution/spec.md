# container-distribution Specification

## Purpose

Предоставить готовый контейнерный дистрибутив CLI `language`, который можно собрать из исходников и запускать без локального OCaml-окружения, с автоматической публикацией проверенного образа в Docker Hub.

## Requirements

### Requirement: Образ SHALL собираться из исходников проекта

Проект SHALL предоставлять Dockerfile, позволяющий собрать образ для `linux/amd64` из чистого checkout без локальной установки OCaml, opam или Dune и без предварительно собранных файлов в `_build`.

#### Scenario: Локальная сборка из чистого checkout
- **WHEN** пользователь с работающим Docker и доступом к источникам зависимостей выполняет `docker build --platform linux/amd64 -t language .` в чистом checkout
- **THEN** сборка завершается успешно и создаёт образ с бинарником `language`, собранным из этого checkout

### Requirement: Docker-сборка SHALL запускать полный suite

Dockerfile SHALL выполнять `make test` для eval, JS и Java внутри сборочного этапа с необходимыми OCaml, Node.js и JDK. Финальный этап SHALL получать бинарник только из успешно проверенного сборочного этапа. Отдельные шаги запуска тестов и установки toolchain в GitHub Actions SHALL NOT требоваться.

#### Scenario: Тесты при локальной сборке
- **WHEN** Docker выполняет сборочный этап без готового кеша для текущих исходников и тестов
- **THEN** внутри этапа запускается полный `make test` для eval, JS и Java

#### Scenario: Ошибка тестов останавливает сборку
- **WHEN** тест в сборочном этапе завершается ошибкой
- **THEN** Docker-сборка возвращает ненулевой код и финальный образ этого запуска не создаётся

### Requirement: Финальный образ SHALL содержать готовое окружение запуска

Финальный образ SHALL содержать нативный бинарник `language` и необходимые ему системные библиотеки. Образ SHALL NOT включать пакеты, prelude или предустанавливать `LY2K_PACKAGES_DIR`. OCaml, opam и Dune SHALL оставаться в сборочном этапе. Контракт запуска относится к поставляемому образу; переносимость отдельного бинарника в произвольные образы и запуск в `scratch` не гарантируются.

#### Scenario: Запуск без сборочного окружения
- **WHEN** пользователь запускает собранный образ для `linux/amd64`
- **THEN** CLI запускается без установки дополнительных системных библиотек
- **AND** финальный образ не содержит OCaml, opam и Dune

#### Scenario: Поставка только CLI
- **WHEN** пользователь исследует финальный образ
- **THEN** `/usr/local/bin/language` доступен, пакетный каталог `/opt/language/packages` отсутствует и переменная `LY2K_PACKAGES_DIR` не задана образом

### Requirement: Контейнер SHALL предоставлять интерфейс существующего CLI

Запуск контейнера SHALL непосредственно вызывать `language`, передавать ему аргументы, stdin, stdout, stderr и код завершения. Без аргументов SHALL использоваться `eval`; `--target eval|js|java` SHALL сохранять существующее поведение CLI: вычисление либо генерацию исходного кода.

#### Scenario: Вычисление программы из stdin
- **WHEN** пользователь передаёт `(str "Hello, " "world!")` в stdin команды `docker run --rm -i y2khub/language:latest`
- **THEN** stdout содержит `Hello, world!` с завершающим переводом строки и процесс завершается с кодом 0

#### Scenario: Выбор target
- **WHEN** пользователь передаёт корректную программу в stdin контейнера с аргументами `--target js` или `--target java`
- **THEN** stdout содержит тот же сгенерированный исходный код, что и CLI из той же версии проекта с теми же аргументами и вводом

#### Scenario: Ошибка CLI
- **WHEN** контейнер запущен с аргументами `--target unknown`
- **THEN** процесс завершается с ненулевым кодом и stderr содержит `unknown target: unknown`

### Requirement: Push в main SHALL публиковать проверенный образ

GitHub Actions SHALL при каждом push в `main` собирать образ этого commit и публиковать его для `linux/amd64` как `docker.io/y2khub/language:latest`. Тесты SHALL выполняться внутри Docker-сборки. Публикация SHALL выполняться только после успешной сборки; push в другие ветки SHALL NOT публиковать этот тег.

#### Scenario: Успешная публикация
- **WHEN** происходит push в `main`, настроен доступ к Docker Hub и Docker-сборка с тестами завершается успешно
- **THEN** `docker.io/y2khub/language:latest` получает образ этого commit

#### Scenario: Проверка не пройдена
- **WHEN** Docker-сборка, включая выполнение `make test`, завершается ошибкой
- **THEN** workflow завершается с ошибкой и не выполняет публикацию образа этого запуска

#### Scenario: Push в другую ветку
- **WHEN** происходит push в ветку, отличную от `main`
- **THEN** workflow публикации не обновляет `docker.io/y2khub/language:latest`

### Requirement: Публикация SHALL использовать секрет Docker Hub

Workflow SHALL получать Docker Hub token из GitHub Actions secrets для аутентификации с правом записи в `y2khub/language`. Токен SHALL NOT храниться в исходниках или включаться в публикуемый образ.

#### Scenario: Аутентификация публикации
- **WHEN** workflow публикует образ при настроенном секрете Docker Hub
- **THEN** аутентификация использует этот секрет, а токен не передаётся в сборку образа и не записывается в его слои

### Requirement: README SHALL описывать использование контейнерного дистрибутива

README SHALL содержать команды локальной сборки и запуска через stdin, выбор target, описание полного прогона тестов внутри Docker-сборки и настройку GitHub Actions secret для публикации. Документация SHALL указывать поддержку `linux/amd64` и различать генерацию JS/Java и исполнение сгенерированного кода, требующее runtime-файлов из репозитория и Node.js/JDK.

#### Scenario: Настройка и запуск по документации
- **WHEN** пользователь следует README
- **THEN** он может собрать образ, выполнить пример eval, выбрать JS/Java target и определить имя секрета и необходимые права Docker Hub token для публикации
