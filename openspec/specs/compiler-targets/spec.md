# Compiler Targets Spec

## Purpose

Describe the current runner target dispatch, compiler lowering, JavaScript generation, and Java generation behavior.

## Requirements

### Requirement: Generated try SHALL NOT introduce function wrappers

На JS/Java generated `try` SHALL исполняться непосредственно в исходном body или initializer. Compiler SHALL NOT создавать Supplier, IIFE, callback или helper-метод ради результата try, включая обёртку через enclosing do/let/if. Пользовательские функции и callbacks SHALL сохраняться как границы исполнения. Это ограничение generated source, а не требование к JIT.

#### Scenario: Try в значении без дополнительной функции
- **WHEN** try находится в результате функции, аргументе, условии, RHS let, nested do/if либо операнде throw
- **THEN** generated source содержит native try и доступный потребителю результат без дополнительной функции вокруг try
- **AND** statements остаются в исходной ветке или защищённой секции, включая вложенные try

#### Scenario: Отброшенный try без результата
- **WHEN** результат try не используется, в том числе в непоследней форме функции или финальной форме Java void-callback
- **THEN** generated source содержит native try без result binding, return результата или вызываемой обёртки

#### Scenario: Try в определении
- **WHEN** initializer top-level def содержит try, непосредственно или внутри do/let/if/вызова
- **THEN** инициализация исполняет native try без дополнительной функции и публикует полученное значение определения
- **AND** определения инициализируются в исходном порядке

### Requirement: Lowered try SHALL сохранять порядок вычисления операндов

JS/Java SHALL сохранять вычисление операндов слева направо при извлечении statements из try: вычисляемый callee или receiver, затем аргументы; значения коллекций — в исходном порядке. Ошибка SHALL прекращать последующие вычисления. Извлечение SHALL NOT расширять защищённую область try на соседние операнды.

#### Scenario: Эффекты до и после try
- **WHEN** `(f (before) (try (work) (finally (clean))) (after))` записывает имена исполняемых операций
- **THEN** успешный журнал равен before,work,clean,after,f, каждая операция выполнена один раз

#### Scenario: Ошибка раннего операнда
- **WHEN** before выбрасывает ошибку до try в следующем аргументе того же вызова
- **THEN** тело, catch и finally этого try не исполняются, поздние аргументы и сам вызов не исполняются
- **AND** ошибка достигает внешней защищённой области, если она есть

#### Scenario: Ошибка защищённого операнда
- **WHEN** try в аргументе завершается необработанной ошибкой
- **THEN** более ранние операнды уже вычислены, cleanup исполнен один раз, а более поздние операнды и вызов не исполняются

#### Scenario: Callee receiver и несколько try
- **WHEN** вычисляемый callee или host receiver имеет эффект, а два аргумента содержат try
- **THEN** callee/receiver вычисляется один раз первым, затем оба аргумента со своими cleanup последовательно, затем выполняется вызов
- **AND** host typing и привязка receiver сохраняются

#### Scenario: Try в значениях коллекции
- **WHEN** list/vector/map содержит значения с эффектами до и после значения с try
- **THEN** эффекты происходят в исходном порядке, а значения и их identity сохраняются

#### Scenario: Невыбранная ветка и отложенная функция
- **WHEN** try находится в невыбранной ветке if или внутри созданного, но ещё не вызванного callback
- **THEN** ни тело, ни catch, ни finally этого try не исполняются

### Requirement: Java statement try SHALL поддерживать host-контексты

Java SHALL компилировать try с checked exceptions в methods, typed value/void callbacks, gen-class bridges и static initializers, сохраняя правила host boundary. Во void/discard позиции SHALL допускаться финальный host void call; ранее вычисленные значения SHALL не становиться недопустимыми Java statements. Java-specific metadata SHALL NOT менять семантику JS functions.

#### Scenario: Непоследние значения
- **WHEN** выполняются `(try 1 2 (finally nil))` и `(try (throw error) (catch e 1 2))`
- **THEN** generated Java компилируется и оба результата равны 2

#### Scenario: Void callback и discarded try
- **WHEN** финальный host void call находится в discarded try обычной функции или в финальном try callback с аннотацией void:java.lang.Runnable
- **THEN** Java компилируется, выполняет вызов и cleanup без попытки вернуть void как Object

#### Scenario: Java metadata на JS
- **WHEN** JS вызывает `^void:java.lang.Runnable (fn [] nil)`
- **THEN** результат равен nil, metadata не превращает возвращаемое значение в некорректную statement-форму

#### Scenario: Checked exception в initializer
- **WHEN** top-level def содержит try, перехватывающий checked host exception и возвращающий восстановленное значение
- **THEN** generated Java компилируется и поле получает восстановленное значение при инициализации класса без Supplier вокруг try

### Requirement: Try SHALL возвращать результат выбранного пути

JS/Java SHALL исполнять формы тела `try` последовательно до завершения или ошибки. При успехе SHALL возвращаться последнее значение тела без выполнения `catch`; при обработанной ошибке — последнее значение обработчика. `Try` SHALL работать в позиции результата, аргумента, условия, RHS binding и с отброшенным результатом. Значения SHALL сохраняться без проверки на истинность.

#### Scenario: Успех и falsey значения
- **WHEN** тело последовательно возвращает в отдельных запусках `nil`, `false` и `42`, а `finally` успешно возвращает другое значение
- **THEN** результат `try` равен соответственно `nil`, `false` и `42`, без выполнения обработчика
- **AND** `nil` и `false` не превращаются в строки

#### Scenario: Восстановление результата
- **WHEN** тело выбрасывает ошибку, а обработчик возвращает `nil`, `false` или обычное значение
- **THEN** `try` успешно возвращает именно результат обработчика

#### Scenario: Позиции выражения
- **WHEN** корректный `try` используется как аргумент функции, условие `if`, RHS `let`, результат функции или непоследняя форма её тела
- **THEN** оба targets компилируют и исполняют программу, сохраняя однократность выбранного пути и результат согласно позиции

### Requirement: Catch SHALL получать исходную синхронную ошибку

JS SHALL перехватывать любое синхронно выброшенное значение, Java — экземпляры `java.lang.Exception`, включая checked exceptions. Ошибки вложенных Y2K-вызовов, callbacks и host API SHALL достигать окружающего `catch`. Binding SHALL содержать исходный объект/значение без обёртки или преобразования в строку. Java `Error` SHALL проходить мимо обработчика.

#### Scenario: Вложенный host сбой
- **WHEN** функция внутри `try` вызывает host API, выбрасывающий исключение
- **THEN** обработчик получает тот же объект, пригодный для host-логирования и чтения сообщения
- **AND** выражения тела после ошибочного вызова не выполняются

#### Scenario: Java checked exception через callback
- **WHEN** callback языка вызывает Java API с checked exception внутри защищённого вызова
- **THEN** generated Java компилируется и окружающий обработчик получает исходный exception

#### Scenario: Java Error
- **WHEN** тело выбрасывает экземпляр `java.lang.Error`
- **THEN** `catch` не выполняется, `finally` выполняется, а при успешной очистке наружу выходит тот же `Error`

#### Scenario: JS произвольное выброшенное значение
- **WHEN** JS-код выбрасывает объект, строку, `false` или `null`
- **THEN** обработчик получает в каждом случае исходное значение, без проверки его истинности

### Requirement: Throw SHALL сохранять исходное значение ошибки

JS/Java SHALL вычислять аргумент `(throw expression)` ровно один раз и прерывать нормальное выполнение. На Java допустимое значение SHALL быть `Throwable`, на JS — любое значение. Повторное выбрасывание SHALL сохранять identity. Форма SHALL работать в позиции значения и инструкции, включая ветку `if`; ошибка вычисления аргумента SHALL распространяться обычным образом.

#### Scenario: Выборочное повторное выбрасывание
- **WHEN** обработчик внутреннего `try` выполняет `(throw e)`, а внешний обработчик ловит эту ошибку
- **THEN** внешний обработчик получает исходный объект без промежуточной обёртки

#### Scenario: Выражение и однократность
- **WHEN** аргумент `throw` содержит `let`, `do` или `if` и увеличивает счётчик перед возвратом ошибки
- **THEN** счётчик увеличивается один раз и выполнение после `throw` не продолжается
- **AND** форма компилируется как ветка `if`, аргумент вызова и результат функции

#### Scenario: Синтаксическое продолжение после throw
- **WHEN** корректная программа содержит `(do (throw error) 42)` внутри функции или защищённого тела
- **THEN** JS/Java compilation успешна, исполнение выбрасывает исходную ошибку и не достигает 42

#### Scenario: Try в аргументе throw
- **WHEN** `(throw (try (make-error) (finally (clean))))` вычисляет исходный объект ошибки
- **THEN** make-error и clean исполняются один раз, затем выбрасывается тот же объект
- **AND** generated source не содержит дополнительной функции вокруг вложенного try

### Requirement: Finally SHALL исполняться один раз при выходе

Указанная очистка SHALL выполняться ровно один раз после тела и возможного обработчика, при успехе, необработанной ошибке и ошибке обработчика. Её значение SHALL игнорироваться. При успешной очистке результат или исходная распространяющаяся ошибка SHALL сохраняться. Гарантия относится к обычному выполнению и раскрутке исключений, не к принудительному завершению процесса.

#### Scenario: Порядок эффектов
- **WHEN** тело записывает `body`, обработчик при ошибке — `catch`, а очистка — `finally`
- **THEN** при успехе журнал равен `body,finally`, при обработанной ошибке — `body,catch,finally`
- **AND** каждая запись появляется ровно один раз

#### Scenario: Ошибка без обработчика
- **WHEN** тело `try` без `catch` выбрасывает ошибку, а очистка успешна
- **THEN** очистка выполняется один раз и наружу выходит та же ошибка

#### Scenario: Ошибка обработчика
- **WHEN** обработчик выбрасывает новую ошибку, а очистка успешна
- **THEN** очистка выполняется один раз и наружу выходит ошибка обработчика
- **AND** этот же обработчик повторно не вызывается

### Requirement: Ошибка finally SHALL заменять предыдущий исход

Если очистка выбрасывает ошибку, `try` SHALL завершаться этой ошибкой независимо от успеха либо ошибки тела/обработчика. Собственный `catch` SHALL NOT перехватывать ошибку своего `finally`. Предыдущая ошибка SHALL NOT автоматически присоединяться как cause, suppressed exception или иной дополнительный результат.

#### Scenario: Ошибка очистки после успеха
- **WHEN** тело успешно возвращает значение, а `finally` выбрасывает ошибку
- **THEN** вызывающий получает ошибку очистки, не успешный результат

#### Scenario: Две ошибки
- **WHEN** тело или обработчик выбрасывает ошибку A, а затем очистка выбрасывает B
- **THEN** внешний обработчик получает исходный объект B
- **AND** A автоматически не сохраняется в B

### Requirement: Вложенная очистка SHALL поддерживать сценарии загрузчика

Вложенные `try`/`finally` SHALL позволять очищать каждое успешно открытое состояние при сбое последующей операции. Исключение SHALL прекращать текущий путь, сохраняя уже выполненные эффекты. Публикация, явно расположенная после успешного вычисления, SHALL NOT выполняться при ошибке этого вычисления; автоматический откат SHALL NOT вводиться.

#### Scenario: Неудачный reload
- **WHEN** вычисление нового значения ошибочно, публикация стоит после вычисления, а очистка loader state — в `finally`
- **THEN** прежняя привязка registry остаётся, loader state очищается, ошибка выходит наружу
- **AND** уже выполненные эффекты инициализатора сохраняются

#### Scenario: Чтение и финализация
- **WHEN** защищённая операция чтения завершается EOF, ошибкой чтения, декодирования или финализации
- **THEN** предусмотренные закрытие ресурса и очистка loader state выполняются
- **AND** после ошибки чтения последующее чтение и успешная финализация не выполняются

#### Scenario: Ошибка открытия второго ресурса
- **WHEN** первый ресурс открыт и защищён внешним `finally`, а открытие второго внутри тела завершается ошибкой
- **THEN** первый ресурс закрывается и ошибка распространяется наружу

#### Scenario: Ошибка внутреннего закрытия
- **WHEN** внутренний `finally` выбрасывает ошибку во время закрытия ресурса
- **THEN** внешний `finally` также выполняется; итоговая ошибка определяется обычным правилом замены ошибкой очистки

#### Scenario: Проверка ожидаемой ошибки
- **WHEN** helper возвращает `false` после нормального вызова и `true` только из `catch`
- **THEN** выброшенная ошибка даёт `true`, а обычный возврат `nil` или `false` — `false`
- **AND** после обработанной ошибки продолжаются следующие проверки

### Requirement: Try SHALL оставаться синхронным и ограниченным JS/Java

JS `try` SHALL NOT ожидать Promise или перехватывать его последующее отклонение. Возвращённый Promise SHALL быть обычным результатом, а очистка SHALL происходить при синхронном выходе. FEX compilation SHALL отклонять исполняемые `try`/`throw`, не выдавая их как обычные вызовы; цитированные формы SHALL оставаться данными.

#### Scenario: Promise возвращён без ожидания
- **WHEN** тело возвращает Promise, который отклоняется после возврата `try`
- **THEN** `try` возвращает этот Promise, очистка уже выполнена, а `catch` этого `try` не вызывается

#### Scenario: FEX неподдерживаемая форма
- **WHEN** RHS определения FEX содержит исполняемый `try` или `throw`
- **THEN** compilation завершается ошибкой неподдерживаемой формы

### Requirement: CLI SHALL предоставлять текстовый target fex

CLI SHALL принимать `--target fex`, читать исходник из stdin и возвращать один текстовый bundle в stdout без записи code-файлов и без требования output directory. Bundle SHALL содержать RHS верхнеуровневых `def` в исходном порядке. `--source-map` SHALL оставаться доступным только для JS. Существующие eval/JS/Java SHALL сохранять свои интерфейсы.

#### Scenario: Несколько определений
- **WHEN** исходник namespace `app.logic` содержит `def a` и `def b` и компилируется в `fex`
- **THEN** stdout содержит пары для `app.logic.a` и `app.logic.b` в указанном порядке
- **AND** каждый payload кодирует только соответствующий RHS

#### Scenario: Каталог не указан
- **WHEN** CLI получает `--target fex` без `--output-dir`
- **THEN** корректный source компилируется в текстовый stdout без создания code-файлов

### Requirement: Bundle SHALL содержать пары имени и Base64 RHS

На каждое определение bundle SHALL содержать ровно две строки: canonical key и стандартный Base64 с padding полного текста RHS, включая переводы строк. Compiler SHALL завершать обе строки LF. Заголовок, trailer, счётчик и дополнительные пустые строки SHALL отсутствовать. Внешнее кодирование SHALL NOT менять формат FEX payload.

#### Scenario: Точная упаковка RHS
- **WHEN** компилируется `(ns app.logic) (def answer 42)`
- **THEN** bundle состоит из `app.logic.answer` и `aW50IDQyCg==`, каждая строка заканчивается LF
- **AND** декодированный payload равен bytes `int 42` с завершающим LF

### Requirement: FEX compiler SHALL использовать общий frontend

FEX compiler SHALL использовать существующее раскрытие макросов и поддерживать literals, `quote`, `if`, `do`, `let`, `fn`, вызовы, коллекции и деструктуризацию в поддерживаемом переносимом подмножестве. Пользовательские locals SHALL сохранять имена; необходимые временные имена SHALL создаваться через `Gensym`. Host interop и верхнеуровневые формы кроме namespace и `def` SHALL отклоняться.

#### Scenario: Макросы и деструктуризация
- **WHEN** программа использует `defn`, `cond`, векторную и map-деструктуризацию в `let` и параметрах
- **THEN** файлы содержат раскрытые core-формы и именованные bindings для деструктуризации, без исходных макросов

#### Scenario: Цитированные значения
- **WHEN** компилируется `quote` атомов и вложенных списков
- **THEN** атомы представлены строковыми данными, как в существующих compiled targets
- **AND** `'nil` даёт строку `nil`, а не ложный литерал

#### Scenario: Цитирование после desugar
- **WHEN** компилируется `'[1]`
- **THEN** результат представлен вызовом `list` со строками `list` и `1`, как на JS/Java после раскрытия vector syntax
- **AND** compiler цитирует результат существующего desugar, не меняя frontend на Clojure quote

#### Scenario: Непереносимая форма
- **WHEN** RHS содержит `raw-code` или непосредственный вызов host interop
- **THEN** компиляция завершается ошибкой, а не выдаёт неисполняемый файл

#### Scenario: Host-формы после раскрытия
- **WHEN** source использует `.method`, `Class.`, `cast`, типизированный параметр, раскрывающийся в `cast`, `instance?`, `gen-class`, `export-default`, `:import` или строковый host `:require`
- **THEN** FEX compilation отклоняет соответствующую форму без добавления host semantics

#### Scenario: Недопустимый верхний уровень
- **WHEN** source после desugar содержит верхнеуровневый вызов или литерал вместо namespace или `def`
- **THEN** FEX compilation завершается ошибкой

### Requirement: FEX compiler SHALL разрешать именованные ссылки

Compiler SHALL учитывать lexical shadowing, namespace, aliases и собственные определения при выборе `local`, `global` и `builtin`. Глобальный ключ SHALL совпадать с именем файла. Namespace по умолчанию SHALL быть `user`. Требования namespace SHALL разрешать имена, но SHALL не запускать автоматическую загрузку зависимостей.

#### Scenario: Alias и затенение builtin
- **WHEN** функция обращается к `dep/value` через alias, а локальный binding или собственный `def` затеняет builtin
- **THEN** alias разрешается в полное глобальное имя
- **AND** затенённое имя записывается как `local` либо `global`, а не `builtin`

#### Scenario: Рекурсия и ссылки вперёд
- **WHEN** тело функции ссылается на собственное или более позднее определение того же source, в том числе затеняющее builtin
- **THEN** ссылка представлена `global` с canonical key этого определения
- **AND** compiler не загружает и не вычисляет определение

### Requirement: Имена FEX файлов SHALL быть однозначными и безопасными

Canonical key SHALL состоять из компонентов namespace и имени `def`, разделённых точками. В компонентах `[a-z0-9_-]` SHALL сохраняться, ASCII `A–Z` SHALL кодироваться как `!a–!z`, остальные UTF-8 bytes — `%HH` с заглавными hex digits. Один key SHALL использоваться в bundle, filename и `global` без повторного кодирования.

#### Scenario: Точка в имени определения
- **WHEN** компилируются `a.b/c` и `a/b.c`
- **THEN** получаются разные имена `a.b.c` и `a.b%2Ec`
- **AND** global references используют те же ключи без дополнительного percent escaping полей

#### Scenario: Коллизия регистра
- **WHEN** компилируются `app/foo`, `app/Foo` и `app/FOO`
- **THEN** keys равны `app.foo`, `app.!foo` и `app.!f!o!o`
- **AND** keys не совпадают даже при регистронезависимом сравнении

#### Scenario: Буквальный маркер и регистр namespace
- **WHEN** компилируются `App/!foo` и `app/Foo`
- **THEN** keys равны `!app.%21foo` и `app.!foo` и не конфликтуют

#### Scenario: Unicode в имени
- **WHEN** компилируются `app/Я` и `app/я`
- **THEN** keys равны `app.%D0%AF` и `app.%D1%8F`
- **AND** различие сохраняется без Unicode case folding файловой системы

### Requirement: Файл определения SHALL содержать плоские выражения

Декодированный compiler payload и распакованный файл SHALL содержать UTF-8 без BOM: одну запись на строку с разделителем LF и одним ASCII space между полями. Файл SHALL содержать только RHS одного `def`, с корнем в строке 1 и forward references по 1-based номерам строк внутри RHS. Имена переменных SHALL сохраняться; заголовок, обёртка `def`, пустые записи и инструкции возврата SHALL отсутствовать.

#### Scenario: Функция в отдельном файле
- **WHEN** компилируется `(ns app.logic) (defn calculate [x] (+ x 1))`
- **THEN** декодированный payload ключа `app.logic.calculate` содержит записи `fn 2 x`, `call 3 4 5`, `builtin +`, `local x`, `int 1` в этом порядке

### Requirement: Строковые значения SHALL использовать UTF-8 Base64

Compiler SHALL кодировать строки как `string base64` со стандартным Base64 с padding без переносов; пустую строку — как `string -`. Имена и числа SHALL оставаться текстовыми токенами. Percent escapes SHALL применяться к filename components, но не к строковым значениям.

#### Scenario: Точная сериализация строк
- **WHEN** компилируются пустая строка, Unicode, пробелы, TAB, LF, CR, кавычки и буквальный `%0A`
- **THEN** каждый payload соответствует стандартному Base64 исходных UTF-8 bytes, а пустая строка записана как `string -`
- **AND** строка `hello world` записана как `string aGVsbG8gd29ybGQ=`

### Requirement: FEX compiler SHALL сохранять структуру выражений

Compiler SHALL использовать записи `nil`, `true`, `false`, `int`, `float`, `string`, `local`, `global`, `builtin`, `fn`, `call`, `if`, `let`, `do`. `fn` SHALL содержать адрес тела и параметры; `call` — callee и аргументы в исходном порядке; `if` — условие и обе ветви; `let` — имя, значение и тело; `do` — последовательность адресов. Все адреса SHALL указывать на существующие последующие записи.

#### Scenario: Вложенные выражения
- **WHEN** компилируются функция с шестью параметрами, вложенные `let`, `if`, `do` и вызовы
- **THEN** записи сохраняют параметры, lexical shadowing, порядок аргументов и обе ветви `if`, не вычисляя исходные выражения
- **AND** пустой `do` представлен записью `do` без адресов

#### Scenario: Неявная ветвь и последовательное тело
- **WHEN** source содержит `if` без else, несколько bindings в `let` и несколько выражений тела функции
- **THEN** отсутствующая ветвь представлена `nil`, bindings вложены последовательно, а тело функции представлено `do` в исходном порядке

### Requirement: JavaScript CLI SHALL предоставлять opt-in inline source map

CLI SHALL принимать `--source-map` для `--target js`, сохраняя stdin как источник текста и stdout как единственный результат. При включении карты generated JS SHALL завершаться комментарием `sourceMappingURL` с data URL стандартной Source Map v3. Для других targets `--source-map` SHALL завершаться явной ошибкой.

#### Scenario: Карта в единственном выходном файле
- **WHEN** CLI получает корректную программу через stdin с `--target js --source-map`
- **THEN** stdout содержит исполняемый JS и inline source map
- **AND** compiler не создаёт отдельный `.map`-файл

#### Scenario: Неподдерживаемый target
- **WHEN** CLI вызывается с `--source-map` и target `eval` или `java`
- **THEN** CLI завершается ненулевым кодом и сообщает, что карта поддерживается только для JS

### Requirement: Inline source map SHALL использовать user.clj по умолчанию

При включённой карте имя исходника SHALL быть `user.clj`, если не передан `--source-file PATH`. Переданный PATH SHALL переопределять имя; относительный путь SHALL разрешаться относительно выходного JS. Compiler SHALL NOT читать этот файл или автоматически подставлять абсолютный путь. `--source-file` сам по себе SHALL NOT включать карту.

#### Scenario: Исходник без имени
- **WHEN** компиляция выполняется с `--target js --source-map` без `--source-file`
- **THEN** карта содержит единственный source `user.clj`, даже если такого файла на диске нет

#### Scenario: Выход в другом каталоге
- **WHEN** JS сохранён в `dist/demo.mjs`, а карта включена с `--source-file "../src/my demo.clj"`
- **THEN** карта ссылается на `../src/my demo.clj`, и Node разрешает source в `src/my demo.clj` относительно каталога `dist`
- **AND** текст берётся только из stdin независимо от наличия или содержимого указанного файла

#### Scenario: Имя без включения карты
- **WHEN** передан `--source-file example.clj` без `--source-map`
- **THEN** вывод совпадает с обычной компиляцией без этих параметров

#### Scenario: URL-символы в имени файла
- **WHEN** `--source-file` задаёт путь к файлу `a#b.clj`, `a?b.clj` или `a%20b.clj`
- **THEN** карта кодирует имя как URL reference так, что Node показывает буквальное имя файла без усечения или превращения `%20` в пробел

### Requirement: Inline source map SHALL сохранять входной текст

Карта SHALL содержать `version: 3`, единственный элемент `sources`, соответствующий элемент `sourcesContent`, `names` и корректные `mappings`. `sourcesContent` SHALL точно воспроизводить входной текст до преобразований. `names` SHALL быть пустым: восстановление имён переменных не входит в контракт.

#### Scenario: Декодирование исходника
- **WHEN** stdin содержит кириллицу, emoji, кавычки, обратные слеши и переводы строк CRLF
- **THEN** после декодирования карты и JSON её `sourcesContent[0]` точно совпадает с входом

### Requirement: JavaScript source map SHALL привязывать стек к исходным вызовам

При запуске generated JS с `node --enable-source-maps` пользовательские frames ошибок SHALL указывать исходное имя, строку и столбец начала формы вызова. Это SHALL работать для прямых и вложенных вызовов, тел функций и callback, шагов threading и вызовов внутри `let`, `do` и веток `if`, включая destructuring. Восстановление отсутствующих в штатном стеке Node frames не требуется.

#### Scenario: Прямой ошибочный вызов
- **WHEN** source состоит из `(ns demo)`, `(defn fail []`, `  (.parse JSON "invalid-json"))`, `(fail)` на четырёх последовательных строках и запускается с картой
- **THEN** первый пользовательский frame ошибки указывает `user.clj:3:3`
- **AND** ошибка остаётся `SyntaxError`, а процесс завершается ненулевым кодом

#### Scenario: Вызовы после преобразований
- **WHEN** ошибочный вызов находится в теле callback, в выбранной ветке `if` внутри `let` с destructuring либо в отдельном шаге threading
- **THEN** frame этого вызова указывает начало соответствующей исходной формы или шага, а не начало окружающей функции или служебного binding

#### Scenario: Вложенный вызов и несколько форм на строке
- **WHEN** два вызова стоят на одной строке, либо один вызов вложен в аргумент другого, и ошибка возникает в конкретном вызове
- **THEN** frame указывает столбец начала именно ошибочного вызова

#### Scenario: Ошибка внешнего вызова после успешного аргумента
- **WHEN** выполняется `(.parse JSON (str "invalid"))`, внутренний `str` успешен, а `JSON.parse` выбрасывает ошибку
- **THEN** первый пользовательский frame указывает начало внешней формы `.parse`, а не позицию `str`

#### Scenario: Восстановление позиции после receiver или callee
- **WHEN** выражение receiver или callee успешно возвращает значение, но последующий внешний вызов завершается ошибкой
- **THEN** frame внешнего вызова указывает начало внешней исходной формы

#### Scenario: Ошибка во вложенном callback
- **WHEN** callback, переданный в Promise, вызывает ошибочную форму и Node включает этот вызов в стек
- **THEN** соответствующий пользовательский frame указывает начало формы внутри callback
- **AND** generated JS-frame ошибочного вызова не подменяется привязкой более позднего caller

### Requirement: Source map SHALL корректно представлять координаты Unicode

Карта SHALL использовать нумерацию и единицы Source Map v3: нулевые индексы строк и UTF-16 столбцов. Стек Node SHALL показывать соответствующие исходные позиции с единицы. Unicode перед выражением и CRLF SHALL NOT смещать привязку. Generated positions SHALL относиться к фактическому JS, включая пролог.

#### Scenario: Unicode и CRLF перед вызовом
- **WHEN** перед ошибочным вызовом на той же строке есть кириллица и emoji, а строки source разделены CRLF
- **THEN** строка и UTF-16 столбец в стеке совпадают с началом исходного вызова

#### Scenario: Пролог и многострочный вывод
- **WHEN** generated JS содержит runtime import, namespace imports и многострочные функции перед ошибочным вызовом
- **THEN** эти строки учтены в карте и не сдвигают исходную позицию ошибки

#### Scenario: Переносы внутри generated raw-code
- **WHEN** допустимый многострочный `raw-code` содержит CR, LF, CRLF, U+2028 или U+2029 и за ним выполняется ошибочный пользовательский вызов
- **THEN** generated line positions учитывают эти разделители по правилам JavaScript и стек указывает исходную позицию следующего вызова

### Requirement: Source map SHALL различать пользовательский и служебный код

Синтетический код SHALL связываться с породившей его формой либо оставаться без привязки. Runtime import SHALL оставаться без привязки; frames отдельного runtime SHALL сохранять собственные JS-позиции. `raw-code` SHALL связываться с началом исходной формы целиком без точного сопоставления строк внутри payload.

#### Scenario: Ошибка в runtime
- **WHEN** ошибка возникает внутри функции runtime, вызванной из `.clj`
- **THEN** frame runtime остаётся JS-frame, а пользовательский frame вызова указывает `.clj`

#### Scenario: Многострочный raw-code
- **WHEN** ошибка возникает в одной из строк допустимой вставки `raw-code`
- **THEN** пользовательская привязка указывает начало исходной формы `raw-code`

### Requirement: Inline source map SHALL сохранять поведение программы

Включение карты SHALL NOT менять исполняемый JS, порядок эффектов, exports, imports, сообщения и типы ошибок; отличие вывода SHALL ограничиваться завершающим комментарием карты. Без карты compiler SHALL сохранять прежний формат вывода без `sourceMappingURL`. Обычные вызовы runner и JS compiler без новых параметров SHALL сохранять работоспособность.

#### Scenario: Совместимость двух режимов
- **WHEN** один source компилируется с картой и без неё
- **THEN** после удаления завершающего комментария карты JS совпадает побайтово
- **AND** при исполнении совпадают результаты, эффекты и типы ошибок

#### Scenario: Совместимость с генератором до изменения
- **WHEN** одна корректная программа компилируется без карты прежним и обновлённым генераторами из одинакового исходного состояния
- **THEN** JS совпадает побайтово, включая imports, exports, служебные имена и форматирование

### Requirement: Compiler targets SHALL предоставлять двухаргументный conj

JS и Java SHALL предоставлять без пользовательского импорта `(conj items value)` для list/vector и одного значения. Результат SHALL быть новой коллекцией с исходными элементами в прежнем порядке и value в конце, без изменения входа. List и vector SHALL иметь одинаковую семантику. Другие арности, map и nil вместо коллекции не входят в переносимый контракт.

#### Scenario: Пустой вход и добавление в конец
- **WHEN** программа выполняет `(conj [] 1)`, `(conj [1 2] 3)` и `(conj (list 1 2) 3)`
- **THEN** JS и Java возвращают соответственно коллекции с 1; 1, 2, 3; 1, 2, 3, как eval
- **AND** исходные коллекции сохраняют длину и элементы

#### Scenario: Вложенный namespace
- **WHEN** программа с namespace `checks.collections.core` вызывает conj без пользовательских imports
- **THEN** generated JS и Java компилируются и исполняются с соответствующим runtime без неразрешённого символа conj

### Requirement: Compiler conj SHALL сохранять значения поверхностно

Conj SHALL сохранять элементы без преобразования, фильтрации и рекурсивного копирования. Nil, false, 0 и пустая строка SHALL оставаться элементами. Коллекция в позиции value SHALL добавляться одним элементом. JS SHALL поддерживать обычные плотные host-массивы с сохранением ссылок на объекты; sparse arrays и произвольные iterable вне контракта.

#### Scenario: Типы и вложенность
- **WHEN** через conj последовательно добавлены nil, false, 0, пустая строка и `[1 2]`
- **THEN** результат содержит пять элементов с исходными типами, последний — коллекция из двух элементов
- **AND** извлечённые nil и false не равны строкам `"nil"` и `"false"`

#### Scenario: Сохранение ссылок
- **WHEN** исходный либо добавляемый элемент является Atom
- **THEN** изменение Atom, извлечённого из результата, наблюдается через исходную ссылку
- **WHEN** JS conj получает плотный host-массив объектов и добавляемый объект
- **THEN** результат является новым массивом, а все объекты сохраняют JS identity

### Requirement: JS conj SHALL поддерживать последовательное накопление Promise-результатов

Скомпилированная JS Promise-цепочка по образцу effect/batch SHALL выполнять conj внутри then без неразрешённого символа и накапливать результаты в порядке эффектов. Conj SHALL работать как обычная синхронная операция коллекции внутри callback; управление асинхронностью остаётся у Promise-цепочки.

#### Scenario: Несколько эффектов
- **WHEN** batch начинает с `Promise.resolve([])`, последовательно запускает два эффекта через then и добавляет каждый результат через `(conj result x)`
- **THEN** итоговый Promise разрешается коллекцией двух результатов в исходном порядке
- **AND** второй эффект запускается после завершения первого

#### Scenario: Пустой batch
- **WHEN** та же цепочка получает пустой список эффектов
- **THEN** итоговый Promise разрешается пустой коллекцией без вызовов эффектов

### Requirement: Compiler targets SHALL вставлять raw-code без преобразования текста

JS и Java targets SHALL поддерживать специальную форму `(raw-code "text")` с ровно одним исходным строковым литералом. В допустимой позиции compiler SHALL вставлять декодированное парсером содержимое литерала ровно один раз, сохраняя его символы и порядок относительно окружающих форм. Compiler SHALL NOT экранировать, повторно декодировать, mungе-ить, анализировать синтаксис host-кода или добавлять к вставке `return`, `;`, скобки либо отдельную обёртку. Разделительные переводы строк вокруг вставки допустимы; содержимое не изменяется. Пустая строка SHALL быть допустимой вставкой без кода. Текст относится к выбранному target, без автоматического перевода между JS и Java. Корректность host-кода и необходимые terminators SHALL оставаться ответственностью автора; ошибки host-синтаксиса определяются host toolchain.

#### Scenario: Инструкции JavaScript
- **WHEN** JS target компилирует `(defn test [] (raw-code "console.log('hello');") "done")`
- **THEN** тело функции содержит ровно `console.log('hello');` перед обычным возвращением `"done"`
- **AND** вставка не содержит вызова `raw_code`, дополнительного `;` или префикса `return`

#### Scenario: Инструкции Java
- **WHEN** Java target компилирует `(defn test [] (raw-code "System.out.println(\"hello\");") "done")`
- **THEN** тело метода содержит ровно `System.out.println("hello");` перед обычным возвращением `"done"`

#### Scenario: Декодирование выполняется только парсером
- **WHEN** литерал содержит source escapes `\n`, `\t`, `\r`, `\"`, `\\` либо сохранённую неизвестную пару `\q`
- **THEN** вставленный текст совпадает с декодированным содержимым литерала, включая LF, TAB, CR, кавычку, обратный слеш и буквальную пару `\q`
- **AND** decoded пара обратного слеша и `n` не становится LF при генерации

#### Scenario: Сохранение текста и отсутствие суффикса
- **WHEN** допустимая вставка содержит несколько строк, пунктуацию, пробелы и завершающий комментарий без `;`
- **THEN** содержимое сохраняется точно, без автоматически добавленного `;` или форматирования внутри вставки

#### Scenario: Пустой текст
- **WHEN** допустимая форма содержит `(raw-code "")`
- **THEN** генерация успешна и не добавляет вместо вставки инструкцию, значение или `;`

### Requirement: Compiler targets SHALL поддерживать raw-code в позициях инструкций и top-level вставках

Непосредственная top-level форма raw-code SHALL вставляться на своём месте в JS module или внутри Java helper class. В Java compiler SHALL NOT перемещать её перед классом или автоматически помещать в static initializer. Внутри `fn`/`defn` raw-code SHALL допускаться как непоследняя форма последовательного тела функции, `let` или `do`; окружающие формы сохраняют обычную семантику. Для условной вставки SHALL допускаться непоследняя форма внутри тела `do`/`let` в ветке, например `(do (raw-code "...") nil)`. Цитированная форма SHALL оставаться данными, а не вставкой. Expression-valued вставки, включая последнее выражение тела, аргументы, callee, RHS, условия и прямые результаты веток, не поддерживаются. Автор отвечает за использование поддержанных позиций; compiler не гарантирует диагностику исходной позиции и не выполняет отдельный обход до lowering.

#### Scenario: JavaScript module declaration
- **WHEN** top-level JS source содержит `(raw-code "export const hostValue = 42;")`
- **THEN** декларация появляется в module на месте формы без дополнительного terminator

#### Scenario: Java class members
- **WHEN** top-level Java source содержит `(raw-code "public static int hostValue = 42;")`
- **THEN** поле появляется внутри helper class на месте формы
- **AND** отсутствует автоматически созданный static initializer вокруг вставки

#### Scenario: Последовательные тела и условная вставка
- **WHEN** raw-code находится внутри функции перед обычным последним выражением тела `let`/`do`, в том числе в `(if condition (do (raw-code "...") nil) nil)`
- **THEN** вставка сохраняет порядок выполнения и выполняется только при достижении соответствующего пути

#### Scenario: Цитирование
- **WHEN** source содержит `(quote (raw-code "host text"))`
- **THEN** форма компилируется как данные и текст не вставляется как host-код

### Requirement: Compiler targets SHALL диагностировать недопустимые аргументы raw-code

При извлечении payload неверная арность и аргумент, не являющийся исходным строковым литералом, SHALL приводить к ошибке JS/Java compilation, называющей raw-code, причину, строку и столбец формы. Keywords, символы, runtime-строки и выражения, возвращающие строки, SHALL NOT приниматься вместо литерала. Отдельная проверка до lowering не требуется; диагностика удалённых или преобразованных lowering форм не гарантируется. Точный текст ошибки не фиксируется.

#### Scenario: Неверная арность
- **WHEN** source содержит `(raw-code)` или `(raw-code "a" "b")`
- **THEN** compilation сообщает ошибку арности raw-code с координатами

#### Scenario: Только исходный литерал
- **WHEN** при извлечении payload аргумент равен `:text`, `text`, `42`, `nil`, `true` или `(str "text")`
- **THEN** compilation сообщает ошибку аргумента raw-code с координатами, не вставляя результат преобразования аргумента

### Requirement: Eval SHALL явно отклонять raw-code без вычисления аргументов

Eval SHALL при достижении формы raw-code выдавать Eval_error, называющий raw-code и поддержку только JS/Java targets. Eval SHALL NOT вычислять аргументы или исполнять host-код, включая формы с неверной арностью или нестроковым аргументом. Цитированные формы и формы в недостигнутой ветке SHALL сохранять обычное поведение данных и управления исполнением.

#### Scenario: Достигнутая вставка
- **WHEN** eval достигает `(raw-code "console.log('hello');")`
- **THEN** выдаётся ошибка неподдерживаемой формы, а не lookup error для raw-code

#### Scenario: Аргумент с побочным эффектом
- **WHEN** eval достигает `(raw-code (reset! counter 1))`, где counter хранит 0
- **THEN** возникает ошибка неподдерживаемой формы и counter остаётся равным 0

#### Scenario: Недостигнутая форма и данные
- **WHEN** eval выполняет `(if false (raw-code "...") "ok")` либо цитирует форму raw-code
- **THEN** соответственно возвращается `"ok"` либо данные без ошибки неподдерживаемой формы

### Requirement: The runner SHALL dispatch to eval, JavaScript, and Java targets

The shared runner SHALL parse and desugar input once, then dispatch by target name.

#### Scenario: Known target
- **WHEN** target is `eval`, `js`, or `java`
- **THEN** the runner returns the evaluated output or generated source

#### Scenario: Unknown target
- **WHEN** target is unknown
- **THEN** the runner returns `unknown target: TARGET`

### Requirement: Compiler targets SHALL lower expressions into statement-safe forms

Before JavaScript or Java code generation, compiler targets SHALL lower expression-valued control flow into statement-safe forms. Existing `if` lowering SHALL use explicit `do`, `let*`, `if`, and `set!` forms with generated temporaries. Value-position `try` SHALL produce a native statement and a generated result binding assigned by its body or handler; discard-position `try` SHALL produce a native statement without a result binding. Lowering SHALL preserve protected boundaries, lexical scope, evaluation order, single evaluation, and expression results without moving body, handler, or cleanup effects outside their respective regions.

#### Scenario: If expression in value position
- **WHEN** an `if` expression is used where a value is required
- **THEN** lowering creates a generated result binding and assigns branch results before returning that binding

#### Scenario: Ошибка внутри преобразованного binding
- **WHEN** внутри `try` RHS `let` использует вложенные `do` и `if`, а выбранный путь выбрасывает исключение
- **THEN** исключение попадает в обработчик этого `try`, а очистка выполняется после обработчика
- **AND** вычисления RHS не происходят до входа в защищённую область

### Requirement: Value-if SHALL исполняться без дополнительной функции

JS/Java SHALL генерировать value-if как инструкции и результат в исходном теле или initializer, без Supplier, IIFE, callback, helper-метода или switch-expression ради значения if. Вложенные do/let SHALL NOT восстанавливать такую обёртку. Пользовательские функции SHALL сохранять свои границы исполнения, а bindings — lexical scope.

#### Scenario: Значение в разных позициях
- **WHEN** if используется как результат функции, аргумент, условие другого if, RHS let, внутри do/let или initializer top-level def
- **THEN** generated source передаёт результат выбранной ветки без дополнительной функции вокруг if
- **AND** nil, false и неявный nil отсутствующей else сохраняют свои значения

#### Scenario: Ветка и отложенный callback
- **WHEN** if находится в невыбранной ветке или теле созданного, но ещё не вызванного callback
- **THEN** его условие и ветви не исполняются до достижения соответствующего пути

#### Scenario: Shadowing и discarded позиции
- **WHEN** ветви содержат вложенные let с затенением, а результат внешнего if отброшен
- **THEN** bindings не выходят за исходную область и результаты не требуют result temporary
- **AND** Java void callback допускает финальный if с void-вызовами без return значения

#### Scenario: Порядок инициализации
- **WHEN** несколько top-level def содержат if с эффектами
- **THEN** эффекты и публикация значений происходят в исходном порядке без дополнительных функций

### Requirement: Statement prefixes SHALL сохранять порядок операндов

При извлечении инструкций из операндов JS/Java SHALL сохранять вычисление слева направо и ровно один раз: вычисляемый callee или receiver, затем аргументы; элементы коллекций в исходном порядке. Ошибка SHALL прекращать последующие вычисления. Синтаксические class/type/method позиции SHALL сохраняться, вычисляемые JS callee/constructor SHALL сохранять момент lookup. Явные Java hints/casts и source-map позиции SHALL сохраняться; inferred тип за границей сложного выражения не гарантируется.

#### Scenario: Ранний аргумент перед условием позднего
- **WHEN** выполняется `(f (before) (if (condition) (selected) (unused)) (after))` и condition истинно
- **THEN** журнал равен before,condition,selected,after,f без повторений и unused
- **AND** существующий sample if_value.clj сохраняет вывод `7|12|3|nil|false|3|ab`

#### Scenario: Ошибка раннего операнда
- **WHEN** before выбрасывает host-ошибку до if в следующем аргументе
- **THEN** условие, ветви, поздние аргументы и f не исполняются
- **AND** исходная ошибка распространяется без изменения

#### Scenario: Несколько prefixes и вычисляемый callee
- **WHEN** вычисляемый callee или host receiver имеет эффект, а два аргумента содержат if
- **THEN** callee/receiver вычисляется первым, затем аргументы последовательно, затем вызов
- **AND** host method binding и Java typing позволяют скомпилировать и выполнить вызов

#### Scenario: Коллекции и синтаксические имена
- **WHEN** list/vector/map содержит if среди эффектных значений либо if находится в аргументе new, host method, cast или instance?
- **THEN** вычисляемые значения сохраняют исходный порядок и identity
- **AND** Java class/static method и type/method в синтаксических позициях не становятся runtime-переменными

#### Scenario: Явный Java тип результата let
- **WHEN** результат `let` используется как host receiver через явно типизированный внешний binding либо cast, включая результат `new` или host method call
- **THEN** вызов компилируется и выполняется; неаннотированный промежуточный результат может иметь тип Object
- **AND** `(defn f [] (let [^String text (let [x (new String "a")] x)] (.concat text "b")))` возвращает `"ab"`
- **AND** наличие `if` в позднем аргументе сохраняет вычисление receiver перед условием, однократность вызова и отсутствие дополнительных функций-обёрток
- **AND** metadata внутреннего binding не переносится автоматически на тип результата всего let; универсальный expression hint не добавляется

#### Scenario: Java static-вызов
- **WHEN** static-вызов использует документированную форму `Class/method` и аргумент содержит if
- **THEN** сохраняются имя метода и порядок аргументов
- **AND** распознавание class qualifier в receiver-позиции `.` не требуется

#### Scenario: Java nil перед поздним prefix
- **WHEN** литерал nil является ранним аргументом host-вызова, а поздний аргумент содержит инструкции do/if
- **THEN** nil остаётся Java null без промежуточного Object, сохраняя выбор перегрузки
- **AND** инструкции позднего аргумента выполняются ровно один раз в исходном порядке

#### Scenario: JS lookup и this
- **WHEN** аргумент с if заменяет host-функцию, метод или constructor либо receiver имеет getter метода
- **THEN** callee/constructor и lookup метода вычисляются до аргументов, ровно один раз
- **AND** сохранённый метод вызывается с исходным receiver как this; проверка callable не опережает вычисление аргументов

#### Scenario: Исходное окружение позднего аргумента
- **WHEN** ранний операнд содержит `let` с локальным binding, одноимённым внешнему binding, а поздний аргумент использует внешнее имя и содержит `if`
- **THEN** поздний аргумент использует внешнее значение независимо от размещения generated statements внутри lexical blocks
- **AND** порядок эффектов и границы отложенных callbacks сохраняются

#### Scenario: Raw-code и локальные имена
- **WHEN** корректный raw-code обращается к локальному binding, затеняющему global/field, либо содержит выходящий Java return
- **THEN** локальное имя и исходная граница выхода сохраняются, payload не разбирается и не изменяется
- **AND** поздние операнды за пределами этого let сохраняют своё окружение, включая host-имена из raw-code

#### Scenario: Source map после переноса инструкций
- **WHEN** пользовательский вызов в условии или выбранной ветке завершается ошибкой и включена JS source map
- **THEN** пользовательский frame указывает исходную позицию этого вызова

### Requirement: Compiler targets SHALL call local function values

JavaScript и Java compiler targets SHALL разрешать символ в позиции функции как локальное значение, если символ связан параметром или локальным binding. Java target SHALL вызывать такое значение через runtime-интерфейс `FnN`, соответствующий числу аргументов, а локальное binding SHALL иметь приоритет над одноимённой top-level или runtime-функцией.

#### Scenario: Call a lambda passed as a function parameter
- **WHEN** top-level функция принимает лямбду параметром и вызывает этот параметр с поддерживаемой арностью
- **THEN** JavaScript и Java output компилируются и возвращают тот же результат, что и eval

#### Scenario: Call a lambda from a sequential local binding
- **WHEN** функциональное значение связано обычным или созданным destructuring local binding и вызывается в следующей форме lexical body
- **THEN** JavaScript и Java targets вызывают локальное значение
- **AND** Java output компилируется и возвращает тот же результат, что и eval

#### Scenario: Local function value shadows a non-local function
- **WHEN** символ локального функционального значения совпадает с именем top-level или runtime-функции
- **THEN** compiler target вызывает локальное функциональное значение

### Requirement: Lowering SHALL eliminate destructuring let bindings

Lowering SHALL преобразовывать `let*` bindings и `fn*` parameter patterns с sequential или associative patterns в bindings только с symbol слева. Для каждого destructuring `let*` RHS lowering SHALL вычислять RHS ровно один раз во временное имя через `Gensym`, а для каждого non-symbol parameter pattern SHALL создавать один fresh symbol parameter через `Gensym` и initial bindings в function body. Затем lowering SHALL создавать leaf bindings с core-вызовами `get`. JavaScript и Java generators SHALL не содержать специальной логики для destructuring patterns.

#### Scenario: Lower sequential destructuring let binding
- **WHEN** source содержит `(let [[a b] (list "x" "y")] (str a b))`
- **THEN** lowering передаёт generator только symbol bindings для временного значения, `a` и `b`

#### Scenario: Lower associative destructuring let binding
- **WHEN** source содержит `(let [{:name n :age a} (hash-map "name" "Ada" "age" "36")] (str n a))`
- **THEN** lowering передаёт generator только symbol bindings, использующие `get` с ключами `"name"` и `"age"`

#### Scenario: Lower nested destructuring let binding
- **WHEN** source содержит `let` binding с вложенными sequential или associative patterns
- **THEN** lowering рекурсивно создаёт symbol bindings для всех leaf symbols

#### Scenario: Preserve single evaluation of destructured value
- **WHEN** destructuring `let*` RHS имеет побочный эффект или вызывает функцию
- **THEN** JavaScript и Java выполняют RHS ровно один раз до выполнения leaf bindings

#### Scenario: Lower sequential function parameter pattern
- **WHEN** source содержит `(fn [[a b]] (str a b))`
- **THEN** lowering передаёт generator один fresh symbol parameter и symbol `let*` bindings для `a` и `b`
- **AND** generated function сохраняет arity в один аргумент

#### Scenario: Lower associative and nested function parameter pattern
- **WHEN** source содержит `(fn [{:name n :tags [tag]}] (str n tag))`
- **THEN** lowering передаёт generator только symbol parameters and bindings
- **AND** leaf bindings используют `get` для каждого map key и list index

#### Scenario: Compile destructuring function parameters on all targets
- **WHEN** a `fn` or `defn` uses sequential, associative, or nested parameter patterns
- **THEN** JavaScript and Java compile the function without generator-specific destructuring support
- **AND** compiled execution produces the same bindings as eval

### Requirement: Compiler target runtimes SHALL provide core get

JavaScript и Java runtimes SHALL предоставлять двухаргументный `get` для list по неотрицательному целому индексу и hash-map по ключу. Отсутствующий ключ или индекс за границей SHALL возвращать `nil`/`null`. Коллекция `nil` SHALL возвращать `nil`/`null`. Чтение существующего `false` SHALL сохранять `false`. В JavaScript прочитанное `undefined` SHALL нормализоваться в `nil`/`null`. Числа, строки и booleans не получают поддержку как коллекции.

#### Scenario: Read list and hash-map values through get
- **WHEN** compiled source вызывает `get` для list по неотрицательному целому индексу или hash-map по ключу
- **THEN** runtime возвращает соответствующее значение
- **AND** отсутствующий индекс или ключ возвращает `nil`/`null`

#### Scenario: Nil-безопасный get и keyword lookup
- **WHEN** compiled source исполняет `(get nil :text)` или `(:text nil)`
- **THEN** JavaScript и Java возвращают `nil`/`null`

#### Scenario: Нормализация JS undefined
- **WHEN** JavaScript `get` читает отсутствующее свойство обычного JS object либо свойство со значением `undefined`
- **THEN** результат равен `null`
- **WHEN** прочитанное значение равно `false`, `0` или пустой строке
- **THEN** результат сохраняет это значение

### Requirement: Compiler targets SHALL предоставлять get-in с путём-вектором

JavaScript и Java SHALL поддерживать `(get-in collection keys)` с двумя аргументами и путём-вектором, в том числе полученным из переменной или функции. Результат SHALL соответствовать последовательному двухаргументному `get`, начиная с `collection`. Путь SHALL поддерживать map keys и неотрицательные целые индексы, включая смешанные пути. Пустой путь SHALL возвращать исходное значение. Отсутствующий ключ, индекс за границей или промежуточный `nil` SHALL давать `nil`; конечный `false` SHALL сохраняться. Продолжение пути через число, строку или boolean SHALL завершаться ошибкой. `nil`, map, строка и скаляры вместо пути SHALL отклоняться, даже при исходной коллекции `nil`. Точный текст ошибок не фиксируется. Поведение list-пути и некорректных индексов не специфицируется; существующая поддержка list-пути допустима. Трёхаргументный вариант не входит в контракт. Для гарантированных сценариев результаты SHALL совпадать с evaluator.

#### Scenario: Вложенный ключ и смешанный путь
- **WHEN** compiled source исполняет `(get-in {:chat {:id 42}} [:chat :id])` и `(get-in {:items [{:id 42}]} [:items 0 :id])`
- **THEN** оба результата равны `42` на JavaScript и Java

#### Scenario: Путь из значения
- **WHEN** compiled source исполняет `(let [path [:chat :id]] (get-in {:chat {:id 42}} path))`
- **THEN** результат равен `42`

#### Scenario: Отсутствующие данные
- **WHEN** compiled source исполняет `(get-in {} [:chat :id])`, `(get-in {:chat nil} [:chat :id])`, `(get-in nil [:chat :id])` и `(get-in {:items []} [:items 0 :id])`
- **THEN** каждый результат равен `nil`/`null`

#### Scenario: Сохранение false
- **WHEN** compiled source исполняет `(get-in {:enabled false} [:enabled])`
- **THEN** результат равен `false`

#### Scenario: Пустой путь
- **WHEN** compiled source исполняет `(get-in {:id 42} [])`, `(get-in nil [])` и `(get-in false [])`
- **THEN** результаты являются исходными значениями: map `{:id 42}`, `nil`/`null` и `false`

#### Scenario: Скаляр внутри пути
- **WHEN** compiled source исполняет `(get-in {:chat value} [:chat :id])`, где `value` равно `42`, `"hello"` или `false`
- **THEN** исполнение завершается ошибкой

#### Scenario: Неверный тип пути
- **WHEN** compiled source передаёт в `get-in` вместо пути `nil`, map, строку, число или boolean, в том числе при исходной коллекции `nil`
- **THEN** исполнение завершается ошибкой

### Requirement: Compiler target runtimes SHALL provide basic two-argument equality

JavaScript и Java runtimes SHALL предоставлять `_EQ_` для сравнения ровно двух значений. Для `nil`, boolean, string и integer значений одного типа результат SHALL быть `true`, когда значения равны, и `false`, когда они различаются.

#### Scenario: Equal scalar values
- **WHEN** compiled source вызывает `(= left right)` с двумя равными `nil`, boolean, string или integer значениями одного типа
- **THEN** JavaScript и Java target возвращают `true`

#### Scenario: Unequal scalar values
- **WHEN** compiled source вызывает `(= left right)` с двумя различными boolean, string или integer значениями одного типа
- **THEN** JavaScript и Java target возвращают `false`

#### Scenario: JavaScript runtime import
- **WHEN** JavaScript source содержит вызов `=`
- **THEN** generated runtime import предоставляет identifier `_EQ_`

### Requirement: Compiler target runtimes SHALL provide basic two-argument inequality

JavaScript и Java runtimes SHALL предоставлять `not_EQ_` для сравнения ровно двух значений. Для поддерживаемых `nil`, boolean, string и integer значений результат SHALL быть логическим отрицанием результата существующей `_EQ_` operation target для тех же аргументов.

#### Scenario: Equal scalar values are not unequal
- **WHEN** compiled source вызывает `(not= left right)` с двумя равными `nil`, boolean, string или integer значениями одного типа
- **THEN** JavaScript и Java target возвращают `false`

#### Scenario: Unequal scalar values are unequal
- **WHEN** compiled source вызывает `(not= left right)` с двумя различными boolean, string или integer значениями одного типа
- **THEN** JavaScript и Java target возвращают `true`

#### Scenario: JavaScript runtime import
- **WHEN** compiler генерирует JavaScript module
- **THEN** unconditional runtime import предоставляет identifier `not_EQ_`

### Requirement: Compiler target runtimes SHALL provide core logical negation

JavaScript и Java runtimes SHALL предоставлять одноаргументную core-функцию `not`, которая возвращает boolean, противоположный language truthiness переданного значения.

#### Scenario: Negate falsey values
- **WHEN** compiled source вызывает `not` со значением `false` или `nil`
- **THEN** JavaScript и Java target возвращают `true`

#### Scenario: Negate truthy values
- **WHEN** compiled source вызывает `not` с любым другим значением, включая integer `0`
- **THEN** JavaScript и Java target возвращают `false`

#### Scenario: JavaScript runtime import
- **WHEN** compiler генерирует JavaScript module
- **THEN** unconditional runtime import предоставляет identifier `not`

### Requirement: Compiler target runtimes SHALL provide binary integer comparisons

JavaScript и Java runtimes SHALL предоставлять `_GT_`, `_LT_`, `_GT__EQ_` и `_LT__EQ_` для бинарного сравнения integer значений, представимых соответствующим target.

#### Scenario: Strict integer comparisons
- **WHEN** compiled source вызывает `(> left right)` или `(< left right)` с двумя поддерживаемыми integer значениями
- **THEN** JavaScript и Java target возвращают `true` exactly when `left` соответственно больше или меньше `right`

#### Scenario: Inclusive integer comparisons
- **WHEN** compiled source вызывает `(>= left right)` или `(<= left right)` с двумя поддерживаемыми integer значениями
- **THEN** JavaScript и Java target возвращают `true` exactly when `left` соответственно больше или равен либо меньше или равен `right`

#### Scenario: JavaScript runtime imports
- **WHEN** compiler генерирует JavaScript module
- **THEN** unconditional runtime import предоставляет identifiers `_GT_`, `_LT_`, `_GT__EQ_` и `_LT__EQ_`

### Requirement: Compiler target runtimes SHALL support reduce with an initial value

JavaScript и Java runtimes SHALL поддерживать `(reduce fn init collection)` для list, выполняя left fold по всем элементам `collection` начиная с `init`. Существующая форма `(reduce fn collection)` SHALL сохранить текущее поведение.

#### Scenario: Reduce a non-empty list with an initial value
- **WHEN** compiled source вызывает `(reduce fn init collection)` с непустым list
- **THEN** runtime вызывает `fn` для каждого элемента по порядку как `fn(acc, item)`, начиная с `init`
- **AND** JavaScript и Java возвращают тот же результат, что и evaluator

#### Scenario: Reduce an empty list with an initial value
- **WHEN** compiled source вызывает `(reduce fn init collection)` с пустым list
- **THEN** runtime возвращает `init`
- **AND** runtime не вызывает `fn`

#### Scenario: Preserve two-argument reduce
- **WHEN** compiled source вызывает `(reduce fn collection)` с непустым list
- **THEN** runtime использует первый элемент как initial accumulator и сворачивает оставшиеся элементы
- **AND** вызов с пустым list продолжает завершаться ошибкой

### Requirement: Compiler target runtimes SHALL provide core drop

JavaScript и Java runtimes SHALL предоставлять core-функцию `drop`, которая принимает целое число и list и возвращает list без первых указанного количества элементов.

#### Scenario: Drop items from a list
- **WHEN** compiled source вызывает `(drop n items)` с положительным целым `n`, меньшим длины `items`
- **THEN** target runtime возвращает оставшиеся элементы в исходном порядке
- **AND** JavaScript и Java возвращают тот же результат, что и evaluator

#### Scenario: Drop with boundary counts
- **WHEN** `n` меньше или равно нулю
- **THEN** target runtime возвращает все элементы list
- **WHEN** `n` не меньше длины list
- **THEN** target runtime возвращает пустой list

### Requirement: The JavaScript compiler SHALL emit ES module code using the language runtime

The JavaScript target SHALL считать объявленный `ns` каноническим путём модуля относительно output root: точки разделяют каталоги, а последний сегмент задаёт имя `.js` файла. Target SHALL вычислять относительный префикс к output root по глубине текущего namespace и применять его к runtime import и символьным namespace requires. Для namespace из одного сегмента и исходника без `ns` префикс SHALL оставаться `./`. Символьный namespace require SHALL компилироваться в путь от output root с расширением `.js`: compiler SHALL применять стандартное symbol munging к required namespace, затем преобразовывать точки в `/`. Строковый `:require` SHALL сохранять свой module specifier как bare ESM import без munging, добавления префикса output root или `.js`. Локальный алиас string require SHALL использовать стандартное munging символов, чтобы быть допустимым JavaScript identifier. Строковые литералы SHALL сохранять исходное содержимое, включая `/`. Форма `(export-default key value ...)` SHALL принимать одну или несколько пар с keyword или string literal keys и компилироваться в статическую ESM-декларацию, значением которой является обычный JavaScript object с соответствующими own properties. Она SHALL NOT вызывать `hash_map` или `export_default`. Пустая форма, нечётное число аргументов или key, который после desugaring не представлен строковым atom, SHALL приводить к ошибке JavaScript compilation. Public top-level `def` SHALL compile to an `export const` binding; top-level `def` with private metadata SHALL compile to a non-exported `const` binding.

#### Scenario: Runtime import
- **WHEN** source без `ns` или с `(ns main)` компилируется в JavaScript
- **THEN** generated module импортирует runtime functions из `./language_runtime.js`

#### Scenario: Runtime import from a nested namespace
- **WHEN** source с `(ns app.commands.add)` компилируется как `app/commands/add.js` относительно output root
- **THEN** generated module импортирует runtime functions из `../../language_runtime.js`

#### Scenario: Namespace requires
- **WHEN** source содержит `(ns main (:require [io.math.core :as mc]))`
- **THEN** JavaScript emits `import * as mc from "./io/math/core.js"`

#### Scenario: Nested namespace requires a root namespace
- **WHEN** source содержит `(ns commands.add (:require [db :as db]))` и компилируется как `commands/add.js` относительно output root
- **THEN** JavaScript emits `import * as db from "../db.js"`

#### Scenario: Nested namespace relationships
- **WHEN** source в namespace `app.commands.add` требует родительский `app.commands`, соседний `app.commands.remove`, дочерний `app.commands.add.audit` и чужой дочерний `other.feature.worker` namespaces
- **THEN** JavaScript emits imports соответственно из `../../app/commands.js`, `../../app/commands/remove.js`, `../../app/commands/add/audit.js` и `../../other/feature/worker.js`

#### Scenario: Hyphenated root namespace require
- **WHEN** source содержит `(ns main (:require [effect-fetch :as fetch]))`
- **THEN** JavaScript emits `import * as fetch from "./effect_fetch.js"`

#### Scenario: Hyphenated dotted namespace require
- **WHEN** source содержит `(ns main (:require [effects-promise.fetch :as fetch]))`
- **THEN** JavaScript emits `import * as fetch from "./effects_promise/fetch.js"`

#### Scenario: String Node module require
- **WHEN** source contains `(:require ["node:test" :as t])`
- **THEN** JavaScript emits `import * as t from "node:test"`

#### Scenario: String npm package require
- **WHEN** source contains `(:require ["wrangler" :as w])`
- **THEN** JavaScript emits `import * as w from "wrangler"`

#### Scenario: String require with a hyphenated alias
- **WHEN** source contains `(:require ["node:async_hooks" :as async-hooks])`
- **THEN** JavaScript emits `import * as async_hooks from "node:async_hooks"`

#### Scenario: String literal with slash
- **WHEN** source contains `(str "/")`
- **THEN** JavaScript emits `(str)("/")`

#### Scenario: Definitions and functions
- **WHEN** source contains a top-level `(defn handler [request] request)`
- **THEN** JavaScript emits an `export const` binding to an arrow function

#### Scenario: Public value definition
- **WHEN** source contains a top-level `(def storage value)`
- **THEN** JavaScript emits `export const storage = value`

#### Scenario: Private function definition
- **WHEN** source contains a top-level `(defn- helper [value] value)`
- **THEN** JavaScript emits a non-exported `const` binding to an arrow function

#### Scenario: Private value definition
- **WHEN** source contains a top-level `(def- storage value)`
- **THEN** JavaScript emits `const storage = value` and does not emit `def_`

#### Scenario: JavaScript interop syntax
- **WHEN** source uses `new` or `.` forms
- **THEN** JavaScript emits constructor calls and instance method calls

#### Scenario: Default export
- **WHEN** source contains `(export-default :fetch handler :scheduled scheduled-handler)`
- **THEN** JavaScript emits `export default {["fetch"]: handler, ["scheduled"]: scheduled_handler};`
- **AND** exported value has `Object.prototype` in its prototype chain
- **AND** output does not invoke `hash_map` or `export_default`

#### Scenario: Malformed default export
- **WHEN** source contains an empty `(export-default)`, an unmatched key, or a key that is neither a keyword nor a string literal
- **THEN** JavaScript compilation fails

#### Scenario: Ordinary hash maps retain their representation
- **WHEN** a map literal is compiled outside `export-default`
- **THEN** JavaScript continues to construct it through `hash_map`

### Requirement: Строковые JS module specifiers SHALL сохранять декодированное значение

JavaScript target SHALL представлять строковый `:require` корректным JS-строковым литералом, значение которого совпадает с декодированным значением исходного module specifier. Целевое экранирование SHALL NOT добавлять символы в значение или повторно декодировать source escapes. Это требование дополняет существующие правила ESM imports: munging, префикс output root и суффикс `.js` к строковому specifier SHALL NOT применяться. Требование определяет генерацию литерала, а не существование или загрузку указанного модуля.

#### Scenario: Кавычка в module specifier
- **WHEN** source содержит `(:require ["./a\"b.js" :as dep])`
- **THEN** generated import содержит `from "./a\"b.js"`, представляющий значение с одной кавычкой и без обратного слеша перед ней

#### Scenario: Обратный слеш без повторного декодирования
- **WHEN** source содержит `(:require ["./a\\n.js" :as dep])`
- **THEN** generated import содержит `from "./a\\n.js"`, представляющий обратный слеш и `n`, а не LF

#### Scenario: Управляющие символы и неизвестные пары
- **WHEN** строковый specifier содержит исходные `\n`, `\t`, `\r` или `\q`
- **THEN** generated JS-литерал корректно представляет соответственно LF, TAB, CR или буквальную пару обратного слеша и `q`, без вставки необработанного LF или CR в литерал

### Requirement: JavaScript compiler SHALL compile cast as a transparent expression

JavaScript compiler SHALL compile `(cast TYPE value)` as compiled `value`, не выполняя проверку `TYPE` и не генерируя runtime-зависимость для cast. `value` SHALL вычисляться ровно один раз согласно обычной семантике выражений JavaScript.

#### Scenario: Compile JavaScript cast
- **WHEN** source содержит `(cast java.util.List xs)`
- **THEN** JavaScript output содержит скомпилированное выражение `xs` без вызова или идентификатора `cast`

### Requirement: The Java compiler SHALL emit a Java helper class using the language runtime

The Java target SHALL emit Java source with a static import of `y2k.language.language_runtime.*` and a generated helper class.

#### Scenario: No namespace
- **WHEN** no namespace is declared
- **THEN** Java emits class `user`

#### Scenario: Namespace package and class
- **WHEN** namespace is `app.main`
- **THEN** Java emits package `app` and class `main`

#### Scenario: Top-level functions
- **WHEN** top-level `def` defines a `fn*`
- **THEN** Java emits a static method whose parameters are `Object`

#### Scenario: Qualified requires
- **WHEN** a required alias is used as `alias/member`
- **THEN** Java emits a call to the required namespace class and member

#### Scenario: Java imports
- **WHEN** namespace imports include Java classes
- **THEN** Java emits corresponding `import` statements

### Requirement: The Java compiler SHALL support Java interop forms

The Java target SHALL compile casts, constructors, method calls, annotated lambdas, and `gen-class` forms.

#### Scenario: Cast form
- **WHEN** source contains `(cast java.util.List xs)`
- **THEN** Java emits a Java cast expression

#### Scenario: Typed lambda annotation
- **WHEN** a `fn*` has metadata such as `^java.util.function.Function`
- **THEN** Java emits a lambda cast to the annotated target type

#### Scenario: Void typed lambda annotation
- **WHEN** a `fn*` has metadata `^void:java.lang.Runnable`
- **THEN** Java emits a void lambda body

#### Scenario: Invalid void annotation
- **WHEN** metadata is `^void:` with no target type
- **THEN** Java compilation fails with `Java lambda annotation ^void: requires a target type`

#### Scenario: gen-class
- **WHEN** source contains a valid `gen-class` declaration
- **THEN** Java emits a nested public static class extending the requested base class and forwarding declared methods to helper functions

### Requirement: Java compiler SHALL honor type hints on let bindings

Java target SHALL использовать `^TYPE` metadata символьного `let` binding для приведения RHS к `TYPE` перед созданием локальной переменной. RHS SHALL вычисляться ровно один раз в обычном последовательном порядке `let`, а последующие Java interop expressions SHALL видеть локальную переменную с указанным Java-типом. Это требование не применяется к destructuring patterns и не меняет поведение eval или JavaScript targets.

#### Scenario: Вызов Java-метода через hinted binding

- **WHEN** source содержит `(let [^java.lang.String text (make-text)] (.concat text "!"))`, где `make-text` компилируется с Java return type `Object`
- **THEN** Java output приводит результат `make-text` к `java.lang.String` перед созданием `text`
- **AND** generated Java компилируется и вызов `concat` возвращает ожидаемую строку

### Requirement: Java target SHALL вызывать функциональный результат выражения

Java target SHALL поддерживать выражение в позиции вызываемой функции, если его результат является функциональным значением языка с арностью текущего вызова от 0 до 4 включительно. Явный `cast` или промежуточный локальный binding SHALL NOT требоваться. Вызываемое выражение SHALL вычисляться ровно один раз на вызов. Для перечисленных ниже сценариев фабрики, callback-цепочки, `get`, `if` и поддерживаемых арностей generated Java SHALL компилироваться и при исполнении возвращать тот же результат, что и eval. В этих сценариях аргументы не создают побочных эффектов, взаимодействующих с вызываемым выражением. Порядок эффектов вызываемого выражения относительно эффектов аргументов этим требованием не определяется. Существующие вызовы непосредственной лямбды и выражения с явным приведением к соответствующему `FnN` SHALL сохранять работоспособность.

#### Scenario: Непосредственный вызов возвращённой функции
- **WHEN** `make-effect` возвращает `(fn [w] w)` и программа исполняет `((make-effect) "ok")`
- **THEN** generated Java компилируется и результат равен `"ok"`

#### Scenario: Цепочка вызовов через параметр
- **WHEN** параметр `onclick` содержит функцию без аргументов, возвращающую `(fn [w] w)`, и программа исполняет `((onclick) "ok")`
- **THEN** generated Java компилируется и результат равен `"ok"`

#### Scenario: Функция из коллекции
- **WHEN** программа исполняет `((get [(fn [w] w)] 0) "ok")`
- **THEN** generated Java компилируется и результат равен `"ok"`

#### Scenario: Функция из условного выражения
- **WHEN** программа исполняет `((if true (fn [w] w) (fn [w] nil)) "ok")`
- **THEN** generated Java компилируется и результат равен `"ok"`

#### Scenario: Поддерживаемые арности
- **WHEN** выражение возвращает функцию арности `N`, где `N` равно 0, 1, 2, 3 или 4, и результат вызывается с `N` аргументами
- **THEN** generated Java компилируется и передаёт значения аргументов соответствующим параметрам по их позиции

#### Scenario: Однократное вычисление фабрики
- **WHEN** фабрика увеличивает счётчик в atom и возвращает функцию, а программа непосредственно вызывает результат фабрики один раз с аргументами без побочных эффектов
- **THEN** счётчик увеличивается ровно на один и возвращённая функция вызывается с переданными аргументами

#### Scenario: Совместимость существующих форм
- **WHEN** программа вызывает непосредственную лямбду, локальное функциональное значение либо результат выражения с явным `cast FnN`, соответствующим числу аргументов
- **THEN** generated Java компилируется и сохраняет результат исполнения этих форм

### Requirement: Java target SHALL применять единое правило FnN к вызываемым выражениям

Функциональный вызов результата выражения SHALL приводить вызываемое значение к `FnN` по числу аргументов без исключений для непосредственных лямбд или явного `(cast TYPE ...)`. Наличие произвольного Java-метода `call` SHALL NOT заменять требование соответствующего `FnN`. Для прямого вызова такого Java-метода SHALL использоваться форма `(.call receiver args...)`, сохраняющая обычное поведение Java interop.

#### Scenario: Явный cast к FnN
- **WHEN** вызывается результат `(cast Fn1 (make-effect))` с одним аргументом и фабрика возвращает функцию одного аргумента
- **THEN** generated Java содержит внешний cast к `Fn1`, компилируется и сохраняет результат вызова

#### Scenario: Явный cast к произвольному Java-интерфейсу
- **WHEN** компилируется `((cast java.util.concurrent.Callable x))`
- **THEN** generated Java приводит вызываемое выражение к `Fn0` перед функциональным вызовом, несмотря на явный Java-тип
- **AND** успешный вызов не гарантируется для объекта, реализующего только `java.util.concurrent.Callable`

#### Scenario: Прямой вызов Java call
- **WHEN** программа исполняет `(.call (cast java.util.concurrent.Callable x))`, где `x` содержит `Callable`, возвращающий `"ok"`
- **THEN** generated Java вызывает Java-метод `call` без дополнительного приведения к `Fn0` и возвращает `"ok"`

### Requirement: Java target SHALL отклонять неподдерживаемую арность вызова выражения

При вызове результата выражения с более чем четырьмя аргументами Java target SHALL завершать генерацию ошибкой, указывающей неподдерживаемую арность, строку и столбец исходной формы вызова.

#### Scenario: Пять аргументов у вызова результата
- **WHEN** компилируется `(defn test [factory] ((factory) 1 2 3 4 5))`
- **THEN** Java-генерация завершается ошибкой, указывающей арность `5` и координаты внешнего вызова, до запуска `javac`

### Requirement: Java target SHALL предоставлять статическую проверку instance?

Java target SHALL поддерживать специальную форму `(instance? TYPE value)` с ровно двумя аргументами. `TYPE` SHALL быть статическим символом класса или интерфейса: коротким именем, разрешаемым обычными Java imports и правилами Java, либо полным именем. Операнд типа SHALL NOT вычисляться как значение языка. Generated Java SHALL использовать нативный `instanceof` без `Class/forName` и отражательной проверки типа. Результат SHALL быть boolean: `true` для экземпляра указанного класса, его подкласса или реализации указанного интерфейса, `false` для `nil` и несовместимого объекта. Числовые и boolean-значения SHALL проверяться как соответствующие boxed Java objects. Динамические Class-значения, параметризованные типы и отдельный синтаксис типов массивов не входят в контракт.

#### Scenario: Импортированный класс
- **WHEN** namespace содержит `(:import [java.util ArrayList])` и функция возвращает `(instance? ArrayList (ArrayList.))`
- **THEN** generated Java компилируется, содержит `instanceof` и функция возвращает `true`
- **AND** проверка не использует `Class/forName`

#### Scenario: Полное имя и подкласс
- **WHEN** функция возвращает `(instance? java.util.AbstractList (java.util.ArrayList.))`
- **THEN** результат равен `true`

#### Scenario: Интерфейс
- **WHEN** функция возвращает `(instance? java.util.List (java.util.ArrayList.))`
- **THEN** результат равен `true`

#### Scenario: Nil и несовместимый объект
- **WHEN** функции проверяют `(instance? String nil)` и `(instance? Integer "hello")`
- **THEN** generated Java компилируется и обе проверки возвращают `false`

#### Scenario: Boxing скаляров
- **WHEN** функции проверяют `(instance? Integer 42)`, `(instance? Boolean true)` и `(instance? String 42)`
- **THEN** результаты равны соответственно `true`, `true` и `false`

### Requirement: Java instance? SHALL сохранять однократное вычисление значения

При достижении формы `instance?` Java target SHALL вычислять `value` ровно один раз. Форма SHALL работать в условии, возвращаемом значении, аргументе вызова, binding и позиции с отброшенным результатом, включая `value` с `if`, `let` или `do`. Невыбранная ветвь SHALL NOT выполнять содержащуюся в ней проверку или её `value`.

#### Scenario: Побочный эффект значения
- **WHEN** `value` увеличивает счётчик и возвращает объект, проверяемый через `instance?`
- **THEN** счётчик увеличивается ровно на один и результат соответствует типу объекта

#### Scenario: Управляющая форма в значении
- **WHEN** `value` использует `let`, `do` и `if` для выбора объекта с наблюдаемым побочным эффектом
- **THEN** generated Java компилируется и выполняет эффекты выбранного пути ровно один раз

#### Scenario: Отброшенный результат
- **WHEN** функция выполняет `(instance? Object (make-value))` перед последним выражением тела
- **THEN** generated Java компилируется, `make-value` вызывается ровно один раз и функция возвращает последнее выражение

#### Scenario: Проверка в невыбранной ветви
- **WHEN** `instance?` находится в невыбранной ветви `if`
- **THEN** побочные эффекты её `value` отсутствуют

### Requirement: Java instance? SHALL диагностировать недопустимую форму и тип

Неверная арность, несимвольный операнд типа, literal вместо имени типа и primitive type, включая `void`, SHALL приводить к ошибке до запуска `javac`. Ошибка SHALL указывать `instance?`, причину и исходную позицию. Выражение в позиции типа SHALL NOT становиться допустимым из-за упрощения при компиляции. Неизвестное или недоступное имя класса SHALL отклоняться при компиляции generated Java через `javac`; Java-генератор не обязан проверять classpath. Точный текст ошибки `javac` не фиксируется.

#### Scenario: Неверная арность
- **WHEN** компилируются `(instance?)`, `(instance? String)` или `(instance? String value extra)`
- **THEN** генерация завершается ошибкой арности `instance?` с координатами формы

#### Scenario: Недопустимый операнд типа
- **WHEN** первым аргументом переданы `"String"`, `:String`, `42`, `nil`, `true`, `false`, `int`, `void`, `(do String)` или `(if true String Object)`
- **THEN** генерация завершается ошибкой операнда типа `instance?` с исходной позицией

#### Scenario: Неизвестный класс
- **WHEN** форма использует отсутствующий на classpath тип `missing.package.NoSuchType`
- **THEN** `javac` отклоняет generated Java до исполнения программы

### Requirement: Eval и JavaScript SHALL явно отклонять instance?

JavaScript target SHALL отклонять компиляцию формы `instance?`, а eval SHALL отклонять её при достижении во время исполнения. Диагностика SHALL называть `instance?` и указывать, что форма поддерживается только Java target. На eval аргументы неподдерживаемой формы SHALL NOT вычисляться.

#### Scenario: JavaScript compilation
- **WHEN** JavaScript target компилирует функцию, содержащую `(instance? String value)`
- **THEN** компиляция завершается явной ошибкой неподдерживаемой формы

#### Scenario: Eval execution
- **WHEN** eval достигает `(instance? String (make-value))`
- **THEN** возникает явная ошибка неподдерживаемой формы до вызова `make-value`

### Requirement: Java gen-class SHALL поддерживать новые void instance methods

Java target SHALL позволять объявлять через `gen-class` новые публичные `void` instance methods, отсутствующие у указанного предка, в пределах существующих ограничений арности и Java-типов. Метод SHALL передавать текущий экземпляр первым аргументом в соответствующую top-level реализацию `-method`, а объявленные аргументы — следом в исходном порядке. Методы `gen-class` SHALL генерироваться без `@Override`. Переопределение SHALL определяться обычными правилами Java, без новой metadata для проверки такого намерения. Non-void methods SHALL оставаться неподдерживаемыми.

#### Scenario: Новый метод у подкласса Object
- **WHEN** source объявляет `(gen-class :name Runner :extends Object :methods [[main [] void]])` и top-level `(defn -main [this] (println "ok"))`
- **THEN** generated Java компилируется через `javac` вместе с runtime
- **AND** вызов `main()` на экземпляре `Runner` выводит `ok`
- **AND** объявленный метод не содержит `@Override`

#### Scenario: Передача получателя и аргументов нового метода
- **WHEN** source объявляет новый метод `[accept [String String] void]` и реализацию `-accept` с параметрами `this`, `left`, `right`
- **THEN** вызов `accept("left", "right")` передаёт реализации тот же экземпляр, строку `"left"` и строку `"right"` в этом порядке

#### Scenario: Неподдерживаемый результат метода
- **WHEN** `gen-class` объявляет метод с return type, отличным от `void`
- **THEN** Java-генерация завершается ошибкой `gen-class: only void methods are supported`

### Requirement: Java gen-class SHALL сохранять независимость переопределения и вызова super

Метод `gen-class`, сигнатура которого переопределяет доступный метод предка по правилам Java, SHALL сохранять динамическую диспетчеризацию независимо от наличия `^override`. Без этой metadata generated method SHALL вызывать только соответствующую реализацию языка, без неявного вызова предка. При `^override` метод SHALL сначала вызвать `super.method(...)` с исходными аргументами, а после его нормального завершения — реализацию языка ровно один раз. Metadata SHALL NOT делать допустимым вызов отсутствующего или недоступного метода предка.

#### Scenario: Переопределение без super
- **WHEN** `gen-class` переопределяет конкретный `void`-метод предка без `^override`, и метод вызывают через ссылку типа предка
- **THEN** выполняется реализация языка ровно один раз
- **AND** тело метода предка не выполняется
- **AND** generated method не содержит `@Override`

#### Scenario: Переопределение с super
- **WHEN** `gen-class` переопределяет конкретный `void`-метод предка с `^override`, и вызов предка завершается нормально
- **THEN** сначала выполняется тело метода предка ровно один раз, затем реализация языка ровно один раз
- **AND** реализация языка наблюдает побочные эффекты уже выполненного метода предка
- **AND** generated method не содержит `@Override`

#### Scenario: Super для отсутствующего метода
- **WHEN** подкласс `Object` объявляет `[^override main [] void]`
- **THEN** generated Java содержит вызов `super.main()` и отклоняется `javac`, поскольку такого метода у предка нет

### Requirement: Java gen-class SHALL позволять прямой запуск instance main на JDK 25

Для namespace `checks.entry`, `gen-class` с именем `Runner`, предком `Object` и методом `[main [] void]` Java target SHALL генерировать вложенный класс, запускаемый непосредственно как `checks.entry$Runner` средствами JDK 25. После компиляции generated source вместе с runtime запуск SHALL выполнять реализацию `-main` без отдельного static-main wrapper и без preview flags.

#### Scenario: Прямой запуск вложенного класса
- **WHEN** source содержит `(ns checks.entry)`, `(gen-class :name Runner :extends Object :methods [[main [] void]])` и `(defn -main [this] (println "ok"))`, а generated Java и runtime скомпилированы в каталог `out` средствами JDK 25
- **THEN** команда `java -cp out 'checks.entry$Runner'` на JDK 25 успешно завершается и выводит `ok`
- **AND** запуск не требует `--enable-preview` или отдельного класса-обёртки

### Requirement: Java target SHALL задавать явную видимость top-level определений

Java target SHALL генерировать обычные top-level `defn` и core `def`, содержащие `fn*`, как `public static` методы, а остальные обычные top-level `def` как `public static` поля. Определения с private metadata, включая `defn-` и `def-`, SHALL генерироваться соответственно как `private static` методы и поля. Правило SHALL применяться как при наличии `ns`, так и к классу `user` без `ns`, независимо от способа инициализации поля.

#### Scenario: Публичные и приватные методы
- **WHEN** исходник объявляет `(defn visible [] 1)` и `(defn- hidden [] 2)`
- **THEN** Java содержит `public static Object visible()` и `private static Object hidden()` с обычным контрактом исключений

#### Scenario: Поля с простым и составным значением
- **WHEN** исходник объявляет `(def scalar 1)`, `(def items [1 2])`, `(def- secret 3)` и `(def- secrets [3 4])`
- **THEN** поля `scalar` и `items` имеют модификаторы `public static`, а `secret` и `secrets` имеют модификаторы `private static`
- **AND** значения и порядок инициализации сохраняются

#### Scenario: Определения без namespace
- **WHEN** публичные и приватные определения компилируются без `ns`
- **THEN** методы и поля класса `user` получают те же явные модификаторы видимости

### Requirement: Java target SHALL обеспечивать публичный доступ между packages

Публичные методы и поля сгенерированного namespace SHALL быть доступны другому namespace через alias `:require`, включая namespace в другом Java package. Совместная компиляция исходников вместе с runtime через `javac` SHALL завершаться успешно, а исполнение SHALL возвращать объявленные значения.

#### Scenario: Вызов функции из issue #23
- **WHEN** `words.dic.serbian` объявляет `(defn words [] [["zdravo" "привет"]])`, а `words.app` требует его как `serbian` и вызывает `(serbian/words)`
- **THEN** сгенерированные классы компилируются вместе с runtime
- **AND** вызов возвращает объявленный вложенный список

#### Scenario: Чтение публичных полей
- **WHEN** namespace в другом package через alias читает публичные поля, одно с простым значением и другое со значением коллекции
- **THEN** generated Java компилируется, а чтение возвращает исходные значения обоих полей

### Requirement: Java target SHALL ограничивать private определения своим namespace

Приватные методы и поля SHALL оставаться доступными внутри сгенерированного класса своего namespace, включая вложенные классы `gen-class`. Обращение к ним из класса другого namespace SHALL отклоняться `javac`, даже если оба namespace отображаются в один Java package. Точный текст диагностики `javac` не фиксируется.

#### Scenario: Внутренний доступ
- **WHEN** публичная функция своего namespace вызывает `defn-` и читает `def-`
- **THEN** generated Java компилируется и функция возвращает ожидаемый результат

#### Scenario: Внешний доступ из того же package
- **WHEN** другой namespace того же Java package отдельно пытается вызвать приватную функцию или прочитать приватное поле
- **THEN** каждый такой исходник отклоняется `javac` из-за недоступности соответствующего члена

#### Scenario: Внешний доступ из другого package
- **WHEN** namespace другого Java package отдельно пытается вызвать приватную функцию или прочитать приватное поле
- **THEN** каждый такой исходник отклоняется `javac` из-за недоступности соответствующего члена

#### Scenario: Приватная реализация gen-class
- **WHEN** метод `gen-class` делегирует в `defn-` своего namespace
- **THEN** generated Java компилируется, а вызов метода выполняет приватную реализацию

### Requirement: Compiler targets SHALL предоставлять переносимый regex API

JavaScript и Java SHALL предоставлять без пользовательского импорта `(re-pattern pattern)`, `(re-pattern pattern flags)`, `(re-find regex text)`, `(re-find-groups regex text)` и `(re-replace text regex replacement)` с арностями 1 или 2, 2, 2 и 3 соответственно. Pattern, flags, text и replacement SHALL быть строковыми runtime-значениями, regex — результатом re-pattern. Пустой pattern SHALL быть допустимым. Строка вместо regex SHALL NOT компилироваться неявно. Без flags или с `""` поиск SHALL учитывать регистр; `"i"` SHALL включать регистронезависимость ASCII. Другие flags SHALL отклоняться. Regex reader syntax не входит в API.

#### Scenario: API в скомпилированном исходнике
- **WHEN** программа без imports связывает r с `(re-pattern "foo[0-9]+")`, затем выполняет `(str (re-find r "xfoo42") "|" (re-replace "foo1 foo2" r "X"))`
- **THEN** generated JS и Java компилируются и исполняются с результатом `"foo42|X X"`, как eval

#### Scenario: Вложенный namespace
- **WHEN** программа с namespace `checks.regex.core` вызывает regex API, включая re-find-groups и двухаргументный re-pattern
- **THEN** bindings доступны через стандартное подключение runtime соответствующего target

#### Scenario: Необязательные flags
- **WHEN** выполняются `(re-find (re-pattern "post" "") "POST")` и `(re-find (re-pattern "post" "i") "POST")`
- **THEN** результаты — nil и `"POST"`, как eval
- **WHEN** выполняется `(re-find (re-pattern "[a-z]+" "i") "ABC")`
- **THEN** результат — `"ABC"`, исходный регистр текста сохраняется

### Requirement: Compiler targets SHALL согласовывать переносимый regex-поиск с eval

Для переносимого подмножества JavaScript и Java SHALL возвращать те же результаты, что eval. Гарантия распространяется на pattern и text из печатного ASCII, TAB и LF; regex escapes SHALL использоваться после обычного декодирования строк языка. Подмножество включает литералы, экранированные метасимволы, простые положительные/отрицательные классы и диапазоны, `\d`, `\D`, `\w`, `\W`, `\s`, `\S` внутри и вне классов, `.`, конкатенацию, `|`, обычные группы, greedy/lazy `*`, `+`, `?`, `{n}`, `{n,}`, `{n,m}`, `^` и `$`. Классы с POSIX-синтаксисом, вложением и пересечением, lookaround, backreferences, inline flags и прочие расширения вне общей гарантии; единое отклонение этих расширений не требуется. Unicode и остальные управляющие символы подчиняются диалекту target и SHALL быть описаны как непереносимые.

Поиск SHALL учитывать регистр без flags или с `""`; при `"i"` SHALL игнорировать регистр ASCII, сохраняя исходный текст совпадения. `.` SHALL не совпадать с LF, anchors SHALL обозначать начало и строгий конец всей строки. Re-find SHALL возвращать первое слева полное совпадение строкой, независимо от capture groups; порядок альтернатив и greedy/lazy SHALL определять выбор в одной позиции. Отсутствие совпадения SHALL давать ложное nil, пустое совпадение — истинную пустую строку.

#### Scenario: Порядок альтернатив и длина совпадения
- **WHEN** выполняется поиск `"foo([0-9]+)"` в `"xfoo42 foo7"`, `"a|ab"` в `"ab"`, `"a+"` и `"a+?"` в `"aaa"`
- **THEN** результаты соответственно `"foo42"`, `"a"`, `"aaa"`, `"a"`, а не коллекции групп

#### Scenario: Nil отличается от пустого совпадения
- **WHEN** r1 ищет `"x"` в `"abc"`, а r2 ищет пустой шаблон в `"abc"` или пустом text
- **THEN** первый результат равен nil, ложен и не равен `"nil"`; второй равен `""`, истинен и не равен nil

#### Scenario: Регистр, точка и anchors
- **WHEN** выполняется поиск `"foo"` в `"FOO"`, `"^foo"` в `"x\nfoo"`, `"foo$"` в `"foo\n"` и `"a.b"` в `"a\nb"`
- **THEN** каждый результат — nil
- **WHEN** выполняется поиск `"foo$"` в `"foo"` и `"a[\\s\\S]b"` в `"a\nb"`
- **THEN** результаты — `"foo"` и `"a\nb"`

#### Scenario: Anchors не изменяют буквальные символы
- **WHEN** выполняется поиск шаблонов `"[$]"`, `"\\$"` и `"[.]"` в `"x$.$"`
- **THEN** результаты — `"$"`, `"$"` и `"."`

#### Scenario: Классы word и non-word
- **WHEN** выполняется поиск `"[\\W]+"`, `"\\W+"` и `"[^\\w]+"` в `"!!!"` и `"abc_42"`
- **THEN** каждый шаблон возвращает `"!!!"` для первой строки и nil для второй
- **WHEN** выполняется поиск `"[^\\W]+"` в `"!!!abc_42"` и `"[\\W_]+"` в `"a_!?b"`
- **THEN** результаты — `"abc_42"` и `"_!?"`

#### Scenario: Флаг не меняет anchors и точку
- **WHEN** с flags `"i"` выполняется поиск `"^foo"` в `"x\nFOO"`, `"foo$"` в `"FOO\n"` и `"a.b"` в `"A\nB"`
- **THEN** каждый результат — nil

### Requirement: Compiler targets SHALL выполнять переносимую буквальную regex-замену

Re-replace SHALL заменять все неперекрывающиеся совпадения слева направо, вставляя replacement буквально без раскрытия dollar/backslash и без повторного сканирования вставленного текста. При отсутствии совпадений SHALL возвращаться исходное содержимое; пустой replacement SHALL удалять совпадение. Для переносимого подмножества результат SHALL совпадать с eval, включая пустые совпадения.

Пустое совпадение SHALL вставлять replacement и продвигать поиск на один исходный ASCII-символ, сохраняя его. Пустое совпадение непосредственно в конце предыдущего непустого совпадения SHALL пропускаться с таким же продвижением, если исходный символ существует. Конец строки SHALL обрабатываться не более одного раза; обработка SHALL завершаться и для пустого pattern/text. Anchors SHALL сохранять привязку к целому исходному text при продвижении поиска.

#### Scenario: Глобальная замена и удаление
- **WHEN** выполняются `(re-replace "foo1 foo22" (re-pattern "foo[0-9]+") "X")`, `(re-replace "abc" (re-pattern "x") "X")` и `(re-replace "export f" (re-pattern "^export ") "")`
- **THEN** результаты — `"X X"`, `"abc"` и `"f"`

#### Scenario: Буквальный replacement
- **WHEN** выполняется `(re-replace "aa" (re-pattern "(a)") "$1\\1$&")`
- **THEN** результат — `"$1\\1$&$1\\1$&"`
- **WHEN** выполняются замены `"a"` на `"aa"` в `"aa"` и `"aa"` на `"X"` в `"aaa"`
- **THEN** результаты — `"aaaa"` и `"Xa"`

#### Scenario: Пустые совпадения и завершение
- **WHEN** пустой шаблон заменяется на `"-"` в `"ab"` и `""`
- **THEN** результаты — `"-a-b-"` и `"-"`
- **WHEN** `"a*"` заменяется на `"-"` в `"ab"` и `"a"`
- **THEN** результаты — `"-b-"` и `"-"`
- **WHEN** пустой шаблон заменяется пустой строкой в `"ab"`
- **THEN** результат — `"ab"`, вызов завершается

#### Scenario: Anchors при глобальном обходе
- **WHEN** `"^"` и `"$"` заменяются на `"-"` в `"ab"`
- **THEN** результаты — `"-ab"` и `"ab-"`

### Requirement: Compiler targets SHALL сохранять непрозрачность regex-значений

Regex SHALL быть истинным, не-callable значением, сохраняющим пригодность к regex API при передаче через bindings, функции, list/map values, get/get-in, деструктуризацию и Atom. Str SHALL представлять regex как `#<regex>`, включая значения внутри коллекций. Бинарное = SHALL возвращать false, если хотя бы один непосредственный операнд — regex, включая сравнение с собой; бинарное not= SHALL возвращать true. Это требование не расширяет гарантии равенства коллекций, lookup по regex-ключам, других арностей =/not= и финального runner output на compiled targets.

#### Scenario: Прямое равенство
- **WHEN** r связано с `(re-pattern "x")` и вычисляются `(= r r)`, `(not= r r)`, `(= r (re-pattern "x"))`, `(= r "x")` и `(= "x" r)`
- **THEN** результаты — false, true, false, false и false

#### Scenario: Сохранение значения и текста
- **WHEN** regex проходит через identity-функцию, get/get-in по обычным ключам и индексам, деструктуризацию let/fn и atom/deref/reset!/swap!
- **THEN** результат остаётся истинным и пригодным для re-find
- **WHEN** вычисляются `(str (re-pattern "x"))` и `(str [(re-pattern "x")])`
- **THEN** результаты — `"#<regex>"` и `"(#<regex>)"`

#### Scenario: Повторное использование после поиска и замены
- **WHEN** один r используется для поиска в `"x"`, поиска в `"abc"`, замены `"xx"` на `"zz"` и поиска в `"xx"`
- **THEN** результаты — `"x"`, nil, `"zz"`, `"x"`; позиция предыдущего поиска не влияет на последующий вызов

#### Scenario: Regex не является функцией
- **WHEN** программа пытается вызвать локальное regex-значение как функцию
- **THEN** исполнение завершается ошибкой; единый текст и класс этой ошибки не требуются

### Requirement: Compiler targets SHALL проверять аргументы regex API до поиска

Неверные арности, неверные runtime-типы, flags кроме `""` и `"i"` и недопустимые для текущего движка шаблоны SHALL приводить к ошибке исполнения, называющей regex builtin и ожидаемые аргументы либо причину недопустимого pattern или flags. Проверки SHALL выполняться и для пустого text или отсутствующего совпадения, включая re-find-groups. Callback replacement SHALL отклоняться. Keywords и другие значения, уже представленные target как строки, SHALL приниматься как строки; числа, booleans и nil SHALL NOT преобразовываться в строки автоматически. Различия представления quoted symbols не входят в переносимую гарантию. Необработанная ошибка в исполняемой compiled программе SHALL приводить к ненулевому exit status и диагностике в stderr; стадия генерации исходника не обязана исполнять regex и выявлять такие ошибки. Точный текст, host exception type и stack trace не фиксируются.

#### Scenario: Неверные арности
- **WHEN** compiled программа вызывает regex builtin с меньшим или большим числом аргументов, включая `(re-pattern "x" "i" "extra")`, `(re-find-groups)`, `(re-find-groups (re-pattern "x"))` и `(re-find-groups (re-pattern "x") "x" "extra")`
- **THEN** исполнение завершается ошибкой с именем builtin и указанием ожидаемых аргументов

#### Scenario: Типы даже при пустом вводе
- **WHEN** выполняются `(re-pattern nil)`, `(re-pattern 42)`, `(re-pattern false)`, `(re-find "x" "")`, `(re-find (re-pattern "x") nil)` или `(re-replace "" (re-pattern "x") (fn [x] x))`
- **THEN** каждый вызов завершается ошибкой соответствующего builtin до поиска

#### Scenario: Ошибка синтаксиса pattern
- **WHEN** исполняется `(re-pattern "[")`
- **THEN** возникает ошибка с именем re-pattern, а при отсутствии обработчика процесс завершается ненулевым кодом с диагностикой в stderr

#### Scenario: Ошибки flags
- **WHEN** re-pattern получает вторым аргументом nil, false, число, коллекцию либо строку `"g"`, `"m"`, `"ii"`, `"I"` или `"flags"`
- **THEN** возникает ошибка исполнения с именем re-pattern и причиной ошибки flags

#### Scenario: Типы поиска групп
- **WHEN** выполняется `(re-find-groups "x" "")` или `(re-find-groups (re-pattern "x") nil)`
- **THEN** возникает ошибка исполнения с именем re-find-groups до поиска

### Requirement: Compiler targets SHALL возвращать группы первого regex-совпадения

Re-find-groups SHALL выполнять тот же поиск первого совпадения, что re-find. Успешный результат SHALL быть обычной коллекцией языка: полное совпадение на позиции 0, затем строки групп по порядку открывающих скобок. При отсутствии совпадения SHALL возвращаться nil/null. Get, count и позиционная деструктуризация SHALL работать как для обычного list/vector. Re-find SHALL сохранять строковый результат.

#### Scenario: Извлечение ID
- **WHEN** r равно `(re-pattern "post-([0-9]+)" "i")` и text равно `"xPOST-5657 post-42"`
- **THEN** re-find-groups возвращает коллекцию `"POST-5657"`, `"5657"`, как eval; get по 1 возвращает `"5657"`, count равен 2
- **AND** re-find возвращает только `"POST-5657"`

#### Scenario: Порядок вложенных групп
- **WHEN** выполняется `(re-find-groups (re-pattern "((ab)([0-9]+))") "xab42")`
- **THEN** результат содержит ровно `"ab42"`, `"ab42"`, `"ab"`, `"42"` в этом порядке

#### Scenario: Совпадение без групп и отсутствие совпадения
- **WHEN** выполняются `(re-find-groups (re-pattern "ab") "xab")` и `(re-find-groups (re-pattern "z") "xab")`
- **THEN** первый результат — одноэлементная коллекция с `"ab"`, второй равен nil, ложен и не равен `"nil"`

#### Scenario: Передача и деструктуризация
- **WHEN** результат извлечения ID передаётся через функцию и извлекается позиционной деструктуризацией
- **THEN** полное совпадение и группа сохраняются строками, как на eval

### Requirement: Compiler targets SHALL различать отсутствующие и пустые группы

Для необязательных групп и ветвей альтернативы, не участвовавших в совпадении, re-find-groups SHALL возвращать nil/null на соответствующих позициях, сохраняя их число; JS undefined SHALL нормализоваться в null. Пустая участвовавшая группа SHALL давать `""`. Захваты внутри повторяемой группы SHALL следовать движку target без гарантии одинаковых результатов и быть описаны в справочнике.

#### Scenario: Необязательная группа
- **WHEN** выполняется `(re-find-groups (re-pattern "(a)?(b)") "b")`
- **THEN** результат содержит ровно `"b"`, nil, `"b"`; группа 1 равна nil, ложна и не равна `"nil"`
- **AND** на JS элемент результата действительно null, а не undefined

#### Scenario: Неучаствовавшая альтернатива
- **WHEN** выполняется `(re-find-groups (re-pattern "(a)|(b)") "b")`
- **THEN** результат содержит ровно `"b"`, nil, `"b"`

#### Scenario: Пустая группа и пустой шаблон
- **WHEN** выполняются `(re-find-groups (re-pattern "(a*)b") "b")` и `(re-find-groups (re-pattern "") "")`
- **THEN** результаты содержат соответственно `"b"`, `""` и только `""`
- **AND** пустая группа истинна и не равна nil; оба результата — истинные коллекции

### Requirement: Compiler targets SHALL сохранять flags во всех regex-операциях

Флаг i SHALL влиять на re-find, re-find-groups и re-replace одного regex. Каждая операция SHALL начинать независимый поиск. Глобальность и буквальность замены и правила пустых совпадений SHALL сохраняться. Переносимая регистронезависимость SHALL ограничиваться ASCII; Unicode SHALL оставаться зависимым от движка и быть описан в справочнике.

#### Scenario: Поиск после замены
- **WHEN** r равно `(re-pattern "post-([0-9]+)" "i")` и последовательно выполняются поиск групп в `"POST-1"`, замена в `"POST-1 post-2"` на `"$1"`, re-find в `"POST-3"` и поиск групп в `"post-4"`
- **THEN** результаты — коллекция `"POST-1"`, `"1"`; строка `"$1 $1"`; строка `"POST-3"`; коллекция `"post-4"`, `"4"`, как eval

### Requirement: Java target SHALL разрешать ссылки на свои именованные функции в namespace

Передача своей top-level функции как значения SHALL использовать фактический класс текущего namespace. Это SHALL работать как без ns, так и во вложенном namespace, включая передачу callback в map и связывание функции локальным binding, без пользовательского cast.

#### Scenario: Named callback во вложенном namespace
- **WHEN** программа в namespace `checks.callbacks.core` передаёт собственную unary-функцию duplicate в map непосредственно и через локальное функциональное значение
- **THEN** generated Java компилируется и возвращает результаты callback в порядке исходной коллекции
- **AND** программа без ns сохраняет работоспособность передачи именованных функций

### Requirement: Compiler targets SHALL предоставлять run! для последовательных эффектов

JavaScript и Java SHALL предоставлять без пользовательского импорта обычную функцию `(run! f items)` для unary callback и list/vector. Run! SHALL немедленно вызывать callback ровно один раз для каждого элемента в исходном порядке, передавая только элемент, игнорировать результаты и SHALL NOT собирать результирующую коллекцию. После успешного обхода SHALL возвращаться nil/null. Пустая коллекция SHALL NOT вызывать callback и SHALL возвращать nil/null. Именованная функция, лямбда и локальное функциональное значение SHALL поддерживаться. Поддержка maps, nil как коллекции и произвольных iterable не входит в контракт. Ошибка callback SHALL прерывать обход и передаваться наружу без отката выполненных эффектов; единый host exception type и текст диагностики не требуются.

#### Scenario: Переносимый порядок и результат
- **WHEN** `(run! f [1 2 3])` записывает аргументы в Atom, а callback возвращает произвольные значения
- **THEN** после возвращения run! журнал содержит ровно 1, 2, 3 в этом порядке, как на eval
- **AND** результат равен nil, ложен и не равен строке `"nil"`

#### Scenario: Пустая коллекция
- **WHEN** compiled программа выполняет `(run! f [])` с callback, изменяющим Atom
- **THEN** Atom не изменяется и результат равен nil

#### Scenario: Формы callback и вложенный namespace
- **WHEN** программа в namespace `checks.effects.core` передаёт run! именованную unary-функцию, лямбду или локальное функциональное значение
- **THEN** generated JS и Java компилируются с обычным runtime и выполняют ожидаемые эффекты

#### Scenario: Ошибка прерывает обход
- **WHEN** callback выполняет наблюдаемый эффект и затем завершается ошибкой на втором элементе из трёх
- **THEN** третий callback не вызывается, ошибка выходит из run!, эффекты первого и второго вызовов сохраняются

### Requirement: JavaScript run! SHALL поддерживать массивы host-объектов

JavaScript run! SHALL принимать обычные плотные JS-массивы, включая массивы DOM-элементов, полученные через Array.from. Элементы SHALL передаваться callback без преобразования или копирования объектов. Непосредственный обход NodeList и поведение при изменении состава массива во время обхода не специфицируются.

#### Scenario: Скрытие тредов через interop
- **WHEN** массив host-объектов thread передаётся `(run! hide-thread! threads)`, где hide-thread! вызывает `(.click (.querySelector thread ".post__btn_type_hide"))`
- **THEN** для каждого исходного объекта вызывается querySelector с указанным selector и затем click найденной кнопки ровно один раз в порядке массива
- **AND** run! возвращает nil/null и не собирает результаты click

### Requirement: Compiler targets SHALL предоставлять filter по истинности языка

JS и Java SHALL предоставлять без пользовательского импорта `(filter pred items)` для одного list/vector. Функция SHALL возвращать исходные элементы с истинным по правилам языка результатом unary-предиката, сохраняя порядок. Nil и false SHALL исключать элемент; 0 и пустая строка SHALL быть истинными. На JS undefined SHALL также считаться ложным результатом предиката.

#### Scenario: Отбор сообщений
- **WHEN** filter получает сообщения с типами `"text"`, `"image"`, `"text"` и предикат `(fn [message] (= (:type message) "text"))`
- **THEN** JS и Java возвращают первое и третье исходные сообщения в том же порядке, как eval

#### Scenario: Истинность и исходные значения
- **WHEN** вычисляется `(filter (fn [x] x) [nil false 0 "" "nil" "false"])`
- **THEN** результат содержит ровно `0`, `""`, `"nil"`, `"false"` с сохранением типов и порядка
- **WHEN** вычисляется `(filter (fn [x] true) [nil false])`
- **THEN** результат содержит исходные nil и false

#### Scenario: Undefined в предикате JS
- **WHEN** JS callback возвращает undefined для элемента
- **THEN** filter исключает этот элемент

### Requirement: Compiler targets SHALL предоставлять keep для результатов без nil

JS и Java SHALL предоставлять без пользовательского импорта `(keep f items)` для одного list/vector. Функция SHALL возвращать результаты unary callback, кроме nil/null, в порядке исходных элементов. False, 0, пустая строка и строка `"nil"` SHALL сохраняться. На JS keep SHALL также исключать undefined, включая результат host-вызова.

#### Scenario: Преобразование карточек
- **WHEN** callback для трёх событий возвращает соответственно карточку A, nil и карточку C
- **THEN** keep возвращает карточки A и C в этом порядке, а не исходные события

#### Scenario: Сохранение значений
- **WHEN** вычисляется `(keep (fn [x] x) [nil false 0 "" "nil" "false"])`
- **THEN** JS и Java возвращают ровно `false`, `0`, `""`, `"nil"`, `"false"` с исходными типами, как eval

#### Scenario: Отсутствующие host-результаты JS
- **WHEN** callback JS keep возвращает последовательно null, undefined, false, 0 и пустую строку
- **THEN** результат содержит ровно false, 0 и пустую строку

### Requirement: Compiler filter и keep SHALL выполнять немедленный упорядоченный обход

Обе операции SHALL вызывать callback ровно один раз на элемент слева направо, передавая только элемент. Именованная функция, лямбда и локальное функциональное значение SHALL поддерживаться, включая вложенный namespace. Сами операции SHALL NOT изменять исходную коллекцию. Пустой вход SHALL давать пустую коллекцию без callback. Ошибка callback SHALL прерывать обход и передаваться наружу без отката эффектов; единый тип и текст host-ошибки не требуются.

#### Scenario: Порядок, namespace и callback
- **WHEN** программа во вложенном namespace передаёт каждой операции `[1 2 3]` и callback, записывающий аргументы в Atom, непосредственно по имени, как лямбду либо через локальный binding
- **THEN** generated JS и Java компилируются, после возврата журнал содержит ровно 1, 2, 3 в этом порядке
- **AND** исходная коллекция по-прежнему содержит 1, 2, 3

#### Scenario: Пустые результаты
- **WHEN** каждая операция получает пустой list/vector и callback с наблюдаемым эффектом
- **THEN** результат является пустой коллекцией, callback не вызывается
- **WHEN** filter отклоняет все элементы либо keep получает nil от каждого callback
- **THEN** результат является пустой коллекцией, не nil

#### Scenario: Ошибка callback
- **WHEN** callback каждой операции записывает эффект и завершается ошибкой на втором элементе из трёх
- **THEN** третий callback не вызывается, ошибка выходит наружу, предыдущие эффекты сохраняются

### Requirement: JavaScript filter и keep SHALL поддерживать плотные host-массивы

JS filter и keep SHALL принимать обычные плотные host-массивы. Callback SHALL получать исходные объекты без преобразования или копирования. Filter SHALL сохранять выбранные исходные объекты, keep SHALL сохранять возвращённые объекты без копирования; операции SHALL NOT изменять входной массив. Sparse arrays, произвольные iterable и изменение состава входа callback не входят в контракт.

#### Scenario: Ссылки и неизменность host-массива
- **WHEN** filter отбирает объекты из плотного JS-массива, а keep возвращает объекты из callback
- **THEN** элементы результатов являются теми же объектами по JS identity, а длина, порядок и элементы исходного массива не изменены самими операциями

### Requirement: Compiler targets SHALL предоставлять предикат string?

JS и Java SHALL предоставлять без пользовательского импорта `(string? value)` для одного значения любого типа. Результат SHALL быть boolean true для строкового runtime-значения, включая пустую строку и keywords, и boolean false для остальных типов. Аргумент SHALL вычисляться ровно один раз без преобразования в текст. Иные арности не входят в переносимый контракт.

#### Scenario: Строки и keywords
- **WHEN** выполняются `(string? "")`, `(string? "text")`, `(string? "nil")`, `(string? "false")`, `(string? "42")`, `(string? :name)` и `(string? (str 42))`
- **THEN** каждый результат — boolean true, как в eval

#### Scenario: Нестроковые значения
- **WHEN** string? получает nil, true, false, целое, дробное число, list/vector, map, функцию, Atom или regex
- **THEN** каждый результат — boolean false без ошибки из-за типа аргумента

#### Scenario: Доступность во вложенном namespace
- **WHEN** программа с namespace `checks.string.core` вызывает `(string? "ok")` без пользовательского импорта предиката
- **THEN** generated JS и Java компилируются с соответствующим runtime и возвращают boolean true

#### Scenario: Проверка полученного значения и однократное вычисление
- **WHEN** string? получает строку из get либо функции, увеличивающей счётчик Atom и возвращающей строку
- **THEN** результат — boolean true
- **AND** при вызове функции счётчик увеличивается ровно один раз

#### Scenario: Boolean вместо текстового результата
- **WHEN** выполняются `(= (string? "") true)`, `(= (string? nil) false)` и `(if (string? 42) "yes" "no")`
- **THEN** результаты — true, true и `"no"`

### Requirement: String? SHALL учитывать строковое представление host и quoted значений

На JS string? SHALL принимать только примитивные строки, а на Java — экземпляры java.lang.String. Цитированные атомы, представленные compiled target как строки, SHALL давать true. Справочник SHALL описывать эти границы и отличие от eval, где цитированные символы, nil, boolean и числа не являются строками.

#### Scenario: Строки из JSON
- **WHEN** JS передаёт string? результаты JSON.parse для JSON-строки, пустой строки, null, числа, boolean, массива и объекта
- **THEN** первые два результата — true, остальные — false

#### Scenario: JS host-значения
- **WHEN** JS передаёт string? объект `new String("x")`, undefined или обычный объект
- **THEN** каждый результат — false

#### Scenario: Java host-значения
- **WHEN** Java передаёт string? экземпляры java.lang.String и java.lang.StringBuilder с одинаковым текстом
- **THEN** результаты — true и false соответственно

#### Scenario: Цитированные атомы compiled targets
- **WHEN** выполняются `(string? 'foo)`, `(string? 'nil)`, `(string? 'false)`, `(string? '42)` и `(string? '"text")`
- **THEN** каждый результат — true на JS и Java

### Requirement: Compiler targets SHALL предоставлять assoc и merge для map

JS и Java SHALL предоставлять без пользовательского импорта `(assoc map key value)` и `(merge left right)`. Assoc SHALL добавлять или заменять одно поле; merge SHALL объединять поля с приоритетом правой map. Результат SHALL быть новой поверхностной map без изменения входов. Строковые и keyword ключи SHALL давать те же результаты, что eval. Порядок обхода и равенство map между targets не гарантируются.

#### Scenario: Добавление и замена
- **WHEN** m равно `{:a 1}` и выполняются `(assoc m :b 2)` и `(assoc m :a 3)`
- **THEN** результаты содержат соответственно a=1,b=2 и a=3 с count=2 и count=1
- **AND** m сохраняет a=1 и count=1

#### Scenario: Объединение и пустые map
- **WHEN** выполняются `(merge {:a 1 :b 2} {:a 3 :c 4})`, `(merge {} {:a 1})`, `(merge {:a 1} {})` и `(merge {} {})`
- **THEN** результаты содержат соответственно a=3,b=2,c=4; a=1; a=1; пустую map
- **AND** оба входа сохраняют свои поля и значения

#### Scenario: Вызов во вложенном namespace
- **WHEN** source в namespace `checks.maps.core` вызывает assoc и merge
- **THEN** generated JS и Java компилируются с обновлённым runtime и возвращают ожидаемые поля без пользовательских imports

### Requirement: Compiler assoc и merge SHALL сохранять значения поверхностно

Assoc и merge SHALL сохранять значения false, nil, 0 и пустую строку без фильтрации по истинности. Вложенные map SHALL заменяться целиком и SHALL NOT копироваться рекурсивно. Значения объектов SHALL передаваться без преобразования. Эти правила SHALL совпадать с eval для переносимых значений.

#### Scenario: Перезапись ложными значениями
- **WHEN** вычисляются `(assoc {:x 1} :x nil)` и `(merge {:a 1 :b 2} {:a false :b nil})`
- **THEN** count результатов равен 1 и 2, соответствующие поля равны nil, false и nil, а не строкам

#### Scenario: Вложенная map заменяется целиком
- **WHEN** r равно `(merge {:nested {:a 1 :b 2}} {:nested {:a 3}})`
- **THEN** nested содержит только a=3 и count=1

#### Scenario: Ссылочные значения сохраняются
- **WHEN** значение Atom проходит через assoc или merge и извлекается из результата
- **THEN** изменение извлечённого Atom наблюдается через исходную ссылку

### Requirement: Compiler targets SHALL ограничивать арности и map аргументы

Assoc SHALL принимать ровно три аргумента, merge — ровно два. Nil, list и скаляры вместо map SHALL отклоняться, а не трактоваться как пустые map. Неверная арность SHALL отклоняться при компиляции либо исполнении; единые стадия, класс и текст ошибки не требуются. Новые overloads для нескольких пар, нескольких map или векторов SHALL NOT предоставляться.

#### Scenario: Неверная арность
- **WHEN** source вызывает `(assoc {})`, `(assoc {} :a 1 :b 2)`, `(merge {})` или `(merge {} {} {})`
- **THEN** программа отклоняется при компиляции либо исполнении

#### Scenario: Неверная коллекция
- **WHEN** assoc получает nil, list или скаляр вместо map либо merge получает такое значение в любой позиции
- **THEN** исполнение завершается ошибкой, включая сочетания с пустой map

### Requirement: JavaScript assoc и merge SHALL поддерживать JSON-объекты

JS SHALL принимать map языка и обычные объекты из JSON.parse. Копирование SHALL включать собственные перечислимые строковые поля, без унаследованных полей. Результат SHALL иметь null prototype, а ключи `__proto__` и `constructor` SHALL оставаться обычными данными. Поддержка class instances, getters, proxies и symbol keys не входит в контракт.

#### Scenario: Обновление данных события
- **WHEN** item и result получены из JSON.parse и выполняется `(assoc (merge item result) :selection_reason (:reason item))`
- **THEN** результат содержит объединённые поля с правым приоритетом и selection_reason из item; оба исходника сохраняются

#### Scenario: Специальные строковые ключи
- **WHEN** JSON-объект с собственными полями `__proto__` и `constructor` передаётся merge либо assoc обновляет эти ключи
- **THEN** поля доступны как данные в результате, его prototype остаётся null

### Requirement: Compiler targets SHALL предоставлять двухаргументный sort-by

JS и Java SHALL предоставлять без пользовательского импорта обычную функцию `(sort-by keyfn coll)` для unary-функции и list/vector. Результат SHALL содержать исходные элементы по возрастанию ключа. Именованная функция, лямбда и локальное функциональное значение SHALL работать, включая вложенный namespace. Другие арности, пользовательский компаратор, map и nil вместо коллекции не входят в API.

#### Scenario: Сортировка событий во вложенном namespace
- **WHEN** программа в namespace checks.sorting.core сортирует события A, B, C с приоритетами 20, 3, 10 через sort-by
- **THEN** JS и Java компилируются с соответствующим runtime и возвращают B, C, A, как eval
- **AND** функция ключа работает по имени, через локальный binding и как лямбда

### Requirement: Compiler sort-by SHALL поддерживать числовой порядок ключей

Числовые ключи SHALL сортироваться по числовому значению без epsilon, включая смесь целых и конечных binary64. Численно равные ключи, включая 1 и 1.0 и оба знака нуля, SHALL считаться равными для сортировки. Переносимость ограничивается числами, представимыми на соответствующих targets; расширение диапазонов чисел и non-finite значения вне контракта.

#### Scenario: Смешанные числа
- **WHEN** ключи элементов равны 10, -2, 1.5, 1, 0.25
- **THEN** JS и Java возвращают порядок по ключам -2, 0.25, 1, 1.5, 10, как eval

#### Scenario: Равные значения разных числовых представлений
- **WHEN** элементы A, B, C, D, E имеют ключи 1, 1.0, 0, -0.0, 0.0
- **THEN** порядок результата — C, D, E, A, B

### Requirement: Compiler sort-by SHALL сравнивать строки без locale

Строковые runtime-ключи SHALL сравниваться лексикографически, с учётом регистра и без locale. Для ASCII порядок SHALL совпадать с eval; префикс предшествует более длинной строке. Остальной Unicode SHALL иметь документированный target-specific порядок. Все ключи одного вызова — либо строки, либо числа; nil, boolean, составные ключи и смесь строк с числами вне контракта.

#### Scenario: ASCII и префиксы
- **WHEN** ключи равны "a", "2", "A", "10", "", "aa"
- **THEN** порядок ключей результата — "", "10", "2", "A", "a", "aa" независимо от locale

### Requirement: Compiler sort-by SHALL сохранять стабильность и входные элементы

Sort-by SHALL сохранять исходный порядок элементов с равными ключами и SHALL NOT изменять входную коллекцию или копировать её элементы. Пустой вход SHALL давать пустую коллекцию, не nil. Гарантии относятся к действиям самой операции; изменение входа или элементов из callback вне контракта.

#### Scenario: Равные ключи и исходный порядок
- **WHEN** события A, B, C имеют ключи 20, 3, 20
- **THEN** результат содержит B, A, C, а исходная коллекция по-прежнему содержит A, B, C

#### Scenario: Пустой вход
- **WHEN** sort-by получает пустой list/vector
- **THEN** результат является пустой коллекцией, не nil

### Requirement: Compiler sort-by SHALL вычислять ключи однократно слева направо

Sort-by SHALL немедленно вызвать keyfn ровно один раз для каждого элемента в исходном порядке с единственным аргументом — этим элементом. Пустой вход SHALL NOT вызывать keyfn; одноэлементный SHALL вызывать её один раз. Ошибка keyfn SHALL прерывать обход и передаваться наружу без отката предыдущих эффектов. Единый host exception type и текст диагностики не требуются.

#### Scenario: Журнал вычисления ключей
- **WHEN** keyfn записывает ID в Atom и возвращает ключ для входных A, B, C
- **THEN** после sort-by журнал содержит ровно A, B, C независимо от порядка результата

#### Scenario: Ноль и один элемент
- **WHEN** sort-by последовательно получает пустую и одноэлементную коллекции с keyfn, увеличивающей счётчик
- **THEN** счётчик после первого вызова равен 0, после второго — 1

#### Scenario: Ошибка callback
- **WHEN** keyfn записывает эффект и завершается ошибкой на втором элементе из трёх
- **THEN** третий keyfn не вызывается, ошибка выходит наружу, предыдущие эффекты остаются

### Requirement: JavaScript sort-by SHALL поддерживать плотные host-массивы

JS sort-by SHALL принимать обычные плотные host-массивы и передавать keyfn исходные объекты без преобразования. Элементы результата SHALL сохранять JS identity, исходный массив SHALL оставаться неизменным самой операцией. Sparse arrays и произвольные iterable вне контракта.

#### Scenario: Очередь host-объектов
- **WHEN** очередь из JS-объектов A, B, C с ключами "2026-10-14", "2026-10-13", "2026-10-14" сортируется через sort-by
- **THEN** результат содержит те же объекты B, A, C по JS identity
- **AND** исходный массив сохраняет длину, ссылки и порядок A, B, C
