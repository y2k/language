# Перенос cond на сам язык — MVP

## Destination

Согласовать решения для двух атомарных OpenSpec changes: сначала подготовить точки расширения без изменения поведения языка, затем перенести существующий `cond` из OCaml на сам язык, сохранив его поведение и автоматическую доступность на eval, JS и Java.
Карта завершена, когда не осталось вопросов, препятствующих подготовке этих changes. Чистовая реализация не входит в эту карту; отдельно разрешённый исследовательский spike выполнен в worktree.

## Notes

- Первый полезный результат — единый pipeline с точками подключения расширений, включая загрузку пакетов; нынешний OCaml `cond` на этом этапе сохраняется. Второй — работающее определение `cond` на языке вместо `cond_macro`.
- MVP поддерживает только внутренние макросы стандартной библиотеки. Пользовательское определение макросов не требуется.
- Существующие программы используют `cond` без дополнительных импортов.
- Минимальный механизм определяется потребностями полного переноса `cond`, а не будущей универсальной системой макросов.
- Сохранить обработку произвольного числа пар, пустого `cond`, короткое замыкание и существующую ошибку при нечётном числе форм.
- Каждый последующий заход должен самостоятельно приносить пользу; следующий перенос выбирается после работающего MVP.
- Перед чистовой разработкой выполнен spike в отдельном worktree; результаты и границы двух заходов приложены к билету «Загрузка cond и граница атомарного переноса». Прототип не является реализацией для автоматического переноса в main.
- Для работы над билетами использовать `wayfinder`, `grilling`, `domain-modeling`; учитывать правила `AGENTS.md`. Планирование реализации ведётся через OpenSpec.
- Локальный трекер: эта карта — родитель; билеты находятся в `tickets/`. YAML-поля `parent`, `status`, `assignee`, `blocked_by` задают связи и состояние. Только метки `wayfinder:*`.
- Перед работой над билетом заполнить `assignee` именем разработчика. Доступный фронт: открытые билеты без исполнителя, все зависимости которых закрыты; порядок — по имени файла.
- За одну сессию разрешается решить один билет. Решение записывать в секцию `Resolution` его файла, затем закрыть билет и добавить сюда ссылку с кратким итогом. Детали решения остаются только в билете.

## Decisions so far

- [Выполнение встроенного макроса на языке](tickets/01-execution.md): переиспользуем evaluator через отдельный верхний API полного раскрытия; функция получает один список форм.
- [Представление входа и результата макроса](tickets/02-forms.md): для первой версии исходные аргументы передаются в `Syntax`, новые формы строятся обычными значениями; сохраняется один проход раскрытия.
- [Загрузка cond и граница атомарного переноса](tickets/03-bootstrap.md): два отдельных changes; отключение через список обработчиков, окружение на файл, встроенный исходник и минимальная обработка ошибок.

## Not yet specified

Нет. Решения для подготовки двух последовательных OpenSpec changes согласованы; карта завершена.

## Out of scope

- Пользовательский `defmacro` и импорт пользовательских макросов.
- Перенос остальных встроенных макросов и выбор следующего переноса до получения работающего MVP.
- Возможности макросистемы, не необходимые для `cond`, включая syntax-quote и генерацию уникальных имён.
- Чистовая реализация компилятора в рамках этой карты; после решений — два последовательных OpenSpec changes.
